# Changelog

## 0.11.0 - 2026-09-03
### Added
* Every turn now opens with a CURRENT TIME message in UTC, so the agent resolves a relative period the user names — "last week", "since Friday" — against a real clock and reports the absolute range it resolved it to, rather than guessing a date or asking for one. It rides the same per-turn system message as WORKSPACE STATE and for the same reason it cannot ride the system prompt: that block is a literal resolved once at load, so a date stamped there would be the process's boot date for as long as it runs, wrong from the second day on with nothing to show it. UTC rather than an operator timezone, stated as UTC in the message: where a report's boundaries genuinely depend on the user's zone, that is a question to ask rather than an offset to bury.
* The agent runs with reasoning on. Its model resource is an `OpenAI.ResponsesModelStream` rather than a chat-completions one, because `/v1/chat/completions` refuses a non-`none` reasoning effort alongside function tools and this agent is nothing but tools — so it previously had to run with reasoning off, which measurably cost it on structural work. The encrypted reasoning rides the contract's `providerState` and `Ai.AgentStream` replays it, so thinking survives each tool loop instead of restarting every turn. A new `REASONING_EFFORT` variable (`minimal` | `low` | `medium` | `high`, default `medium`) is the operator's dial: it trades answer quality against latency and spend on every turn, and `minimal` restores the previous behaviour without editing the manifest.
* Thinking is visible. The model resource now asks for `reasoning.summary`, so a turn streams the model's own précis of its reasoning as `reasoning-delta` parts beside the answer, and Telo Studio renders them as a collapsible Thinking block — open while it is the only thing to read, collapsed once the answer starts, unless the reader says otherwise. Reasoning effort alone produced nothing a client could show: the reasoning itself comes back encrypted and is only ever replayed through providerState, so the summary is the whole readable surface and asking for it is what turns it on. It is kept apart from the reply rather than folded into the text: the conversation history persists the answer and not the thinking, a resume report never quotes it, and a client that does not render it simply drops the parts.
### Fixed
* Discovery goes through the hub tools, and the CLI's duplicates are named as the fallback they are. The prompt advertised two equally-weighted routes to a module's schema — `get_module_manifest` / `search_resources`, and `telo module manifest` / `telo search` — and the paragraph on not reading `.telo/` reached for the CLI one as the instruction, so a run would answer "what fields does this kind have" through either, at random. Both places now say the hub tools are the first move and the CLI verbs are for when a hub tool errors or returns nothing. The `telo` tool's own docs also said `args` is "SEPARATE strings" without saying a multi-word VALUE is still one argument, so `search http server` went out as three positionals and the CLI, which is strict, rejected it as an unknown argument.
* The agent no longer asks what to name an environment variable. An env var name, a file path, a resource name and an app slug are all names the manifest DECLARES, so asking makes the user invent an answer whose only effect is what the agent was about to write anyway — it picks the name, writes the binding, and reports which vars to set when it finishes. Two places in the prompt had told it otherwise: the credentials item on the unspecified-facts checklist asked for "the env var it arrives in", and the OAuth section called the variable names for a client id and secret "a real question". What stays a question is the part only the user holds: which identity each side authenticates as where several plausibly exist, and the credential's value itself. Anything derivable from what is being built — an OAuth scope follows from the calls the agent is about to make — is the agent's to pick too.

## 0.10.2 - 2026-08-30
### Fixed
* Both apps declare an `Http.Client` account — bearer token where there is one, no credential where the endpoint needs none — and reference an `Http.Request` from their model resources, which is what `openai@0.2.0` requires. They were left writing the removed `apiKey:` field when their pins moved, so neither could boot. The hub's embedder keeps its own base URL, which now sits on the client rather than on the model.

## 0.10.0 - 2026-08-29
### Added
* The agent now gathers requirements before it builds. A request to create something new that leaves something material unsaid — what it exposes, where its data lives, auth, tests — is answered with questions rather than guesses, and no files are written until they are settled. Questions come in ROUNDS that narrow: round one settles the shape in at most four questions, each later round asks only what the previous answers made relevant, and three rounds is the ceiling. Asking everything at once produced compound questions ("provide: (1) the id, (2) the tab, (3) the headers") that cannot be answered in a text box, and it asks for a spreadsheet tab's headers only once it knows which tab. Options carry a recommended one where real alternatives exist. A request that already specifies everything is still built immediately, and so is any edit, fix or follow-up in a thread that settled the questions once. The questions ride in the reply as a fenced `telo-questions` JSON block rather than a tool call, because a tool result feeds the model loop into another step and so cannot end a turn: Telo Studio renders the block as clickable options, and a client that does not parse it shows the same questions as text. Every question also takes an answer in the user's own words — the options are guesses at the useful answers, not the set of legal ones — and such an answer is built as written rather than snapped to the nearest option offered. A question may carry no options at all, for a fact only the user has: a spreadsheet's columns, a tracker's field names, the key two sources are joined on. The agent already reads module fields from the hub rather than guessing, and the same rule now covers the user's own systems, which no tool can describe — a request naming YouTrack, a Google Sheet and a PDF reads as a specification while saying nothing about any of them, and an invented column name yields a manifest that checks clean, runs, and is wrong. Every turn now also opens with a `WORKSPACE STATE:` message listing what the workspace holds, so the agent is told rather than having to remember to look: it had been asking whether to create a new application or extend an existing one against an empty workspace.
* The agent now builds an application as several files and verifies it. Domain areas become feature libraries under `apps/<slug>/`, tests are written against their exports in `apps/<slug>/tests/` — a `Test.Suite` at `tests/telo.yaml` plus one file per behaviour — and the application manifest is left as wiring. That split is what makes the behaviour testable at all: nothing can import a `Telo.Application`, so a single `apps/<slug>/telo.yaml` is reachable only by running the whole app, which is the shape it used to produce. A new `run_manifest` tool executes a suite, one test file, or a throwaway PROBE, so the agent can get its own tests green rather than declaring them ready to run — and can answer its own questions about systems it can reach: given a spreadsheet id and a token it reads the tabs and column headers itself instead of asking the user to transcribe them, leaving only the identifier and the credential's env var to ask about. Having no credential is no longer a refusal either: the agent drives OAuth consent through `oauth-client`'s DEVICE flow, printing a verification URL and code for the user to approve — the redirect flow is unusable here, since the container is not reachable from the user's browser. That runs in two parts, because a poll cannot outlast the run timeout while a human signs in, and the second part does the reading in the same run since an in-memory grant dies with the process that obtained it. Registering the OAuth client stays the user's. Probes read and never write, are deleted after, and a failed one becomes a question rather than a guess; the enforceable control is the credential's own scope, since the agent authors the probe. It is gated by `ALLOW_MANIFEST_RUNS`, OFF by default, because a manifest the agent wrote is arbitrary code reaching the network with whatever credentials the container holds, and a child process inherits the operator environment apart from the scrubbed `OPENAI_API_KEY` — enable it only where the caller owns the container. A build is not done while the thing that was ASKED FOR does not happen: a source fetched and then ignored, a join that returns a constant, a `value:` step holding example rows where a computation belongs. Shipping a manifest that checks clean and renders a report of invented numbers is the worst outcome available, because it reads as real and nothing downstream flags it — so a computation the agent cannot work out is reported at the top of its reply instead, and a gap in the central feature is asked about BEFORE building around it rather than footnoted after. A `default:` for a fact only the user has is an invented answer wearing a nicer word, so such a variable is declared required. Runs are bounded by `runTimeoutMs` (120s), since a suite terminates and an application does not. A turn's step budget rises from 16 to 40, which a several-file build with a check-and-fix per file needs to finish at all. Tests that depend on a third-party service now mock it with an `Http.Server` scoped to the test's own sequence rather than calling it, and the library under test is pointed at that mock through its base-URL variable — so an external service's URL and credential are library variables from the start, since a library with the vendor's URL written into it cannot be tested.
### Fixed
* `list_dir` no longer returns `.telo/`, `node_modules/`, `.git/` or `dist/` at any depth: the exclude set is applied by the tool's own inputs mapping, so the model cannot drop it, and an omitted `path` now lists the workspace root rather than failing. A recursive listing was mostly resolved-dependency cache paths, which both drowned the authored files and invited reading a pinned manifest out of the cache as if it were a catalog — the prompt now says why that is not one.

## 0.9.0 - 2026-08-27
### Added
* The workspace directory is configurable via the WORKSPACE_DIR environment variable (default ./workspace). A runner standing this up as a session's co-resident agent points it at the shared workspace volume, so the agent's file tools and spawned commands write the same tree the application containers watch.

## 0.8.0 - 2026-08-26
### Added
* System prompt: the value-or-reference union slot (a column's type: holding a storage class or a !ref) and a referrer-rules section covering peers:, which the primer had no coverage of at all.

## 0.7.0 - 2026-08-23
### Added
* Drops the retired `teardown()` from the surface: ai's model, image and embedding handle interfaces no longer declare it, and the run and vector-store-pgvector controllers no longer implement an empty one. Cleanup is what a controller returns from `init()` / `run()`. Nothing called these, so no behaviour changes; a third-party handle implementing `teardown()` simply has a method nobody invokes.

## 0.6.0 - 2026-08-20
### Added
* Any kind can now carry a step body: the grammar is a shared fragment (`$ref: "telo://manifest#/$defs/Step"`) instead of four `$defs` copies declared here, and `StepEngine` moved to `@telorun/sdk`. Two breaking consequences: `while/do` is now legal in an iteration, projection and loop body, not only a sequence; and reading the grammar requires telo >=0.79.0, which the module now declares.
* The authoring primer covers zone attributes, durable execution and the runtime floor the zone-attribute object form requires.

## 0.5.5 - 2026-08-17
### Fixed
* The manifest-authoring primer named the schema-valued slots `telo check` actually validates as JSON Schema — a kind's `schema:`, its `status:` block and a `Telo.JsonSchema`'s `schema:` — and says plainly that a kind's own `inputType:`/`outputType:` and an API route's `request.schema` are not checked that way yet. The earlier wording claimed every schema block was covered, which would have had the agent trusting a diagnostic that never fires.

## 0.5.3 - 2026-08-16
### Fixed
* Import pins moved to the current module releases

### Fixed

* System prompt: value types are one `x-telo-type` annotation, with type arguments and `!ref`-named shapes.## 0.5.0 - 2026-08-14
### Added
* Teach the CEL rules an author actually gets wrong: call form is part of a function's signature (CEL string built-ins are methods, Telo's stdlib functions are global, a few are both), there is no now() or uuid(), date arithmetic goes through timestamp(nowSeconds()) with string()/int() to convert back out, and a non-deterministic call in an x-telo-eval: compile field freezes at load.
* Boot creates the ./workspace directory the shell host runs commands from, so a fresh checkout or deployment no longer fails the first command with `interpreter not found` (spawn reports a missing cwd as ENOENT, which the shell host attributes to the program). The agent gains a general 'telo' tool: it supplies the CLI argv and a new 'teloVerbs' variable decides which subcommands may run, defaulting to the inspection verbs (check, cel, module, search). 'run', 'publish', 'install' and 'upgrade' are absent by default, so an anonymous prompt can neither execute a manifest on the host nor reach the operator's registry credentials; a bare path, which the CLI would treat as 'run', is rejected for the same reason. 'checkArgv' is replaced by 'teloProgram' so the check loop and the new tool cannot drive different CLI builds.
* The system prompt now states the workspace layout the editor enforces: an application at apps/<slug>/telo.yaml, a library at libs/<slug>/telo.yaml, the manifest filename always telo.yaml (so a relative import names the directory), tests beside the module in tests/ with inputs under __fixtures__/, and .telo/ never written by hand. The agent previously chose paths freely, so work could land where the editor's module scan — which matches telo.yaml alone — would never find it.
* The system prompt covers the two file-embedding tags: `!include-text` yields a file's contents as a string and `!include-bytes` yields raw bytes for an x-telo-binary slot, with the rules an author gets wrong — the path is a literal relative to the module root rather than to the file the tag was written in, the tag only belongs inside a resource because the file is read when that resource is created, publish adds the file to the artifact so it is never restated in files:, and a computed path is not expressible (embed the closed set and select with !cel, or read at runtime with Fs.File).## 0.4.1 - 2026-08-12
### Fixed
* The system prompt no longer describes the standard library as living under an `std` namespace. That framing survived the move to hub-based discovery and taught the deprecated bare `namespace/name@VERSION` registry form; the prompt now names `oci://ghcr.io/telorun/<name>` as where the standard library is published, states that `oci://` refs and relative paths are the only sources that may be written, and calls the bare form out as deprecated.
