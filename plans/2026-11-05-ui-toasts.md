# Toasts for declarative UI

## Problem

A page has no way to say "it happened". An action draws its answer in place (`result:` / `failure:` trees), which is right for a state but wrong for an event: after a row action archives a record, the refresh drops the row and its drawn answer with it — the user sees the row vanish and nothing else. There is no Undo, no "Saved" after a dialog closes, no word when the renderer's event stream is lost. Component authors have no host call to report an event either.

## Solution

**One principle:** a notification reports an *event*; a *state* (a read failed, a field is invalid, a copy succeeded) stays drawn where it holds. A notification never holds the only record of an outcome, so it can be dropped safely.

**What posts.** One named shape, `Ui.Notification { text, tone?, link?, call? }`:
- `text` — a `Ui.BoundText` (one sentence, translated and announced as one).
- `tone` — `info | success | warning | danger`; `ui` fills `success` under `onSuccess`, `danger` under `onFailure`.
- `link` — `{ text, href }`, `href` a `Ui.Address` ("View").
- `call` — an `Ui.ActionCall` (Undo): `{ action, inputs, confirm?, prompt?, enabled? }`, run exactly as from a row — busy while pending, its `result` replaces the button, its own `onSuccess` runs.

Declared at the owners of operations, nowhere else: `Ui.Action.onSuccess.notify` (over `result`, `input`) and a new `Ui.Action.onFailure: { notify }` (over `error`, `input`); a listing's `create` / `edit` openers gain the same `onSuccess` / `onFailure`; `Ui.Listing.delete` takes `true` or `{ onSuccess?, onFailure? }` (over `row`, plus `error`). Row actions, `move` gestures and calls from a notification run a `Ui.Action`, so its own keys apply. Bound values are resolved when posted, so a notification outlives its row and a page move. A failure notification **adds to** the `failure` tree, never replaces it.

**Timing, one fixed rule (no author key):** `info` / `success` with no `link` or `call` last 6 s, paused while hovered, focused or the document is hidden; everything else stays until dismissed (WCAG 2.2.1). Every notification has a dismiss button; Escape and a swipe dismiss too. At most three are shown — a fourth drops the oldest timed one, else the oldest. An equal notification (tone, formatted text, link target, call and inputs) is not added again; the shown one restarts its timer. Reduced motion: no movement. Pinned as rows in `modules/ui/conformance/notifications.json`.

**Placement:** one region per application, `UiReact.App.notifications: { position }` (`top|bottom` × `start|center|end`, default `bottom-end`). Below the breakpoint it spans the width at its edge, above a tab bar. It sits above every layer: a modal never makes it inert, it shields nothing.

**Accessibility:** `danger` is assertive, the rest polite; each is announced once with its button labels. Posting never moves focus; F8 reaches the region (through a modal's trap), Tab walks its buttons, Escape dismisses, focus returns.

**Renderer.** A new layer control `Notifications` (group `status`) in `ui_react_controls-3`, extended in place: 25 controls, ten layer controls, still replaced as one unit (`UI_CONTROLS_LAYERS_PARTIAL` counts ten). The control is fully controlled — the renderer owns timers, the limit and deduplication and draws each item's parts (`notification-text`, `notification-actions`); the control owns `notifications` (at the end of `<body>`, `data-telo-layer`), `notification` (`data-state`, `data-tone`), announcements, F8, Escape and swipe. `ui-react-radix` implements it with Radix Toast. The renderer posts two notices of its own: `connectionLost` (warning, when the event stream fails to reopen; withdrawn at the next `hello`) and `connectionRestored`. Components post through a new host field `postNotification({ text, tone, link?, action? })`, returning `dismiss()`.

**Wire.** The action node's `onSuccess` gains `notify?` and a required `onFailure: { notify? }`; openers and delete carry the same; a notification is `{ text, tone, link?, call? }` with `call` carrying the called action's provided node; the application document carries `notifications: { position }`. New keyed texts, in `Ui.Translations` and all fourteen translations: `notificationsRegion`, `dismissNotification`, `connectionLost`, `connectionRestored`.

## Decisions

- **Notifications are declared, not returned by the API** — a server-supplied text would be unchecked and untranslated; a page binds `result.<field>` when it wants the server's words.
- **Content is a text, not a node tree** — a live region cannot announce a layout, and a tree would open a second layout surface.
- **Undo is a call, never a link** — a link cannot run an operation. `Ui.RowAction` is renamed `Ui.ActionCall` (three use sites now), and `ERR_UI_ROW_ACTION_INPUTS_INVALID` becomes `ERR_UI_ACTION_CALL_INPUTS_INVALID`.
- **Tone is a plain enum, not kinds and not `style`** — it changes behaviour (politeness, timing), not keys.
- **No author `duration`** — it would let a timer sit on an actionable notification; the rule derived from tone and buttons meets WCAG 2.2.1 for every manifest.
- **One app-level region, not a page node** — notifications must survive navigation and share one announcer and stack.
- **A layer control in the one-unit set** — a region outside the stack that draws modals would be made inert by them.
- **Reads, chat and copy do not post** — `Ui.Data` keeps its `failure` tree, the chat draws outcomes in the transcript, the copy button keeps its local check glyph and announcement.
- **No new `UI_*` rule** — every refusal is the generic machinery: `SCHEMA_VIOLATION`, the path-template codes, `CEL_UNKNOWN_IDENTIFIER` (e.g. `result` under `onFailure`), `CONTRACT_INPUTS_MISMATCH`, `MESSAGE_PLACEHOLDER_UNBOUND`, the cycle refusal for a call leading back to its own action; the body-read rule gains `onSuccess.notify` reading `result`.
- **No `requires:` floor** — only keys on `ui`'s own kinds, delivered in its artifact.
- **Bookkeeping:** docs (`ui` `notifications.md`, `action.md`, `listing.md`, `texts.md`; `ui-react` `app.md`, `controls-abi.md`, `styling.md`, `component-abi.md`), contract data files, `modules/CLAUDE.md`, the primer, the hub `build-ui` guide, a benefits-ledger entry (toast notifications with Undo, announced, translated, kept across page moves), one fragment per module.

**Verify:** a row archived and refreshed off the list still shows its notification and a working Undo; a notification posted before `onSuccess.navigate` shows on the new page; five posts show three; a repeated failure shows once; omitting `notifications` gives the same application document as `{ position: bottom-end }`; a notification above an open modal dialog is read and pressed with both control sets; F8 reaches it with a modal open; a nine-of-ten layer set is refused; a copy press leaves the region empty.

## Example

```yaml
kind: Ui.Action
inputModel: !ref ProjectRef
outputModel: !ref ProjectSummary
request: { target: { path: "/api/projects/{id}/archive", pathParams: { id: !cel "input.id" } } }
label: Archive
onSuccess:
  refreshes: [/api/projects]
  notify:
    text: { text: "{$name} archived.", values: { name: !cel "result.name" } }
    call:
      inputs: { id: !cel "result.id" }
      action:
        kind: Ui.Action
        inputModel: !ref ProjectRef
        request: { target: { path: "/api/projects/{id}/restore", pathParams: { id: !cel "input.id" } } }
        label: Undo
        onSuccess: { refreshes: [/api/projects], notify: { text: Restored. } }
onFailure:
  notify:
    text: { text: "Could not archive the project: {$message}", values: { message: !cel "error.message" } }
```
