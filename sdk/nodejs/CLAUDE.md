# SDK (Node) — package guide

Loaded when working under `sdk/nodejs/`. Repo-wide rules live in the root `CLAUDE.md`. The kernel half of what the SDK declares (effect frames, zones, suspension handling, contract binding) is in `kernel/nodejs/CLAUDE.md`; kind semantics and annotations in `analyzer/nodejs/CLAUDE.md`.

## What the SDK owns

`sdk/nodejs/src/` — public API for module authors (re-exports kernel contexts + capability interfaces). It owns the **step grammar's execution** (`step-engine.ts`, beside the `executeInvokeStep` leaf it delegates to): the SDK is the single name in `REALM_COLLAPSE_NAMES`, symlinked onto the kernel's own copy rather than inlined, so it is one version per process whatever anyone pins and is reachable from a controller bundle and the kernel's boot runner alike — a module library (`exports.code:`) is no longer copied per consumer but is still one scope per pinned version, outside the seam entirely for an npm-delivered controller, and unreachable from the kernel. Its context is STRUCTURAL (`StepEngineContext`, `InvokeStepContext` plus `ensureKindRef`), so nothing there imports the kernel or `run`.

It also owns the **durable replay seam** (`durable-run.ts`): `DurableRunHandle` — `step(path, target, inputs, execute)`, `decide(path, kind, compute)`, `park`, and the `writesInside(zone)` QUESTION — plus `stepPath` and the collapse rule. `step` MEDIATES execution rather than merely recording it, because lookup-plus-record is a leaky decomposition (two halves of one operation split so the CALLER performs the effect in between), which would silently fix the step engine and the resource graph in one process; *where* an effect executes is a real architectural axis, so `step` takes a declaration-site target identity even where the local backend resolves it in process. `decide` is the load-bearing half: a run's state is NOT just its `steps` map — inputs, predicates, loop conditions and collections are read from a scope carrying `resources.<name>.status`, a live reading republished on every dispatch by design — so recording only outcomes leaves a resume free to re-derive a decision and hand a recorded result to work it never described.

It also owns **`ctx.runtime`** (`runtime-seam.ts`), the host's own manifest machinery: `run(source, { env })` starts a child manifest isolated from the caller's and returns `{ stdout, stderr, exitCode, cancel }` — the streams are `Stream<string>`, `exitCode` settles at completion, `cancel()` stops the child and resolves once it has torn down; `check(source, { desugarImports })` runs the static-analysis pass and returns plain-data diagnostics plus a `loadError`. `test` runs child manifests through it and `assert`'s `Manifest` kind analyzes through it, so a published module binds to a versioned contract instead of importing `@telorun/kernel` / `@telorun/analyzer` — which would make kernel internals an unversioned ABI between an artifact and whatever kernel loads it. Output is streamed rather than captured because forwarding it live and retaining it on failure are both the caller's choice, and a string forecloses one. **A stream is not itself a memory bound** — withholding a `Writable`'s callback only fills its own unbounded internal buffer, and no controller awaits `drain` — so `cancel()` is what bounds an unread child, and is on the contract from the start because a supervisor needs termination before anything else. Isolation mode is the kernel's to pick (in-process child kernel today, subprocess later), which is what keeps process-global host-env state an implementation detail. Kernel half: `kernel/nodejs/src/runtime-seam.ts`.

**Contract errors are an ambient union** (`ERR_INPUT_INVALID` / `ERR_OUTPUT_INVALID`, `sdk/nodejs/src/contract-errors.ts`): raised as structured `InvokeError`s so they survive into a `catch`, nameable and typo-checked in `catches:`, and never counted toward a kind's declared `throws:`. A kind must not declare either itself.

## Where to look

- "how is a step target named somewhere the instance does not exist?" → `sdk/nodejs/src/durable-target-encoding.ts` (the wire form: canonical key order, a version, refusal at the SENDER — including a `with:`-scoped target, whose `scoped` flag is separate from its `scope` tuple because a step engine knows a name resolved in a scope before it can identify WHICH RUN, and a target recording only the missing tuple would ship as its module-level namesake), `kernel/specs/durable-execution.md` §5.3, `sdk/nodejs/src/resource-instance.ts` (`RefIdentity.origin`, stamped at `create()` — the one point where an instance and its DECLARING context are both in hand), `tests/__fixtures__/durable-remote/` (the fixture backend that ships a step to a child kernel)
- "does this survive a crash?" → `sdk/nodejs/src/durable-run.ts` (the replay seam), `kernel/specs/durable-execution.md` (normative: the determinism contract, the key scheme, the conformance rules), `modules/durable-local/nodejs/src/run-handle.ts` (one backend's implementation), `analyzer/nodejs/src/validate-durable-regions.ts` (the checks), `analyzer/nodejs/src/resolve-zone-containment.ts` (the walk they all consume)
- "a composer runs its body N times — how is each turn journaled?" → `turnStepPath` (`sdk/nodejs/src/step-engine.ts`), and `executeWhileStep`'s `stepPath(path, "do", turn)`, which is the same rule the engine applies to its own loop. A composer that DRIVES its own body (`Run.Iteration`, `Run.Loop`, `Run.Projection`) is handed one prefix for the whole dispatch, and journaling every turn under it is not merely imprecise: the journal takes the FIRST writer at a key, so turns 2..N replay turn 1's outcome instead of executing — work silently skipped, run still reporting success. Measured as one resource kind indexed per module version instead of all of them, with no error anywhere. Regression: `modules/durable-local/tests/iterates-every-item.yaml`, asserted on the kernel's own dispatch record.
- "can this WAIT, and what must not swallow the wait?" → `sdk/nodejs/src/durable-suspension.ts` (the signal, the latch, `parkRun` / `assertNotSwallowed` / `assertMaySuspend`, and `SUSPENDING_BACKOFF_MS`), `modules/durable/nodejs/src/{sleep,await-delivery,value}.ts`, `modules/durable-local/nodejs/src/deliver.ts`, `modules/run/nodejs/src/concurrency.ts` (branch-level parking), `analyzer/nodejs/src/validate-zone-violations.ts` (`ZONE_ATTRIBUTE_VIOLATED`), `modules/durable/docs/waiting.md`
- "what does this region guarantee about its contents?" → `sdk/zone-attributes/*.json` (the vocabulary, as data), `sdk/nodejs/src/zone-attribute.ts` (the reader + the composed schema), `analyzer/nodejs/src/zone-slot.ts` (the annotation's single reader), `kernel/nodejs/src/zone-context.ts` (`ctx.zoneAttributes`)
