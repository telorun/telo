Need types, library needs and their supply at an import. A `Telo.NeedType` document declares a kind a module can ask for (`fields`, `required`, `parameters`); it registers a `Telo.Provider` kind served by the kernel's need-type controller, whose resource is a fulfilment publishing exactly its fields. A `Telo.Library` declares `needs:` (`kind`, `parameters`, `optional`), read in CEL as `resources.<need>.<field>` — typed and closed from the type's fields, nullable when optional — and never handed to a controller as an instance (`ctx.resolveRef` refuses it with `ERR_REF_UNRESOLVED`). An import's `needs:` supplies a need whole by `!ref` to a need or fulfilment of the importer, or field by field with literals and CEL over the importer's scope; a need nobody supplies bubbles to the root. A field marked `x-telo-sensitive` (a string field, else `SENSITIVE_ANNOTATION_INVALID`) joins the redaction set of every module context the fulfilment reaches. `needs:` joins the shared-library agreement. `telo check` reports `NEED_TYPE_UNRESOLVED`, `NEED_PARAMETERS_INVALID`, `NEED_FIELD_UNDECLARED`, `NEED_SLOT_MISMATCH`, `NEED_UNDECLARED`, `NEED_FORWARD_INCOMPATIBLE` and `RESOURCE_INPUT_NEED_TYPE`, and the kernel raises each one's `ERR_` twin at load, before any resource initializes, for every module the application reaches. The Rust kernel refuses `needs:`, an import's `needs:` and a `Telo.NeedType` with `ERR_UNSUPPORTED_MANIFEST_FEATURE`.

A need-type kind's schema is closed — a fulfilment's `fields:` takes exactly the type's fields and requires its required ones — while an undeclared or missing field is still reported once, as `NEED_FIELD_UNDECLARED` / `NEED_SLOT_MISMATCH`. The kind carries its document's `metadata` whole, so `metadata.deprecated` on a need type gives `DEPRECATED_KIND` at a fulfilment and its metadata is checked like any kind document's (`METADATA_UNKNOWN_FIELD`, `METADATA_INVALID_TYPE`, `INVALID_DEPRECATION`). The analyzer exports `kindDeclarationOf` — which kind a document declares, and its definition, the same object for the same document — and `isKindDocument`; the module graph draws a need type on its kind plane rather than as an instance. `TYPE_LEVEL_DOC_KINDS` is replaced by `isTypeLevelDocument(doc)`.
