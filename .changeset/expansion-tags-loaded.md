The expansion tags `!if`, `!switch` and `!for-each` and the `...` splice key are read by every loader, and a misplaced or misshapen one is refused before the app runs. Each tag sits on a mapping and loads as that mapping with the marker `__expand` first; `...` is a plain key; studio's save, `telo migrate` and `telo publish` write all of them back where they were written. A tag where nothing is chosen (`BRANCH_POSITION_INVALID`: a module document outside `targets:`, a kind document outside its template body, a file's first document), a repeat outside a template body (`REPEAT_OUTSIDE_TEMPLATE`), a repeat at a field's value or a `...` key holding no repeat (`REPEAT_POSITION_INVALID`), and a tag mapping that does not fit its position (`BRANCH_SHAPE_INVALID` / `REPEAT_SHAPE_INVALID`, held to the eight new built-in fragments `IfValue` … `ForEachStepRepeat`) are each reported once, at the tag, with nothing else reported beneath it; a library's are refused when an import loads it, as `ERR_MANIFEST_VALIDATION_FAILED` carrying each under its own code, which an import's refusal of a library it analyzes now carries too. `!ref` gains its indexed form, `!ref <family>[<binding>.key]`: the `!ref` engine owns the grammar, the loader attaches its verdict to the sentinel (`parsed` or `refusal`), a text outside it is `REF_MEMBER_INVALID`, and every resolved reference carries `indexes` (`KindRef.indexes` in `@telorun/sdk`, whose `refSentinelTarget` reads the verdict and refuses an indexed or refused sentinel as `ERR_REF_UNRESOLVED`). The Rust loader reads the same sentinels in the same key order and the Rust kernel refuses every expansion construct as `ERR_UNSUPPORTED_MANIFEST_FEATURE`. The parsed-YAML cache format moves to 2. A `Telo.Definition` whose `schema:` holds a refused expansion construct reports that refusal alone: the body's reads of `self` are no longer reported as consequences.
