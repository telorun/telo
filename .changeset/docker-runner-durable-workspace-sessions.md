The docker runner serves the durable workspace session (breaking). A session's containers — `workspace`, one idle `app-<name>` per application and an optional `agent` — are named `telo-run-<id>-<role>` and labelled `telo.run/session-id=<id>` and `telo.run/role`, over the session's own directory on the bundle volume: `workspace/` at `/workspace` and, for the agent, `agent/` at `/var/lib/telo-agent-state` with `TELO_HOST_STATE_DIR` pointing there. Suspend removes the containers and keeps the directory; deleting the session or retention removes both. Every app container runs the session supervisor, which the runner writes at boot from its image (`/opt/telo-runner/supervisor`) to `.supervisor/<digest>/` on the bundle volume and mounts read-only at `/opt/telo-runner`: no TTY, no stdin and no session env — only `TELO_SUPERVISOR_LISTEN` (`0.0.0.0:<9330 + position>`) and a per-container `TELO_SUPERVISOR_TOKEN`; each app's supervisor port and debug port (`9230 + position`) are reserved, refused `400 port_conflict` (or `rejected` on reload). A container that ends, or a supervisor that restarted, fails the session naming the container. At boot the runner adopts each running session's containers by label — reading every supervisor token and the agent's token back from container inspect, reconnecting, and reporting live runs as `running` — suspends a session whose containers are gone, stale or of another supervisor protocol generation (resume rebuilds them), and its orphan sweep removes containers of sessions not running here and directories the store does not know. The runner now refuses to boot on a daemon older than Docker 26 (Engine API 1.45) instead of advertising `features.watch: false`. One-shot run sessions, catalog app sessions, the bundle upload and the attach path are gone. The image gains a static musl session supervisor, built per architecture, in its `development` stage too.

App supervisors are driven through runner-core's `SupervisedApp`, and the test engine's supervisors are runner-core's `FakeSupervisor`; a supervisor that never answers is now named by its full container name (`container 'telo-run-<id>-app-<name>'`), as every other docker message names it.
