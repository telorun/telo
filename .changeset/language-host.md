Added: `@telorun/language-host`, the editor-side half of telo's language tooling. It reads the published `@telorun/language-server` versions from npm (only those speaking an editor protocol generation the host speaks, no prereleases or deprecated releases, plus the bundled engine), selects the telo version each module is edited against from its `requires: telo:` ranges or a pin (`selectVersion`), downloads an engine verified against its `sha512` integrity with its own `teloEditorProtocol` rechecked, and `LanguageRouter` presents one LSP endpoint across the engines in use — routing each document by `telo/requirements`, showing a file's diagnostics only from its owning engine, answering `telo/*` through host services, withdrawing a stopped engine's capability registrations, and reporting a status per active document including the offline-uncached, engine-refused, engine-failed, unoffered-pin and nothing-satisfies error states. URIs are compared in the protocol's canonical form. `initialize` never waits for the network: routing starts on the cached catalog, the registry is read in the background (bounded at 15 s), and a fresh catalog chooses again for every owner. The bundled engine's identity comes from its own handshake (`BundledEngine` is just `{ load() }`), every handshake is verified, and identities are ordered by semver precedence with the published engine winning a tie except when Auto keeps the bundled one. An engine that fails — reported by the spawner's `SpawnedEngine.onFailure`, or silent for 30 s at its handshake — has its pending requests rejected, its documents, registrations and diagnostics withdrawn, and is restarted by `retry()`. The router owns every editor registration: the union of the running engines' features (the semantic-token legend unioned by name and remapped), requests only to engines that advertised them, resolves back to their producer, one registration per distinct file watcher. An imported file shows the union of what running engines publish for it. `describeTeloStatus`, `describeVersionMark` and `describeAutoMark` word the status and the picker for every host. The router answers every `telo/*` request itself over three host seams — `HostFileSystem` (raw `stat` / `readText` / `readDirectory` by `file:` URI), `RemoteReader` (every non-`file:` read) and `HubClient` (the hub's version lists and ref search, parsed once for every host) — and keeps each workspace's Auto resolutions in a host `ResolutionStore`, so a module reopens on the engine it last resolved to. Browser-safe: web globals only.
