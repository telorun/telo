Fixed: a CEL expression at a field that unions a constant with a `Telo.HostPath` (`SQLite.Connection.file`: `":memory:"` or a host path) is type-checked. A `const` / `enum` branch with no `type` accepted any expression, so a plain string, a port or `module.version` passed `telo check` there and failed at creation; a constant branch is now filled only by that literal written as the whole expression (`!cel "':memory:'"`), a string source is `HOST_PATH_UNTYPED_SOURCE`, and a value that is not text is `CEL_TYPE_ERROR` naming the union's branches (`'":memory:" | Telo.HostPath'`). A branded source is matched against a union's branches before it degrades to its base, so a `Telo.HostPath` variable still fills the path branch. Every host-path finding at such a field adds the constants it also accepts, so `":memry:"` points at `:memory:`, and `HOST_PATH_RELATIVE` reads the same for a literal and for an expression.

Added: a module's `variables:` / `secrets:` entries are checked like any other schema. An unknown `x-telo-type` there is `X_TELO_TYPE_UNKNOWN` (it silently left the input a plain string), a `type:` its value type's base contradicts is the new `X_TELO_TYPE_BASE_MISMATCH` (reported wherever a schema is written), and a `default:` that does not satisfy the entry is the new `DEFAULT_INVALID` — the static twin of the kernel's `ERR_MANIFEST_VALIDATION_FAILED` at boot, reading an Application binding's default as the kernel does (through each value type's plain encoding, a relative host path anchored). An empty `env:` name is a `SCHEMA_VIOLATION`.

Changed: a CEL read of a name the site does not declare (`variables.dbFil`, `module.verison`) is `CEL_UNKNOWN_FIELD` naming what is declared (`'variables.dbFil' is not defined (available: dbFile)`) rather than the checker's `No such key: dbFil` under `CEL_TYPE_ERROR`. The engine gains `AnalyzeEnv.explainSchema`, consulted only to explain a rejection the checker already made. A `CEL_TYPE_ERROR` naming a value brand says how to use it (`string(…)`, and `.joinPath('sub/dir')` for a host path). A value of the wrong JSON type is reported once rather than again as each keyword it then fails, `!module-path` on a doc that is never instantiated is reported as `MODULE_PATH_OUTSIDE_RESOURCE` alone (no `MODULE_PATH_NOT_FOUND` beside it), and a tagged `metadata` value no longer draws `METADATA_INVALID_TYPE` beside its tag's own finding.

Fixed: the structural schema comparator no longer treats `Telo.HostPath` as gradual. A source declaring a plain type (`{type: string}`) no longer satisfies a host-path target, a union target only through a branch that takes it, while a source declaring nothing stays compatible — so template forwards, contract substitutability and step inputs refuse a plain string where a host path is declared, and tag completion no longer offers `!include-text` at a host-path field.

Fixed: `CEL_UNKNOWN_FIELD` replaces the checker's `CEL_TYPE_ERROR` only for a chain the checker itself rejects, so an overload error in an expression that also reads a name the site's context does not describe is no longer hidden. At a union beside a host path, the constant branch is decided on the parsed expression (`(':memory:')` fills it) and a source declared `const` / `enum` over the union's constants fills it too. A module input's `default:` holding a tag at any depth is left to the tag's own finding. The engine's `AnalyzeResult` gains `stringLiteral` (the string the whole expression is a literal of) and `readTypes` (the checked types of the chains a rejected expression reads), which the brand hint on `CEL_TYPE_ERROR` now reads instead of the checker's wording.
