# Changelog

## 0.2.0 - 2026-10-08
### Added
* A filter bar shows the filters on one property together: one label, with each control captioned by its operator - from and to for gte and lte, after and before for gt and lt, is, contains and one of for the rest - so a date range reads as one field. Three styling parts are new: filter-group, filter-bound and filter-caption. The filter part now holds every filter of one property, where it held one filter.
* An edit form opens over the record read from GET <basePath>/<rowKey value>, not over the row the table showed, so a list narrower than a record no longer clears the properties it leaves out; while the record loads the dialog shows the loading part, and a failed read shows an error node. BREAKING: a collection a table edits must answer GET on an item.
* Every filter policy is drawn. A bar sits above its content, beside it on either side, folded behind a toggle that counts the active filters, or in a dialog, drawer or popover closed with Done, with pinned filters, Apply and Reset outside whatever folds, no toggle where a folding placement has no filter to fold, and the compact placement below the application breakpoint. Under show: chosen a list offers the filters not on show and each one on show can be removed; controls: chips opens each control from a chip; the select, options, toggle, slider and tags controls are drawn; apply commit, typing and button, summary chips, presets, and Reset returning to the declared defaults are honoured. A bar declaring policy.state keeps what is applied in the query keys _telo.f.<key>.<property>[.<operator>] (replacing the history entry, never adding one, and carried across the history entries of its page) and in browser storage under telo.ui:<mount path>:f:<key>, the address winning at the start and every value read back checked against the declared filters; a store the browser will not read or write is reported once and the bar continues in memory. BREAKING: a filter bar's controls are now inside a new filters-bar part and what it filters inside a new filters-content part; both were direct children of filters, so a stylesheet selecting them as children of filters must be updated. New parts: filters-bar, filters-content, filters-toggle, filters-count, filters-add, filters-apply, filters-presets, filters-preset, filters-summary, summary-chip, summary-chip-remove, filter-remove, filter-chip, filter-options, filter-option, filter-toggle, filter-slider, filter-tags, filter-tag, filter-tag-remove, menu and menu-item. New attributes: data-placement, data-side and data-pending on filters, data-active on filter and filter-chip.
* Every form surface is drawn: dialog, drawer on four sides, popover, inline (create above the grid, edit under its row), panel beside the list, and a page surface in place of the page content. An addressed surface keeps what is open in the query key _telo.open.<name> as a history entry: opening adds one unless a form of the same table is already open in the address, and closing removes only that surface's key, so another surface open on the page stays open. A surface with compact is replaced below the new UiReact.App compactBelow breakpoint (default 40rem, carried in the application document; app carries data-compact), and one open when the viewport crosses it is swapped in place with what was entered. A form fills its surface, its actions at the bottom edge. afterSubmit close, again and keep are honoured, and under unsaved: confirm a form holding unsaved input asks before anything closes it — its own dismissal, navigation, host.navigate from a component, back and forward, and the browser prompt on unload. BREAKING: every dialog-* styling part is renamed into one family shared with confirmations — dialog-overlay, dialog, dialog-header, dialog-title, dialog-description, dialog-close become surface-overlay, surface, surface-header, surface-title, surface-description, surface-close, with new surface-body, table-main and table-detail parts and data-surface, data-side, data-size, data-align, data-modal, data-dirty and data-compact attributes; a stylesheet written against the dialog parts must be updated.
* The renderer offers what a collection declares. Breaking for applications, through the ui vocabulary it renders: every Ui.Table and Ui.Filters placed on a page now names a Ui.Collection, a column carries a sort control only where that collection lists its property, and a filter bar shows the collection's declared filters with their declared operators. The renderer itself is unchanged: it already drew each control from the operator and each sort control from the column it was handed.
* UiReact.App, a mount that serves a Ui interface as a web application: the page shell, per-request application and page documents, content-addressed scripts, stylesheets and fonts, and an event stream, drawn by a prebuilt React renderer. Ships the styling contract (parts, states, cascade layers) and the ui_react-1 component ABI with the useHost host module. An edit form sends the whole row back, since PUT replaces it: the row's model properties with each field's entered value over them, and an emptied field left out. Requires telo 0.112.0 or newer (requires: telo: ">=0.112.0").
