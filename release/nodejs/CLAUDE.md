# Release planner — package guide

Loaded when working under `release/nodejs/`. Repo-wide rules (a fragment for every change to a released unit, pre-1.0 minors) are in the root `CLAUDE.md`; the Telo adapter's pure half is in `analyzer/nodejs/src/release/CLAUDE.md`, its evidence half and the commands only Telo has in `cli/nodejs/CLAUDE.md`. Guides: `release/nodejs/README.md` (a plain Node project), `docs/extend/releasing-modules.md` (a Telo workspace), `docs/guides/workspaces.md` (the marker). The Rust twin is `release/rust` (`telorun-release`); both halves answer the vectors in `release/conformance/`.

`@telorun/release` is MIT, **off the telo version line**, and depends on nothing in this repo but `@telorun/glob`: no analyzer, kernel, CLI, templating or CEL. The main entry builds for the browser without polyfills (the editor still answers "what does this change bump?"); `@telorun/release/node` holds evidence, the adapters' evidence halves and the command tree a host mounts with `releaseCommands`. Bin `telo-release` is that tree over the ecosystems this package ships (`npm`, `cargo`, `docker`, `helm`, `pypi`); `telo release` is the same tree plus the `telo` ecosystem.

**The planner never branches on an ecosystem's name.** A **unit** is a directory with one version, one changelog (`<unit>/CHANGELOG.md`) and one fragment target, however many packages it ships. Each package is an **anchor** — an ecosystem plus a literal directory inside the unit, recognised there by the ecosystem's adapter (`adapter.ts`, the seam). An adapter defaults its anchor's version location and payload, contributes the schema of its own entry keys, and adds only what no declaration can hold: a computed payload and read-back. Adapters are registered in-process by the host program, never discovered from `node_modules`, because the Rust twin cannot discover; an entry naming an ecosystem the host registered none for is `WORKSPACE_ECOSYSTEM_UNAVAILABLE`. A core file naming an ecosystem or one of its files is a defect.

**Three questions, three mechanisms.**
- **Whether** a unit bumps: the digests of its layers at its recorded version against the ledger. Each anchor contributes one layer — a file set digested by one function (`node/files-digest.ts`: sorted unit-relative path, executable bit, content hash), never archive bytes or `dist.integrity` — and a declared `payload:` one more. A cargo anchor with a `bin`, `cdylib`, `staticlib` or `dylib` target also holds `Cargo.lock` — never the file on disk, but the sorted `name version source` lines of the external packages in its normal + build closure across every feature and platform (`adapters/cargo-closure.ts`: `cargo metadata --locked --offline --all-features`, so `cargo fetch --locked` runs first; recomputed on read-back from the `.crate`'s own lockfile and packaged manifest), so a lockfile-only bump releases the binaries that link it; a library-only anchor holds none. A pypi anchor's layer is the sdist its `[build-system]` backend builds through PEP 517 in a fresh venv (`node/adapters/pypi-build-sdist.py`, the frontend both halves run; the `.ts` beside it is its text, held to it by a test), less `PKG-INFO` and `*.egg-info`, with whatever the build leaves in the project removed; with no `[build-system]` it has none. A private npm package supplies its version and edges but no layer. A Telo module's layers are its artifact's, the `sbom` record among them, keyed by the `telo` adapter; the planner reads them as any other. No layer holds the workspace's `.changes/` (`isBookkeeping`), whichever adapter's file set reaches it: `apply` rewrites it after reading the layers, so one holding it would replan itself forever.
- **At what level**: the edge graph. Edges are never declared by hand — adapters supply import edges (`workspace:` and rewritten plain ranges, cargo path dependencies, Python runtime requirements whose source is a sibling anchor's directory, a module's relative imports), one generic rule supplies the rest (another unit's version location among the files a unit's payload is derived from — the files it holds, and any an adapter reports it reads into itself, such as a `package.json` whose version a bill of materials records), and a `metafile:` gives inline edges, which only explain drift the digest already saw. A dependent bumps at its dependency's level; a **group** releases every member at the highest level any needs; a level above `maxBump` is `MAX_BUMP_EXCEEDED`.
- **What is said about it**: fragments. A changed unit with no fragment ships as an unattributed patch and warns `CHANGELOG_ENTRY_REQUESTED`, for every unit.

**The version is resolved, never chosen by order.** A declared `version:` wins; otherwise the one anchor whose ecosystem defaults a location (`docker` defaults none); zero or several is `WORKSPACE_UNIT_VERSION_UNRESOLVED`. `apply` writes the version to every anchor's location and every `versionFiles` entry (a `Cargo.toml` also moves its `Cargo.lock` entry — a lockfile left behind makes every `cargo --locked` re-resolve over a network it forbids; a pypi anchor's `afterStamp` moves every `uv.lock` / `poetry.lock` / `pdm.lock` entry locked from its directory, a dependent's single `==` / `>=` / `~=` requirement, and that dependent's Poetry / PDM content hash, which must be the one the tool computes before it moves; an `afterStamp` hook names each file to the apply journal before writing it); the ledger records it and is never its source; `telo release check` refuses locations that disagree (`UNIT_VERSION_MISMATCH`). An anchor is exactly one package and covers nothing beneath it. A recognized package may report `noStaticVersion` (a reason: it is skipped as a version location and the unit must declare `version:`) and `noLayerReason` (what `WORKSPACE_UNIT_PAYLOAD_EMPTY` lists for it, beside the advice to declare `payload:` on the same entry). Every registry holds the `pyproject.toml` version-file handler (`[project].version`), so `version: pyproject.toml` works on a unit with no ecosystem. A unit with no layer is `WORKSPACE_UNIT_PAYLOAD_EMPTY`, a package directory claimed by two units `WORKSPACE_ANCHOR_CLAIMED`.

**The ledger is a cache; the registry is the authority.** `.changes/ledger.yaml` records per unit its `version`, its layers **as published** nested `<ecosystem>: { <anchor>: <digest> }` (a declared payload under the reserved key `payload`), an optional `registry:` and an optional `candidate: { version, layers }`. The credential-free PR gate reads the committed ledger, so the PR gate and the publish gate compute the same number; a *missing* entry is not drift. `verify [--write]` reconciles it per layer through each adapter's read-back; a layer with no read-back (`docker`, a declared payload) keeps its digest and is reported unverifiable. `baseline [--unit …] [--dry-run]` writes only the ledger, for units with no entry: read-back layers from the registry, the others from the working-copy digest `apply` records; an existing entry is skipped (naming one is an error pointing to `verify --write`), an unpublished or candidate unit is reported and left unrecorded. `check` does NOT fail because a payload moved (a toolchain bump moves every digest; those ship as unattributed patches): it fails when no consistent plan can be formed — a fragment naming no unit, a level above `maxBump`, disagreeing version locations, a registry mismatch.

**Candidates hold no state.** `apply --candidate[=<id>]` versions each planned unit `<final>-<id>.<k>` (default id `rc`); `k` is per unit, shared within a group, and rises only when a layer differs from the unit's `candidate:` record. A candidate consumes no fragment and leaves the final entry alone, so a plain `apply` always plans the final from final entries plus every pending fragment and removes the candidate records. Candidacy is the caller's per call, never repo state. `tag` tags the commit it runs at each unit the last apply moved, its tag format (`tag-format.ts`: `release.tagFormat` or the entry's own, default `{key}@{version}`, the root unit's `v{version}`) rendered at the new version; every reader of a tag takes the rendered `tag` from the plan or `order` JSON. Each resolved unit carries its `tagPattern` (the text around each version), so rendering is a join and `WORKSPACE_TAG_COLLISION` is decided on the patterns before any tag exists.

**Changelogs** are written by one writer in the module format (a multi-line body's continuation lines indented two spaces); history a previous tool wrote stays below the new entries untouched. **`-o markdown`** on `status`, `check` and `apply` is the plan as a CommonMark document (`plan-markdown.ts`, pure: units with entries first, their entries through the changelog writer's own lines, then one section for the rest), written only on success; `--max-length` picks the first of its stated shrinking stages that fits, counting code points, and refuses when none does. The host declares `-o` with `text` and `json`; only the plan commands add `markdown`, so every other command refuses it as a usage error. **`adopt changesets`** (`node/adopt-changesets.ts`) is the one place `@changesets/*` formats are read: it writes one `release.units` entry per package, `fixed` groups → `release.groups`, `ignore` → `!` entries, each pending change file → a fragment with the same units, body and id, seeds the npm layers through `verify --write`, refuses `linked` groups, deletes `.changeset/` and lists the CI steps and dependencies it did not rewrite.

**A destination** is the resolved `registry` plus the unit's name, assigned and never derived from an importer's path; `registry` cascades anchor → `release.ecosystems.<eco>` → the adapter's own rungs (only `telo`: `--registry`, `TELO_OCI_REGISTRY`, the ledger's recorded base). `NO_DESTINATION_KNOWN` and `DESTINATION_COLLISION` cover every `order` row.

**The marker** is `telo-workspace.yaml`'s `release:` block — `units`, `groups`, `ignore`, `maxBump`, `ecosystems` — read leniently with diagnostics (`marker-reader.ts`, `marker-schema.ts` as data, `release-settings.ts`); an ecosystem's keys are read only at its anchors or under `release.ecosystems.<eco>`, anything else `WORKSPACE_UNKNOWN_KEY`. The Rust twin reads YAML with its own parser and refuses a malformed file, where Node's `yaml` recovers; `release/rust/README.md` lists every difference.

## Where to look

- Planning → `release-plan.ts` (the planner, `propagate`), `units.ts` (units, anchors, `WORKSPACE_ANCHOR_*`), `bump-level.ts`, `fragment.ts`, `changelog.ts`, `ledger.ts`, `version-files.ts`; what a person reads of a plan → `bump-reason-text.ts`, `plan-markdown.ts`, `node/render.ts`.
- The marker → `marker-reader.ts`, `marker-schema.ts`, `release-settings.ts`.
- Adapters → `adapters/{npm,cargo,docker,helm,pypi}.ts` (pure halves; `adapters/toml-document.ts` the span-keeping TOML reader pypi edits through), `node/adapters/` (evidence: pack lists, `cargo package --list`, Docker's ignore rules, `helm package`, the PEP 517 sdist build, read-back), `adapter.ts` (the seam).
- Evidence and commands → `node/evidence.ts`, `node/operations.ts`, `node/commands.ts`, `node/host.ts` (what a host supplies), `node/carried-changes.ts`, `node/metafile.ts`, `node/declared-payload.ts`.
- Conformance → `release/conformance/` (README is the format), `release/nodejs/tests/conformance.test.ts`, `release/rust/tests/conformance.rs`.
