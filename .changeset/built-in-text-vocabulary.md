The built-in text vocabulary. A field or a function parameter holding text shown to a person is typed by the new fragment `telo://manifest#/$defs/Text` — a MessageFormat 2 pattern with `{$name}` placeholders, a plural selection `{ plural, cases }`, or either with a `context` — beside `Message` and `TextCatalog` (`{ lang, texts: [{ text, context?, translation }] }`). A module declares the language its texts are written in with the new top-level key `lang:` on `Telo.Application` / `Telo.Library`, and two Telo formats join `css-selector`: `language-tag` (RFC 5646) and `message-pattern`. Two annotations: `x-telo-text-context` gives a data schema node's title, description and enum values a context, and `x-telo-text-values-for: /<pointer>` names the `Text` an object holds the values of. `telo check` refuses, each where it is written and judged in the language of the module that wrote it (a template body's text by its library, a value a template or `base:` forwards by its consumer): `MESSAGE_SYNTAX_INVALID`, `MESSAGE_PLURAL_CATEGORY_INVALID`, `MESSAGE_SOURCE_LANGUAGE_MISSING`, `MESSAGE_PLACEHOLDER_UNKNOWN`, `MESSAGE_PLACEHOLDER_UNBOUND`, `MESSAGE_PLACEHOLDER_VALUE_UNSUPPORTED`, `MESSAGE_ENTRY_COMPUTED`, `MESSAGE_ENTRY_DUPLICATE`, `TEXT_ARGUMENT_COMPUTED` (a `Text` parameter takes only a literal argument) and `TEXT_VALUES_FOR_INVALID`, and warns `MESSAGE_TEXT_UNUSED` (a catalog entry no text of its module's imports shows) and `TEXT_CONTEXT_MISPLACED`. The kernel raises each as `ERR_<code>` at creation and when it binds a call — for a computed text, computed values and a dependency's own texts — and hands a controller each `Text` as the record `{ text, context, lang, computed }`: `TextRecord` / `MessageSource` / `isTextRecord` in `@telorun/sdk`. `CompiledValue.callArguments` records how each module call's arguments are written. A recursive fragment is now hoisted into the root of the schema holding the reference — including a callable's parameter and result schemas and a need type's `parameters` and `fields` — so a parameter typed `Text` checks and binds; `argumentRecordSchema` and `liftFragmentDefs` are the analyzer's readers for a schema composed over such roots (`parameterContextProperties` is removed in favour of the first). A text a controller evaluates per call — in an `x-telo-eval: runtime` field or a CEL region — is settled when it is evaluated: `ctx.expandValue` judges it in the language of the module that wrote it, hands each `Text` back as its record (`computed: true`) and judges the values the same evaluation produces; `Value.Expand` lists the five `ERR_MESSAGE_*` codes and its result's `Text` is its record. A kind typing a text at or beneath an `x-telo-eval: accessor` field is refused — `TEXT_SLOT_ACCESSOR` at the kind (at the `imports:` entry for a dependency's), `ERR_TEXT_SLOT_ACCESSOR` when the kernel registers it — and a values map whose entries are accessor fields is read as its bindings, a chain typed by `telo check`. The Rust kernel refuses a resource whose kind holds a `Text` (`ERR_UNSUPPORTED_MANIFEST_FEATURE`).
