A `!cel` argument at a call site is held to the target's declared `inputType` by `telo check`, as a resource's own fields already were. A step's `inputs:`, an Application boot target's inline step, every reference slot's `inputs:` map (an `Http.Api` route, `Stream.Tap`, `Schedule.Interval`, `RecordStream.EndHandler`) and a templated `Telo.Definition`'s top-level `inputs:` (whose literal half stays `TEMPLATE_TARGET_MISMATCH`) now report `CEL_TYPE_ERROR` at the argument when its expression's type does not fit the slot — a string into an `integer`, a map into a `string`, `duration(...)` into a `string`, a chain declared a string into an `integer` — where the manifest checked clean and failed at dispatch with `ERR_INPUT_INVALID`. A plain chain reading a value its producer declares nullable into a field or argument whose declared type takes no null is `CEL_TYPE_ERROR` too, naming the source and the guard to write (`x != null ? x : <fallback>`); a guarded, computed or `dyn(...)` expression, and a result its producer does not declare, are left to the runtime. A `$ref` in a declared schema is read as the shape it names — a named shape, or a document-local pointer resolved in the document that declares it — on the producer's side at every hop of the chain and on the slot's side at its leaf and union branches, so a nullable or mistyped producer behind a reference is reported where it was silent. An expression at a path that is both a field and an argument map (a whole-map `inputs: !cel`) is reported once: against the target's `inputType`, and against the field only when that passes. One rule decides the code when a plain chain's declared shape conflicts with its slot, at a resource's own field and at a call site alike: `CEL_TYPE_ARGUMENT_MISMATCH` exactly when every conflict lies beneath a type argument of a value type both sides name (a stream of bytes into a stream of strings, at any depth), `CEL_TYPE_ERROR` for everything else — two different value types, `Telo.Bytes` against `type: object`, two JSON types neither of which contains the other, a missing required member. An own-field conflict outside a type argument therefore moves from `CEL_TYPE_ARGUMENT_MISMATCH` to `CEL_TYPE_ERROR`. JSON types compare by containment in the shared schema comparison: a declared `integer`, and a value type whose base is one (`Telo.TcpPort`, `Telo.Uint64`), satisfies a `number` slot, while a `number` into an `integer` slot stays a conflict. Integer-into-number is therefore no longer reported by any check built on that comparison — `CEL_TYPE_ERROR`, `CEL_TYPE_ARGUMENT_MISMATCH`, `FUNCTION_RETURN_MISMATCH`, `FUNCTION_ARGUMENT_MISMATCH`, `CONTRACT_NOT_SUBSTITUTABLE`, `TEMPLATE_FORWARD_INCOMPATIBLE`, `REFERENCE_OUTPUT_MISMATCH`, a callable slot's structural match.
