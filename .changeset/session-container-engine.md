Runners serve each session a container engine of its own, so a test that starts the database it needs runs in a session exactly as it runs locally. With `RUNNER_SESSION_CONTAINERS=true` (default off; chart `session.containers.enabled`) every session gets `TELO_HOST_CONTAINER_ENGINE_URL` (`<RUNNER_INTERNAL_URL>/v1/sessions/<id>/engine`) and `TELO_HOST_CONTAINER_ENGINE_TOKEN`, a token minted for that session; `RUNNER_INTERNAL_URL` is required when the setting is on, and a runner whose backend cannot run containers refuses to boot with it. The engine answers the Docker Engine API 1.41 requests `Docker.Engine` sends and refuses every other one: a missing token is 401 and another session's 403; a create may carry only `Image`, `Cmd`, `Entrypoint`, `Env`, `User`, `ExposedPorts`, `Labels` and `HostConfig.PortBindings` as one `127.0.0.1` binding with an empty `HostPort` per exposed port, anything else being a 400 naming the field path; every container is labelled `run.telo.session=<id>`; a session holds at most `RUNNER_SESSION_CONTAINERS_MAX` (default 4) containers, a create beyond it being 429; inspect, logs, delete and list see only the session's own containers. Nothing is published on a host: inspect answers each requested binding with the address the session reaches the container at. A session's containers are removed when it stops, suspends, reaches its deadline, is deleted or changes its app set, and when the runner shuts down. The docker runner runs them as siblings on `RUNNER_CHILD_NETWORK` and removes every container labelled with a session at boot; the k8s runner runs them as pods under the session namespace's `restricted` Pod Security standard (a `User` that is not a numeric non-root `uid[:gid]` is a 400), with resources from `session.containers.resources` (`RUNNER_SESSION_CONTAINERS_RESOURCES`), owned by the session's pod and reachable only from that session through two per-session NetworkPolicies, deleted when the session ends; the chart's Role gains `networkpolicies` when the setting is on. A pod the Pod Security standard refuses is now reported as that refusal rather than as an unexplained 403. A k8s run session's body-fetch init container now declares the session's resources, so the chart's default resource quota no longer refuses every run session pod.
