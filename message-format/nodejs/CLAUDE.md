# Message core (Node) — package guide

This guide is loaded when working under `message-format/`. Repo-wide rules live in the root `CLAUDE.md`. This package is `@telorun/message-format`, on the telo version line. Its Rust twin is `message-format/rust` (`telorun-message-format`), and the two are one artifact in two languages.

## The boundaries

- **No dependencies, no host locale.** The package has no runtime dependency and no workspace dependency in either direction. The SDK, the analyzer and the renderers consume it; it consumes nothing. Nothing in `src/` may reach `Intl`, a `toLocale…` method or `localeCompare`. `check:browser-safe` builds a real browser bundle and refuses a Node built-in in it, and refuses any of those names in the bundle or in any `src/` file compiled on its own (so code the bundle shakes out is judged too, and a comment is not), because two hosts that answer from their own locale data disagree.
- **No host vocabulary.** The core knows Messages, languages and numbers. The `Text` record, catalogs, `lang:` and the `ERR_` twins belong to the analyzer and kernel, which call it. The one borrowed rule is the Telo name rule for placeholder names, including CEL's 21 reserved words, copied here because the core depends on nothing.
- **The SDK re-exports it whole**, so a controller formats through the SDK's copy. The kernel's realm collapse lists the SDK, not this package.

## The model is the wire

A read Message is plain JSON:
- A pattern is a list of strings and `{ placeholder }` parts.
- A selection is `{ plural, cases }` with its cases in written order.

A host can send a parsed Message across a wire, and the receiving side calls `formatMessage` on it unchanged. A shape change is therefore a change to every wire that carries one.

## Faults

Reading collects every fault, each with a path into the data and, inside a pattern, a UTF-16 range. `MESSAGE_SYNTAX_INVALID` means "not a well-formed Message or Text", which covers:
- an unparsable pattern;
- a selection with no `other`;
- a case key that is not a category or a canonical `=N`;
- an `=N` outside int64 ∪ uint64;
- a selector that is not a name;
- an empty context.

Formatting throws one `MessageFormatError`. It checks every name the message reads, on every branch and in written order, before choosing any branch, so a missing value fails whatever the count is. The two cores word every message identically, and the vectors pin the wording.

## Numbers are value-determined

`1.0` and `1n` are both "1" and `one`. The pipeline:
1. Take the shortest round-trip digits: `String(n)` in Node, `{:e}` in Rust. These agree, and a 30 000-value random cross-check agreed when this package was written.
2. Round half-to-even on those decimal digits, not on the binary value, so `0.0125` → "0.012" and `0.0135` → "0.014".
3. Drop trailing zeros and unsign a zero result.

Plural operands come from the rounded decimal as text, so an integer of any size is exact and `remainder` reads the digits one at a time. `=N` keys compare numerically against that decimal.

## CLDR data

`scripts/generate-cldr-data.mjs` writes `message-format/cldr/*.json` from the exact-pinned devDependencies. The values are verbatim CLDR. A number entry equal to what its parent resolves to is omitted, and the generator asserts that resolution is unchanged by the omission. `tests/cldr-data.test.ts` runs the generator in `--check` mode, so the tracked data provably is the pinned release.
- **Changing the data is a version bump of the pins**, then `pnpm -C message-format/nodejs run generate:cldr`, then the vectors.
- **The Node core reads the data through `src/cldr-data.ts`**, generated by `prepare` and before every build, test and check. It is gitignored because the JSON is the one copy. It opens with the `/*! */` Unicode License V3 notice, and its type import sits last because TypeScript drops a comment that leads an elided import.
- **`prepack` copies the licence in as `LICENSE-CLDR`.** It refuses to pack unless both the licence file and the built `dist/cldr-data.js` carry the notice.

How a tag resolves:
- Lowercase it and set its extensions aside.
- **Number data** goes through the main `parentLocale` map. Failing that, a `lang-Script` tag whose script is not the language's likely one has the root as its parent (`nonlikelyScript`, from `likelyScripts`). Failing that, truncate.
- **Plural rules** go through the plurals component's own map, which stands alone (TR35 §4.1.3), then truncation.
- Every chain ends at `root`.

## The vectors

`message-format/conformance/` holds one vector set, read by `conformance/vector-runner.ts` here and `rust/tests/conformance.rs` there. Both pin the row count of every set, plus 12 396 expanded CLDR samples.
- **The runner takes the core as a parameter and reads no file**, so a browser entry that inlines the core runs the same rows. Load them with `conformance/load-vectors.ts` or any other way, then call `runVectors(core, vectors)`.
- **Its blind spot** is a row rewritten in place, which shows up as a fixture diff. A row that goes missing fails the count pin.
