# Lens: Data modeling

**Applies to** the shape of data that outlives a request, on any backend — SQL, KV, journals, event
payloads, runtime-written files. Relational is one case, not the frame.

**Casing:** SQL snake_case (`created_at`); Telo fields and JS properties and functions camelCase
(`createdAt`). Field names below are in SQL form.

## Principles, in ranking order

1. **One owner writes.** Nothing else writes its store. Reads across a component boundary go only
   through the owner's contract or a read model it publishes; inside the component, reads are free.
   The owner is one logical writer on N replicas.
2. **The store guarantees integrity; the owner holds the rules.** The store enforces types, required
   fields, uniqueness, references and conditional writes — what concurrent replicas cannot enforce
   alone. Business rules live in the owner. Allowed value sets live in the owner's schema and are
   stored as plain values: no store enums, no constraints listing values, no triggers, no stored
   procedures — they cannot evolve without downtime and do not exist on every backend.
3. **Identity.**
   - Internal key: UUIDv7, generated by the owner before the write, never crossing a trust boundary.
   - Exposed records add a public ID `<prefix>_<random>`: at least 128 random bits, alphabet chosen
     by distinguishing question 13. Lowercase 3-letter prefix (4 on collision), unique in the
     system, recorded with the model, frozen once published, declared in every contract field
     carrying it. Contracts carry only public IDs. A public ID derived from the internal UUIDv7 is
     disqualified — it exposes the creation time.
   - Natural and external identifiers are uniquely constrained fields, never keys.
4. **Evolution without downtime:** expand → migrate → contract.
5. **Access paths drive indexes and keys.**
6. **One source per fact.** Copies only as immutable historical facts owned by the holding record,
   or derived read models (one owner, rebuildable, declared staleness).
7. **Capture moment-only facts when they happen** — when, who, the value then — whether or not
   anything reads them yet. They cannot be reconstructed.

## Distinguishing questions

1. Source, or derived?
2. Relation live, or historical?
3. Must anything outlive the record?
4. Personal data?
5. Shape ours to fix?
6. Own lifecycle, part of another record, or pure link?
7. Real-world occurrence?
8. Instant, local wall-clock time, or calendar date?
9. Collection with a small fixed maximum?
10. Money settled, or a rate / unit price?
11. Secret only checked, or presented to a third party?
12. Exposed across a trust boundary?
13. Public ID read, typed or dictated by people, or handled only by code?

## Consequences

- **Derived** → read model. A derived value stored beside its source in the write model is
  disqualified. State is a status field (CRUD) or derived from recorded facts (aggregate) — never
  both as sources.
- **Read model identity** → it mints no identity and carries no lifecycle fields of its own (no
  UUIDv7, public ID, `created_by`…) — minting one makes it a second source. Inside the owning
  context it is keyed by the source's internal key and carries the source's public ID when it
  serves the boundary; in another context it is keyed by the source's public ID and holds only the
  fields it needs. It records the source version it last applied, for staleness and for stale or
  skipped events.
- **Live reference** → one target type, existence enforced by the store. **Historical** → type +
  ID, type values in the owner's schema, target may be gone and readers handle it.
- **Must outlive** → soft delete via `deleted_at`; uniqueness among live records only; owner reads
  and read models exclude deleted. **Nothing outlives, no history needed** → hard delete.
- **Personal data** → erasable. Erasure scrubs personal fields independently of deletion.
  Immutable places hold the person's ID; unavoidable embedding is encrypted with a per-person key
  destroyed on erasure.
- **Shape ours** → real fields; structured data in an opaque field is disqualified. **Not ours**
  (external payloads kept verbatim, historical snapshots of evolving schemas) → opaque allowed.
- **Own lifecycle** → `created_at` + `created_by`. Mutable → `updated_at` + `updated_by`, unless an
  audit log records each change and actor. Every state transition → `<participle>_at` +
  `<participle>_by`. Parts and pure links carry none. Actor = historical reference (person, client
  or system type + ID); automated actions use an explicit system actor; acting on behalf of
  someone records both.
- **Real-world occurrence** → its own occurrence date from input, correctable, never derived from
  `created_at`; same for effective and due dates. A real-life party is a domain field, distinct from
  `created_by`.
- **Instant** → UTC, `<participle>_at`. **Local time** → local date-time + zone. **Calendar date**
  → plain date, `<participle>_on`.
- **Small fixed maximum** → may live inside the record. **Unbounded** → own record type referencing
  its parent.
- **Settled money** → integer minor units + currency, minor-unit count per currency. **Rates, unit
  prices** → exact decimal.
- **Secret only checked** → one-way hash. **Presented to a third party** → encrypted.
- **Exposed** → public ID; no cursor or token reveals the internal key.
- **Handled by people** (support tickets, hand-typed URLs, phone calls) → Crockford base32:
  case-insensitive, no look-alike characters. **Only by code** → base62: shortest, the convention
  developers expect.

**Always:**
- Records listing their own field names as data (`name` + `value` rows) are disqualified.
- Small bounded sets are returned whole; large or growing sets page by opaque cursor over a stable
  order with a unique tiebreaker. Offset paging over a large set is disqualified.
- No floating point for money.
- No domain time derived from an ID.
- One alphabet per prefix, fixed when the prefix is published; one concept never appears in two
  encodings.
- Conflicting writes are detected by a `version` counter, "changed since" feeds by a change log or
  outbox — never by timestamps.

## Horizon

100× the rows · a second writer replica · several tenants · a zero-downtime schema change · a
second backend behind the same abstract · a consumer nobody has written yet.

## Verify

1. The migration applies as expand → migrate → contract, each step deployable beside the previous
   code.
2. The store, not only the owner's code, rejects a write breaking an integrity guarantee.
3. The model is expressible on every backend behind its abstract.
4. No internal key appears in a contract crossing a trust boundary.
5. After erasing a person, none of their data is readable in records, journals, events or read
   models, and every reference to them still resolves.
