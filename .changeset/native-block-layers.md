A `Telo.Library` or `Telo.Application` doc may declare its platform-specific files in a `native:` block, one closed entry per file per platform tuple (`name`, `format`, `os`, `arch`, optional `libc` and `abi`, module-relative `path`). `telo check` reports `NATIVE_NODE_ABI_MISSING` (a `format: node` entry without `abi`), `NATIVE_NAPI_ABI_FORBIDDEN` (a `format: napi` entry with one), `NATIVE_LIBC_OFF_LINUX`, `NATIVE_ENTRY_DUPLICATE` (one name, one selector, twice), `NATIVE_PATH_SHARED` (different selectors, one path), `NATIVE_PATH_NESTED` (a path running through another as a directory), `NATIVE_PATH_CLAIMED` (a path the module also names as a controller candidate's `path=`, an `exports.code:` entry or an `!include-*` embed, naming that declaration), `NATIVE_PATH_ESCAPES_MODULE` and `NATIVE_ENTRY_INVALID` (a name or selector value outside the token grammar), for the entry module's own block; a controller candidate and an `exports.code:` entry report the N-API and libc rules as `CONTROLLER_NAPI_ABI_FORBIDDEN` / `CONTROLLER_LIBC_OFF_LINUX` and `LIBRARY_NAPI_ABI_FORBIDDEN` / `LIBRARY_LIBC_OFF_LINUX`. The layer index recognizes `native` as a selector-carrying role, one layer per selector, where it was previously skipped as unknown. `telo publish` places each entry's file in its selector's `native` layer, ahead of `files:`, `assets:` and `siblings=` patterns selecting it; refuses a file also named by a controller candidate, an `exports.code:` entry or an `!include-*` embed; fails naming an entry whose file is absent; and publishes the `native:` block unchanged. A module adopting the block needs a `requires: telo:` floor at this release.
