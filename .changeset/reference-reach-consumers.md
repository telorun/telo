A reference slot is now reached wherever a kind's schema writes it: behind a local `$ref` (`target: { $ref: "#/$defs/Target" }`), inside a root `anyOf` / `oneOf` / `allOf` branch, under a root `additionalProperties` (every key but the declared ones and `kind` / `metadata`), and at every depth of a recursive `$defs` shape, as deep as the resource's data goes. Before, `telo check` was clean at such a slot while the kernel handed a `!ref` to the controller raw, never created an inline declaration written there (the run failed with "must be a `!ref`"), and `!ref nosuch` there went unreported. Now a `!ref` arrives as the live instance, an inline declaration is extracted and runs, and a missing target is `UNRESOLVED_REFERENCE` at its concrete path — the same as a plain `properties` slot. Every consumer — Phase-5 injection, scope creation, the inherited-controller path, inline extraction, `!ref` resolution, reference validation, the dependency and call graphs, invocation contracts, observed state, peer binding, template bodies and the editor's port list — reads one enumeration of the kind's reach, so `telo check` and the kernel cannot disagree about where a reference is. A step body is still not a slot — a step's `invoke:` resolves at dispatch — except a step list whose items are themselves references, as an Application's `targets:` are. `TEMPLATE_REF_COMPUTED` and a module graph's forwarded edges now find a value written above a reference slot at any depth of a recursive shape too. An `x-telo-schema-from` failure the kind alone decides (`INVALID_SCHEMA_FROM`, an alias-qualified anchor naming nothing) is still reported for every resource of the kind at the declared pattern, now also at patterns behind a local `$ref` or in a root branch; `CONTRACT_SLOT_INPUTS_UNSATISFIABLE` and `CONTRACT_INPUTS_AT_RUN_SITE` name the concrete path.

`x-telo-scope` is legal only on a named top-level property — one in the schema root's `properties` or in a root variant's, written directly or through a local `$ref` — and a scope there (a root `anyOf` branch, a `$ref`'d `with:`) is now stood up. Anywhere else (nested under an object, on an array item, under `additionalProperties`, inside a recursive shape, below an `x-telo-schema-from`) is `SCOPE_SLOT_MISPLACED` at `telo check`, and the kernel refuses the definition at registration with `ERR_SCOPE_SLOT_MISPLACED`, a dependency's kind included.

`@telorun/analyzer`'s field-map API is replaced by the reach: `buildReferenceFieldMap`, `isRefEntry`, `isScopeEntry`, `ReferenceFieldMap` and `shapeMatches` are removed from the package exports; `reachSites`, `declaredReach`, `siteRefEntry` and `scopeSlotProblems` (with their types) are added. `AnalysisRegistry.iterateFieldEntries` is replaced by `referenceSitesOf`, `ModuleGraphDeps` gains `refSites` and `refPositions`, and a `PeerBinderEnv` supplies `refSitesOf` beside `refSlotsOf`.
