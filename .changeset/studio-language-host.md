Changed: every diagnostic studio shows — source view markers, form fields, topology and outline badges, the module's diagnostics summary — and the source view's completion, hover, go-to-definition, rename, signature help, semantic colouring, quick fixes and import-upgrade lenses — and the same features in a resource's YAML pane, which now edits its file's text live — come from the engine of the telo version each module is edited against, running in a Web Worker behind `@telorun/language-host`. The engine studio ships is served with the app as `engine/language-server-<content hash>.mjs` and named by its own handshake — a build of an unreleased tree shows **Telo X (unreleased build)**; other versions are downloaded from the npm registry, verified, and kept in Cache Storage `telo-engines`. A new per-workspace telo version setting (Auto, or an exact version) sits in the top bar beside a "Telo X" status that names what chose X, or the error state with "Select version" and "Retry" — an engine that crashes or never starts included. The structured views (topology, forms, canvas) keep reading studio's bundled model. Running is unaffected.
