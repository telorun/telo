# Changelog

## 0.20.0 - 2026-11-01
### Added
* An application's contract carries its requiredness: each input's `required` is true only where some configuration of the application requires it, with `requiredWhen` listing those configurations, a `default` is served only where one is declared, and `dimensions` names each key's values and the environment variables it is read from. Ingest revision 10 re-ingests every tracked version to record them, and refuses an application whose `telo module manifest --json` payload carries no `dimensions`.
* An application's reported dimensions carry a member dimension's member, which a reader no longer splits out of the key; INGEST_REV defaults to 11, so the deploy re-ingests every tracked version once.

### Added
* The library design guide says how a kind declaring a catch list marks its caught code and data with `x-telo-caught-member`.

### Fixed

## 0.17.0 - 2026-10-18
### Added
* The database is the application's databaseAccess need (Postgres.DatabaseAccess, asking for pgvector), still read from DB_CONNECTION, so a server without the pgvector extension refuses to start with ERR_NEED_UNMET instead of failing at the first vector query. The server binds its port under listen:, as http-server 0.38.0 requires. Requires telo >=0.117.0.
* The hub tracks the built-in vocabulary every telo release publishes, at BUILTINS_REF (default oci://ghcr.io/telorun/telo), registered on every boot before SEED_REFS: a Telo.Builtins root is indexed (root kind Builtins, no runtime facts) and registrable there and refused with INGEST_ROOT_KIND_UNSUPPORTED anywhere else. Search hits and list_libraries entries from it carry builtin: true. get_kinds takes a telo version and reads every built-in at it (the latest tracked by default), heads the vocabulary's own kinds with a no-import line, closes every answer over the schema fragments, value types, zone attributes and formats it names, and refuses an untracked version (ERR_UNKNOWN_TELO_VERSION); its telo argument is a release as telo --version prints it, never an X+unreleased build, whose built-ins come from that CLI's telo builtins. Need types are indexed as kinds, with the runtime reach the CLI reports for them (the kernels serving need types, nodejs today), so a runtime filter selects them; an extends or replacedBy prefix of Telo resolves to BUILTINS_REF and a module's own name to the module, where Telo used to leave the ref empty. Ingest revision 9 re-ingests every tracked version once.

## 0.14.0 - 2026-10-13
### Added
* A Helm chart, apps/hub/chart, published as oci://ghcr.io/telorun/charts/hub at the hub's own version. It deploys the hub alone as one unprivileged instance; the database, the manifest bucket and the embeddings server are supplied, and every credential is read from a named Secret.
* Discovery tools shaped for a model's context. The search_resources tool takes several queries in one call (queries, each answered under results) and a limit per query (default 8), groups hits under the module that owns them so a module's ref, version and description are stated once, and leaves out members that say nothing. New get_kinds tool returns the definitions of exactly the kinds named, across modules, with each module's imports line (ref, version and integrity pin), the shapes and parent kinds a definition references, and no controllers. New list_libraries tool lists every tracked library in one line each, optionally for one publisher. Search ranking gains an identity arm: a query spelling a module and kind name (http server) leads with that module's kinds. Breaking: the search_resources tool no longer answers a flat hits list with the categories facet on every response; read results[].modules[].hits, and list_categories for the facet. The HTTP search routes are unchanged.
* Four additions to the discovery surface. GET /search/modules and /search/resources (and the search_resources tool) take publisher, narrowing to the modules whose module.publisher equals it; the new GET /publishers lists the publishers that hold a searchable module with their module counts. GET /search/modules takes sort (relevance, name, recent), where recent orders by when the hub first tracked the listed version and each hit carries that instant as module.trackedAt. Both parameters are echoed in the response, so a caller can tell a hub that applied them from an older one that ignored them. The new GET /module/manifest serves a tracked version's telo.yaml as text. Ingest now records what each version imports: /module and get_module carry imports and a dependents count, and the new GET /dependents and find_dependents tool list the modules importing a given one. INGEST_REV defaults to 7, so the deploy re-ingests every tracked version once.
* GET /search/modules takes deprecated and contractOnly (include, the default, or exclude), applied before the page is cut, so total and every page count what is listed; the response echoes both and reports what they left out as hidden.deprecated and hidden.contractOnly. total is now reported for a page with no hits. GET /dependents is paged with limit (1 to 100, default 50) and offset and reports total; find_dependents takes the same two arguments and returns each importer as ref, name and a one-sentence summary instead of its whole description. The search resource refuses a sort outside relevance, name and recent for every caller, not only on the HTTP route.
* The embedder is configurable: EMBEDDER_MODEL, EMBEDDER_DIMENSIONS, EMBEDDER_QUERY_PROMPT and EMBEDDER_PASSAGE_PROMPT name the model, its vector length and its prompt wrappers, and an optional EMBEDDER_API_KEY is sent as a bearer token to an embeddings API that asks for one. The defaults are embeddinggemma-300m's and no key, so an existing deployment is unchanged. Changing the model, the vector length or a wrapper is a re-embed of the whole index.

## 0.12.0 - 2026-10-03
### Added
* New `GET /modules` lists every module the hub can describe with its latest version, paged by a stable sequence number, so sites can build complete sitemaps of the catalogue.
* The hub registers and indexes Telo applications. `POST /register` accepts a root `Telo.Application` as well as a `Telo.Library` (anything else is refused naming the root kind); an application is tracked, pinned and cached like a library and indexed by its declared `variables` / `secrets` / `ports` contract, which `/module` and `get_module` return as `application` (null for a library; no secret value is ever stored or served). `/search/resources`, `/search/modules`, `/categories` and the `search_resources` / `list_categories` tools take an `entry` filter (`kind`, `instance`, `application`; default `[kind, instance]`, so no application displaces an existing result); `runtime` combined with `application` is refused as `ERR_RUNTIME_FILTER_UNSUPPORTED`, and `/refs` / `suggest_module_refs` never list an application. Breaking: `TELO_BIN` is replaced by `TELO_COMMAND`, a JSON array (default `["telo"]`) naming the telo the origin reads run, which must be the hub's own generation; the development image points it at the checkout's CLI. `INGEST_REV` defaults to 6, so the deploy re-ingests every tracked version once: a version's root kind can only be learned from its manifest, and applications seeded earlier had their own kinds stored as exported.

## 0.11.0 - 2026-09-24
### Added
* Search ranks exported instances exactly as it ranks kinds: each is embedded and matched, and a hit on /search/resources, search_resources or a module hit's matchedKinds carries entry (kind or instance), name, kind and kindRef. The separate instances list on /search/resources and search_resources is removed; its entries are now hits. A module that only packages ready-made instances, such as one module per OCR language model, is a search result like any other; matching instances of one kind fold into the best-ranked hit as siblings, and so do modules whose every match is one. A module hit lists its implementations, the modules extending its kinds, and a kind is also found by the words of the contract it extends. Instances are also reached from the kind they instantiate: GET /instances and the new find_instances MCP tool list every instance of a kind across modules, and every kind in a search hit or on /module carries an instances count. /categories counts only modules that export a kind or an instance. Existing versions pick up the kind owner on their next ingest; INGEST_REV now defaults to 5, which re-embeds every module. /module and get_module now also list the kinds a module re-exports from an import, marked reexported and described by their owning module, and every listed kind carries its owner's ref; re-exported kinds are not search hits. The web module page shows re-exported kinds and expands a kind's instances. The authoring agent's primer uses find_instances.
* SEED_REFS may name a ./-relative module directory read from the hub's own disk when ALLOW_LOCAL_REFS is true, recorded under a new local transport; the compose stack uses it to index the checkout's unpublished modules. A local module's relative imports are resolved against its own ref, so its extends targets and instance kind owners link to the modules seeded beside it. POST /register still refuses a path. A seed entry that is neither oci://, https:// nor an accepted local path now stops the boot with ERR_INVALID_MODULE_REF instead of being recorded as a url module.

## 0.8.0 - 2026-09-07
### Added
* The hub is now a composition root over six libraries — schema, origin, ingest, search, catalog and registry — each handed the one connection, bucket, embedder, vector index and shell host it needs, so a change is read against one concern instead of a 2600-line file. Ingest is a durable run per module version: the manifest read, the bucket write and the relational writes are recorded step by step, the writes commit as one transaction on the connection the journal records through, and a transient origin failure parks rather than sleeps. POST /register answers 202 and schedules the work instead of ingesting inside an anonymous request; GET /register/status?ref= reports progress. A new version_ingest table decides what is due and mints each attempt's identity in one write, so two concurrent passes collapse to one run and a failed attempt never burns the id its retry needs. TRACK_INTERVAL and TRACK_LOOP are replaced by TRACK_CRON and TRACK_ENABLED, and INGEST_REV is the whole-registry re-ingest control.

## 0.7.0 - 2026-09-03
### Added
* BREAKING. The Telo HTTP registry is gone, so the hub no longer tracks bare `<namespace>/<name>` refs. `/register` now requires an `oci://` or `https://` scheme on the submitted ref, and the transport a registration records is `oci` or `url`. A migration DELETEs the rows already stored under transport `registry` and adds the CHECK constraint the column never had. Deleting is the honest option rather than filtering them out of reads: those refs resolve nowhere, so `telo module versions` on one exits non-zero and the row fails every tracking pass forever, while leaving them readable means search and `get_module_manifest` hand a caller a ref they cannot import — worse than a 404. The delete cascades to `module_versions`, `resource_kinds` and `module_resources`; rows orphaned in the pgvector backend's own table are left alone, since the hub does not reach into it and the RRF query joins vector ids back to the relational rows, so an id with no row yields no hit.

JSON has one number type, so the wire value is unchanged.## 0.6.0 - 2026-08-03
### Added
* Runtime, language and deprecation facets, plus a module detail route. resource_kinds gains runtimes/languages/portable and a resolved deprecation (reason + replaced_by_ref/replaced_by_kind, resolved through the declaring manifest's imports exactly as extends is); module_versions gains homepage, deprecation, a languages list, a portable flag, and the runtime roll-up as `runtimes` (every kernel with at least partial reach) plus `runtimes_full` (the subset covering every kind) — split so a filter reads one column while a UI can still say "Rust (partial)". All of it comes from `telo module manifest --json`, so this app parses no PURLs: the mapping from a controller PURL to the kernels that can load it is loader knowledge, and a second copy here would drift. Publisher is derived from the ref by a new `module_publisher(ref, transport)` function rather than declared — ownership is a property of the host, and a `url` module is attributed to its host alone since its path segments are a directory, not an organisation. /search/resources, /search/modules and the search_resources MCP tool take a `runtime` filter (`nodejs`, `rust`); a portable kind satisfies every runtime. New GET /module returns everything a module page renders in one call — metadata, every exported kind with its own runtime and deprecation, exported instances and the tracked version list — keyed by ref and able to serve a non-latest version, neither of which a search hit can do. `module_versions.runtimes` is nullable and NULL means "never asked", so versions tracked before this backfill themselves on the next sync pass with no separate job. Whether the block was ASKED for is recorded separately (`runtimes_asked`) from the answer, so a hub running against a CLI too old to report it settles in one pass instead of re-entering the whole ingest branch — an origin pull, an R2 put, a kinds and resources rewrite, and a vector purge plus re-embed — on every pass forever. The runtime filter is enumerated (`nodejs`, `rust`) on both HTTP routes and the MCP tool, so a wrong value is a 400 rather than a near-empty result set that reads as "no such module"; the labels match an `imports:` entry's `runtime:` field rather than coining a third spelling for the same two kernels.

Export lists on a /search/modules hit now carry full detail instead of bare names, so a client can preview any kind or instance of any result without a second request — which is what makes scanning results cheap. `exportedKinds` entries become objects (capability, description, extends, runtime, deprecation) rather than strings; `matchedKinds` stays separate because only it carries a relevance score. `exportedResources` entries likewise become objects, gaining the `kind` each instance instantiates and that instance's own description, read from its declaring doc (`module_resources.kind` / `.description`) — a bare name told a reader they could write `!ref Alias.writeLine` but not what they would get. Both are empty for a re-export, whose declaring doc belongs to another module; the verbatim `declared` entry distinguishes the two.

Module hits also carry the declared `metadata.name` as `name`. It was already stored and served by GET /module but not by search, so a result list had only the ref's last path segment to title a row with — which reads as `telo-s3` for a module that calls itself `S3`, and renders two modules of the same name on different hosts identically. Display identity only: the ref remains the locator and a name is not unique across the federation, so a client shows it alongside the ref, never instead of it.
* Relevance floor on the semantic search arm (VECTOR_MIN_SCORE, cosine similarity, default 0.5). An ANN search always returns its nearest topK however far away they are, so a query the index has nothing like still came back with 50 neighbours that RRF ranked and the response presented as answers — "pause execution" returned the timer kind plus an object-storage bucket, a codec and a lease. Matches below the floor are dropped before fusion, so a query with no good answer now returns nothing instead of a page of noise. The floor applies to the vector arm only: the lexical arm has its own gate (a full-text match or a name substring) and thresholding it too would regress the exact-name lookup that hybrid ranking exists to protect. An empty query skips the vector arm entirely, so browsing a category is unaffected. Pinned to the embedding model exactly as the stored vectors are — a different model scores on a different scale, so re-tune alongside a re-embed.## 0.5.0 - 2026-08-03
