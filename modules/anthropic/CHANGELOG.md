# Changelog

## 0.2.0 - 2026-10-10
### Added
* New kind `Anthropic.MessagesModelStream`, an `Ai.ModelStream` over the Messages API's event stream, with the configuration, request translation and thirteen failure codes of `Anthropic.MessagesModel`. Parts arrive in contract order: `text-delta` and `reasoning-delta` as they are written, `tool-call-delta` fragments under the call's own id and name from the first one, the whole `tool-call`, one `provider-state` when the answer holds thinking to carry, then one `finish` with usage and the finish reason. The request is sent when the stream is first read, so a stream nobody reads contacts nothing and a consumer that stops reading cancels the transport. What the request alone decides — an unsupported content part, a `responseFormat`, a structural option — rejects the call before anything is sent; everything the endpoint does rejects the iteration: a refused status by status and error type, an `error` event by its type, and a frame that is not a JSON object, a line or frame over 1 MiB, a body that breaks, or a stream ending with neither a stop reason nor `message_stop`, as `ERR_MODEL_RESPONSE_INVALID`. The answer is complete on the `message_delta` carrying its stop reason or on `message_stop`; a block still open then is closed, a tool call only when its arguments are whole JSON. In both kinds a tool call carries the endpoint's id, and one the endpoint returned with no id gets a minted `call_<uuid>`, which is also the id in the carried `providerState`; no call leaves either kind with an empty id. The module imports `sse-codec`, whose frame reader the stream kind reads through.
* New module. `Anthropic.MessagesModel` is an `Ai.Model` over Anthropic's Messages API, called through an injected `Http.Request` whose client carries the base URL and the `x-api-key` credential — no vendor SDK and no key on the kind. Configuration is closed: `model`, `request`, `maxTokens` (required; the API has no default), `cacheLifetime` (`5m` default, or `1h`), `betas` (sent as `anthropic-beta`) and `options` (camelCase request parameters, which may not name `model`, `messages`, `system`, `tools`, `toolChoice` or `stream`, nor — on the resource — `maxTokens`, which a call's own options may still override). The controller sends `anthropic-version: 2023-06-01`. Every system message is hoisted in order; images go by bytes or http(s) URL (JPEG, PNG, GIF, WebP), PDF files by bytes or http(s) URL and plain-text files by bytes, and anything else is refused before the request as `ERR_MODEL_CONTENT_UNSUPPORTED`; consecutive tool messages are one user turn; `toolChoice: none` is sent with the tools still declared. A content part's `cacheBreakpoint` becomes a cache breakpoint at the configured lifetime — the last four in a request are honoured and earlier ones dropped — and usage reports `cachedPromptTokens` and `cacheWritePromptTokens`, with `promptTokens` the whole prompt. Thinking is returned as `reasoning` parts and carried through a tool loop as `providerState`. The kind restates the thirteen failure codes `Ai.Model` declares and raises nothing else, classifying by HTTP status and the API's error type. A call carrying `responseFormat`, or a structural key in its `options`, is `ERR_MODEL_REQUEST_REJECTED`. Requires telo >=0.114.0.
