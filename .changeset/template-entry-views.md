"@telorun/analyzer": minor

`telo check` judges every entry of a template body as each consumer instantiates it, not only the values the consumer forwards: the body's literals as written, its other expressions as written (typed once, by the definition's own check), and a `!ref` to a sibling entry as that sibling's instance for the same consumer; a `self.<field>` forward of a field the consumer leaves out holds the field's schema `default:`, as `self` does at boot. So a rule reaching across entries — a layout's referrer rule resolving `/presentation/source/collection` through a sibling `presentation: !ref presentation` and on into the consumer's own collection — now judges each consumer's wiring, where before it failed to evaluate (`REFERRER_RULE_INVALID`, "no such key"). A finding at a place the consumer wrote is reported there, as before. A finding at a place the body wrote is reported once at the definition when the definition's own check makes it there (a literal the entry's kind refuses; a text, message or text catalog the body writes whole; a translation the body's own catalog set holds twice, `MESSAGE_ENTRY_DUPLICATE`), and otherwise at each consumer, as `` `<Kind>` body entry `<entry>`, field `<path>`: … ``. A catch list the body writes whole is not judged at a consumer — no consumer can change it, and what a consumer forwards into a handler is bounded by the throws its slot's kind declares — unless a list on its catch ladder is one the consumer forwards, so a published template whose route has no `catches:` no longer fails every consumer's check with `UNCOVERED_THROW_CODE`. A body `!ref` to a resource of the defining module is resolved in that module — never to a consumer's resource of the same name — and a rule reading through one the consumer's analysis does not hold reports that it did not run. A rule reading past a reference into a library's exported declaration now reads that declaration's kind in the library's own scope, so `kind: Self.<Kind>` there no longer reports `REFERRER_RULE_SKIPPED` / `RESOURCE_RULE_SKIPPED` ("which paths … hold references is not known here").
