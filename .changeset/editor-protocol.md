Added: `@telorun/editor-protocol`, the contract between an editor host and a telo language-server engine. It exports protocol generation `1`, the `experimental.telo.protocol` capability, the host-served requests `telo/read`, `telo/exists`, `telo/listDirectory` (entries `{ name, kind }`, `kind` one of `file` / `directory` / `symlink` / `other`, read without following links), `telo/hub/searchRefs` and `telo/hub/listVersions` (a module directory reads as its `TELO_MODULE_FILENAME`, `telo.yaml`; `include:` globs are expanded by the engine over `telo/listDirectory`), the `telo/requirements` notification (an owner module, its member documents and every `requires: telo:` range in its closure as a normalized interval), the `Diagnostic.data` shape carrying a quick fix, and the `telo.upgradeImport` / `telo.upgradeAllImports` / `telo.refreshImportUpgrades` commands — as TypeScript types and as `editor-protocol-schema.json` for hosts in other languages. The README is the protocol spec: it fixes one canonical `file:` URI form that identity is compared in (an empty authority for a local file, a UNC share's lowercased host, `file:////host/…` folded to `file://host/…`), the handshake's engine identity (`X` for a release, `X+unreleased` for a build made while that release is pending) and its verification, and the rule that a receiver ignores members and enum values it does not know — the published schema accordingly closes no object.
