# Changelog

## 0.11.0 - 2026-11-09
### Added
* A Ui.Page's title is optional: a page without one draws no heading, is left out of an omitted navigation, and a navigation entry naming it must give its own text. The page's reading and document carry no title then, and preparedNavigation refuses such an entry with ERR_UI_NAVIGATION_PAGE_UNTITLED.
* Adds the chatToolPreview text, the label of the button opening a tool call's long argument or result in a dialog, with its translations in the fourteen languages.
* Breaking: a filter bar can search. `Ui.Filters` takes `search: { pinned?, default? }` — present when written, or when `fields` and `search` are both left out over a collection declaring `query.search` — kept under `search` in the bar's state and address, set by a preset's `search`, and refused as `UI_FILTER_SEARCH_UNDECLARED` where the collection declares none. `Ui.SearchBoxPlacement` draws the bar as one search box with a `placeholder`, its suggestions and typed tokens (`status:draft,review`, `publishedOn>=2026-11-01`); the texts `searchFilter`, `searchChip` and `searchAndFilter` join `Ui.Translations` in every shipped language. `show`, `controls` and `summary` leave `Ui.FilterPolicy` and are written on `Ui.AbovePlacement`, `Ui.AsidePlacement`, `Ui.CollapsiblePlacement` and `Ui.OverlayPlacement` (a `compact` placement omitting them takes its holder's); the `filters` node carries them on its placement branches and a `search` member when the bar has one.
### Fixed
* `requires.telo` now holds the measured floor, raised to the highest floor among the workspace modules this module imports.

## 0.10.1 - 2026-11-08
### Fixed
* Documentation links now point at telo.run pages and hub module pages instead of the repository tree.

## 0.10.0 - 2026-11-06
### Added
* A `refreshes` entry of `Ui.Action.onSuccess` and `Ui.Chat` (the new `Ui.RefreshTarget`) may hold a whole `*` (one segment) or `**` (any number of segments, none included) segment in its literal path, so `/api/projects/{id}/**` covers `/api/projects/7` and everything beneath it; a wildcard in any other address or request target is a `SCHEMA_VIOLATION`, and a computed path or `pathParams` value is always exact. The matching rows are `conformance/refreshes.json`.
* Action methods: `Ui.Action.source` is replaced by `request: { method, target }`, `method` `POST` (default), `PUT`, `PATCH` or `DELETE`, `target` a `Ui.RequestTarget` whose parameters read `input` (`source:`, `method: GET`, an absolute target and a page reference are schema violations). An input property read whole (`input.<property>`) is consumed: it travels in the target and stays out of the body; a `DELETE` sends no body and must consume every input property (`UI_ACTION_INPUT_UNSENT` / `ERR_UI_ACTION_INPUT_UNSENT`). `onSuccess.navigate` is a `Ui.Address` over `result` and `input` (a path chain is now `navigate: { path: !cel "result.url" }`) and `onSuccess.refreshes` are `Ui.RequestTarget`s over `input` and `result`. The action wire node carries `request: { method, target, consumed }` and addresses in `onSuccess` in place of `path`.
* Added the viewer's keyed texts (mediaViewer, mediaPrevious, mediaNext, mediaPosition, mediaZoomIn, mediaZoomOut, mediaZoomReset, mediaDownload) to Ui.Translations, translated into all fourteen shipped languages.
* Addresses: a link's `href`, a menu item's, a new `href` on a `value` node, on a `list` column and on a `Ui.TableLayout` column, a relation's `href` in `Ui.CollectionPresentation` and `Ui.CollectionOptions` are a string or `{ path, pathParams, queryParams }` (`Ui.Address`): a path template whose `{name}` segments are filled from accessors, a path read from data, or a `!ref` to a `Ui.Page`, read as that page's `path`. A template whose variables do not match `pathParams` is refused before the app runs. A `link`'s `href` is no longer evaluated per request (`href: !cel "request…"` is `CEL_UNKNOWN_IDENTIFIER`; a per-request choice is two links with `when`), and a relation's or option source's `href` is an address rather than a bare path. `Ui.Data` `source` is a `Ui.RequestTarget` and its `params` is renamed `queryParams` (`params` is now a schema violation). Renderers receive every address as `{ path, pathParams, queryParams }` and expand it by `conformance/addresses.json`; `@telorun/ui` exports `addressSpec` and `expandAddress`.
* Documents that a flush Ui.SplitView is one panel with one divider holding its content and aside frameless, that folding the aside leaves a rail with the toggle in place, and that a Ui.ListLayout record is one line with its actions at its end.
* The renderer marks the current location: ui ships conformance/current-location.json, the rows every renderer's rule for when a link to an address is the current location is held to, and its docs state the rule (path exact, query equal once the _telo* parameters are set aside) and the selected record.
* Ui.Chat draws the buttons on a message (copy, edit, regenerate) as the look's glyph unless named, with the button's text as its accessible name and tooltip; the chat node's buttons carry { type: icon, icon: null, label: hidden } for them. Name a Ui.TextButton on a key to keep the text.
* Ui.Chat starters may be written as { prompt, onChoose: send | fill }; fill puts the prompt in the message box instead of sending it, so a file can be attached first. A bare text still sends. The chat node's starters carry { prompt, onChoose }.
* Ui.Chat takes show.copy, a buttons map of Ui.TextButton and Ui.IconButton displays (the new Ui.ButtonDisplay abstract) for its copy, edit, regenerate, attach, send and stop buttons, and composer.actions (inside by default, or outside) placing the attach and send buttons; an icon file that is not an SVG, PNG or WebP image is refused with ERR_UI_ICON_FORMAT_UNKNOWN by the chat as it is by navigation, one rule now in @telorun/ui.
* Ui.ConversationSource and Ui.Chat draw a conversation endpoint as a full chat — streamed replies, reasoning, tool calls and approvals, attachments and branches — with the upload button present only when the endpoint offers it. Ui.Chat takes conversation: { parameter } (the page query parameter naming the conversation shown, written back when the chat creates one) and refreshes (requests read again, over conversation.id, when a send is admitted and when a turn ends); the list of conversations is an ordinary Ui.Listing beside it, so the chat has no sidebar, compact surface or new-conversation button. The chat node and the markdown node join Ui.SpecNode, and the chat's own texts become new keys of Ui.Translations, translated into every shipped language.
* Ui.Listing takes sort (the order records start in, with choosable: false drawing no sort control, and a by.property the collection does not list refused), show (count: false hides the pager range and group counts) and rowActionsDisplay (auto, inline or menu), and the list node takes rowActionsDisplay; the rowActionsMenu text is translated into the fourteen shipped languages.
* Ui.Node gains a bar node (start, center and end regions, the centre centred whatever the sides hold), a command node (a button running a Ui.Command — offered, enabled — that the place it is written in binds, drawn by text or as an icon) and a fill key on every node: fill: true stretches a node to the bottom of the page or surface body it is in, and ui marks every node between it and that room as filling on the wire, where every Ui.SpecNode now carries fill. Ui.Chat takes header, a list of nodes over the open conversation's summary (conversation) and the chat's commands (chat: exportTranscript, copyTranscript, stop, newConversation); omitted it is a bar holding the export command, and [] draws none. Ui.Chat no longer takes title, show.export or buttons.export (each a schema violation): the header says them. A command chain to anything but a command is a CEL type error before the app runs, and a fixed value is ERR_UI_COMMAND_UNRESOLVED when the chat is read.
* Ui.SplitView, a composite drawing an aside tree beside a content tree: a side (start or end), a size (small, medium or large), a required label naming the aside and its toggle, an optional collapse whose fold is kept under a key in a Ui.LocalStore or Ui.SessionStore, and a compact surface (a drawer from the aside side unless another Ui.ViewportOverlay is named) used below the breakpoint, refused when it has an address or a compact surface of its own. Adds the split spec node and the keyed texts splitShow and splitHide, translated into every language ui ships.
* Ui.SplitView takes frame (flush or framed) and toggle (any Ui.ButtonDisplay, an icon button of the look's own when omitted), Ui.ListLayout takes frame (framed or flush), both declared by the new Ui.Frame shape, and a link node takes button, a Ui.ButtonDisplay drawing it as a button-shaped anchor. The split, list-layout and link wires carry them, every member filled by ui; button on any other node is refused.
* Ui.SplitView takes its aside as { actions, content }: content is the tree the panel holds, actions the button links (a link node with button; anything else is refused) drawn under its top bar. The split wire carries aside as { actions, content }, actions always present.

A layout's move is a Ui.RowAction over row and to, checked as a call site and twinned by ERR_UI_ROW_ACTION_INPUTS_INVALID. * Records are listed by Ui.Listing, drawn by a layout under the new Ui.ListingLayout abstract (Ui.TableLayout, carrying the columns, and the default when layout is omitted) with an optional compact layout and paging by pages, more or scroll; the page spec gains type: listing, whose layout is a Ui.ListingLayoutSpec carrying its read plan. A collection is reached through Ui.CollectionSource (a DataModel.Collection and its basePath) and shown through Ui.CollectionPresentation, whose relations label related records in listings, offer them in filter bars and enter them with a derived picker in forms; filter fields take values: all | present (present needs a facet) and their own options, and the absent operator is entered with a toggle. New rules UI_RELATION_UNDECLARED, UI_RELATION_TARGET_MISMATCH, UI_RELATION_SEARCH_NOT_ACCEPTED, UI_FILTER_VALUES_NOT_FACETED and UI_FILTER_OPTION_VALUE_MISMATCH, each with its ERR_ twin. * The app-relative address rule is one exported shape, AppRelativeReference, named by every address field: a link's and a navigation entry's href, an image's src, a page's path, a reader's and an action's source.path, onSuccess.navigate and refreshes, and a collection source's basePath. A refused link or navigation address now quotes the branch it failed.

## 0.5.0 - 2026-10-23
### Added
* A menu node: { type: menu, text, items } is a button labelled text that opens a list of link nodes. Choosing an item follows its href exactly as clicking that link would — a declared page within the application, anything else by a load — under the same address rule, a literal refused by telo check and a computed one turning the menu into an error node for that request. An item whose style holds strong is the current choice; each item is delivered by its own when and drawn by its own shown, and a menu none of whose items is delivered is left out. It works anywhere a node does.
* A `Ui.AsidePlacement` with no `compact` now folds behind a toggle on a narrow viewport: its `compact` is filled as `{ kind: Ui.CollapsiblePlacement }`, folded, so the `aside` branch a renderer receives always carries `compact`. A pinned field on an aside bar is no longer warned (`UI_FILTER_PINNED_UNUSED`), since such a bar always folds on a narrow viewport; an above placement with no `compact` and an omitted placement are still warned.
* An action draws its answer as node trees: result (over result, input and values) for a success and failure (over error, input and values) for anything else, ui filling a default failure; onSuccess navigates and refreshes readers and tables by path; concurrency parallel or serial; clearAnswerOn (UI_ACTION_CLEAR_UNKNOWN_PROPERTY, twin ERR_UI_ACTION_CLEAR_UNKNOWN_PROPERTY). Ui.RowAction is one shape for a table's rows and a list node's rows, with its own enabled; a table declares query for its row actions; a row action carries its action's own node on the wire. Breaking: Ui.Action.lists is removed — write a list node in result — and UI_ROW_ACTION_DRAWS_LISTS with its twin is gone; the wire action node and row action change shape and a table node carries query.
* Conditions and data on page load: Ui.Data reads a record under the record contract (loading, failure, reloadOn focus / unauthorized); every node takes shown, a Ui.Condition over the interpreted profile Ui.Match decided in the browser, while when decides delivery; value and list nodes; Ui.Enablement on Ui.Action.enabled; shown on Form and Action fields; Ui.RequestError and Ui.QueryParameters; conformance rows in conformance/match.json. Breaking: Ui.SpecNode gains the value, list and data branches and shown on every branch, browser roots are accessor-only (x-telo-context-eval), and Action lists write x-telo-context-element-from-item as 0/rows; requires telo >=0.121.0.
* Every displayed text is a Text written in the module's lang: (ui declares lang: en): node texts are Ui.BoundText - a Text, or { text, values } whose accessor values a renderer fills in the page - and action labels, column headers, group labels, presets, disabledText and confirm are Texts; a placeholder nothing fills is refused by telo check. New Ui.Words kind and the exported English set Ui.words hold the words a renderer draws on its own, and texts ui fills in are word references { word: <id> }. Provided nodes carry text records (the TextRecord fragment), labels: [{ value, label }] on value nodes, list and table columns, filter fields and every field spec, a required description on field specs, and a date range's initialPreset as the preset's index or null. @telorun/ui exports SpecTranslator, which replaces every text record of a provided node by following Ui.SpecNode, and isWords. Breaking: a renderer receives records and word references where it received strings.
* Every navigation entry and every tab of a tabs node is keyed by what its author wrote: the slug of its untranslated source text, a navigation entry under its group's key and /, a sibling repeating a key taking ~2, ~3 in declaration order — so an entry gated off by when or added elsewhere moves no other entry's key. A delivered navigation entry carries it as key, and a tabs node's tab in Ui.SpecNode as key. Ui.Words gains siteNavigation, collapseNavigation and expandNavigation. Breaking: a Ui.Words set of one's own must give the three words.
* Form and action fields are kinds under the new Ui.Field abstract: Ui.InputField (a named Ui.Control), Ui.ChoiceField and Ui.PickerField over a Ui.OptionSource such as the new Ui.CollectionOptions (paged, searched, chosen values labelled by one in lookup, pageSize sent as limit), and Ui.DateRangeField with presets. Each field kind judges its own fit to the model through a referrer rule and its invoke answer, so a field kind from another module is placed with no change to ui. Forms and actions gain groups (Ui.FieldGroup) and state (Ui.StateRecord, which Ui.Filters policy.state now is, with fields); the wire field is a type-tagged spec, form and action nodes carry groups and state, a bar's state carries fields, and a table's source.filters are accessors over query sent as bindings. Ui.controlFits is the one exported fit predicate, held to conformance/control-fits.json. Breaking: a fields entry written as { property: text } is refused — write the property name (text) or a field kind, inline as { kind: Ui.InputField, property: text } or as a !ref to one; the codes UI_FORM_FIELD_*, UI_ACTION_FIELD_* and UI_ACTION_REQUIRED_INPUT_NOT_ENTERED are now UI_FIELD_* (UI_FIELD_REQUIRED_NOT_ENTERED applies to forms too); a renderer must read the new wire shapes.
* Icons are resources: Ui.Icon is an abstract providing the one image file a glyph is drawn from, and Ui.FileIcon an icon drawn from an SVG, PNG or WebP file given as file. A navigation entry (page, link or group) takes an optional icon, a Ui.Icon declared in place or named by reference, and reaches a renderer carrying the address it serves the file at; a collapsed sidebar's rail draws each top-level entry's icon. preparedNavigation, exported by @telorun/ui, takes a fifth argument, the function serving an icon's file and answering its address. Breaking for a renderer of another module calling preparedNavigation: it passes that function.
* More navigation placements, in-page tabs and abstract compact slots. Ui.SidebarNavigation draws the tree in a column beside the page whose groups open in place, several at once: side (start | end), rail { collapsed } letting the viewer collapse it to a rail, store (a Ui.StateStore keeping the open groups and the collapsed rail) and compact, which defaults to an overlay navigation whose drawer opens from the sidebar's side. Ui.TabBarNavigation, a Ui.CompactNavigationPlacement, draws the top-level entries as bottom tabs — at most visible (2–5, default 5), More holding the rest — a group's or More's entries opening in surface (default a bottom drawer); it is valid as the main placement too. Ui.NavigationPlacementSpec gains the sidebar and tab-bar branches, and a compact is either an overlay or a tab bar. The tabs node { type: tabs, tabs: [{ text, children, when? }], address? } joins Ui.Node and Ui.SpecNode, each tab delivered by its own when, its chosen tab in the page address with address. Filter placements' compact is typed by the new Ui.FoldingFilterPlacement, which Ui.CollapsiblePlacement and Ui.OverlayPlacement extend, and surfaces' compact by the new Ui.ViewportOverlay, which Ui.Dialog and Ui.Drawer extend under Ui.Overlay, so another module's kind extending either is accepted there; manifests already written validate unchanged. A compact slot naming the wrong kind is now reported as not implementing the abstract.
* Pages and site navigation are vocabulary. Ui.Page (path, title, query, children) is an invocable page: its composites are resolved once when it is created, and it answers each request with its nodes as delivered for that request; its reading is { path, title, query }. Ui.Navigation is the record { items, placement } an application takes: items a tree of Ui.NavigationItem entries tagged page (a page by reference, its text defaulting to the page's title), link and group (nested to any depth), each with a when evaluated per request, a group with nothing delivered left out. Placements are kinds under Ui.NavigationPlacement: Ui.HeaderNavigation (a menu bar with dropdowns and submenus, its compact a Ui.CompactNavigationPlacement) and Ui.OverlayNavigation (the whole tree behind a menu button in a Ui.Overlay surface), sent as Ui.NavigationPlacementSpec. ui fills every default: no navigation is one entry per page, no placement the header, a header's compact an overlay navigation, an overlay's surface a drawer from the start edge. @telorun/ui exports isPage, RequestNodes, headerReads, preparedNavigation and deliveredNavigation, and Ui.Words gains the menu word. Breaking: a Ui.Words set of one's own must give menu.
* The code entry @telorun/ui exports the closed design token names as DESIGN_TOKENS, spelled as Ui.DesignTokens writes them (color.accent), for whatever reads a token set by name — a renderer spelling them in CSS, a check that a theme gives each token a value — so no consumer copies the list.
* Ui.DesignTokens replaces Ui.Theme: the brand of an interface — colours, radii, spacing, shadows, type sizes and typefaces — as a closed, renderer-neutral token set that any theme reads. Breaking: the kind is renamed, and its tokens are written at the resource's top level instead of under tokens: (kind: Ui.DesignTokens, color.accent: '#1d4ed8'). A misspelled token is still refused.
### Fixed
* The description of afterSubmit: again now says the form stays open back at the values a new record starts from, rather than emptied.

## 0.3.0 - 2026-10-10
### Added
* Ui.Action: a button that runs an operation from a page. It takes inputModel (required), outputModel, source.path (one POST with a JSON body, under the new action contract), label (required), fields and lists. Each list names its rows as a path into result, typed from outputModel, and its columns as paths into row — one element of that list — or result; a column's header and presentation come from the member it names, followed through any reference at any depth (a named shape, a pointer into the model's own definitions, a shape reached through a shape), a keyword written beside a reference winning over the shape it names. It provides the new action node of Ui.SpecNode: schema, path, label, fields and lists, all present. New rules, each twinned by the action's controller: UI_ACTION_FIELD_UNKNOWN_PROPERTY, UI_ACTION_FIELD_UNSUPPORTED, UI_ACTION_REQUIRED_INPUT_NOT_ENTERED. Ui.Table takes rowActions, each { action, inputs, confirm }: the inputs are paths into the row or fixed values, checked as a record of that action's input model, and the table refuses inputs that make no such record when it is first read (ERR_UI_ROW_ACTION_INPUTS_INVALID). An action that declares a list is refused in a row by the new rule UI_ROW_ACTION_DRAWS_LISTS, twinned by the table as ERR_UI_ROW_ACTION_DRAWS_LISTS. A form enters lists: a property typed array whose items are a scalar is enterable beside the scalars, in Ui.Form and Ui.Action alike. BREAKING for a manifest: a Ui.Form with no fields now shows a field for every list-of-scalars property of its model, and a Ui.Form listing a field for a property no control can enter — an object, or a list of anything but scalars — is refused by the new rule UI_FORM_FIELD_UNSUPPORTED, twinned by the form as ERR_UI_FORM_FIELD_UNSUPPORTED; it was accepted and drew nothing. BREAKING for a manifest: a Ui.Table column, written or derived, over any member reached through a reference — a top-level property that is itself a reference, or a member nested beneath one — now takes its header from that member's title and its presentation from its type and format, where it showed the member's name and plain text; and a reference on the way to such a member, or to an action's list, that names nothing or leads back to itself is refused when the table or action is first read (ERR_REF_UNRESOLVED), where it was ignored. BREAKING for a renderer: the table node of Ui.SpecNode now requires rowActions, an empty list when the table declares none.

## 0.2.0 - 2026-10-08
### Added
* A filter bar declares how it behaves. Ui.Filters takes policy, a Ui.FilterPolicy record: show (all or chosen), placement, controls (direct or chips), apply (commit, typing or button), summary (none or chips) and state. A placement is a kind under the new Ui.FilterPlacement abstract: Ui.AbovePlacement, Ui.AsidePlacement, Ui.CollapsiblePlacement and Ui.OverlayPlacement, the first two with a compact replacement for narrow viewports. State is { key, address, store }, where store is a kind under the new Ui.StateStore abstract: Ui.LocalStore or Ui.SessionStore. A field takes pinned, control (auto, select, options, toggle, slider, tags, none) and default, and a bar takes presets. A control is judged against its property's types with null set aside, so a nullable boolean takes a toggle and a nullable number a slider; a toggle holds true or nothing, so false is refused as its default and as a preset value for it. New shapes Ui.FilterPolicy, Ui.FilterPlacementSpec and Ui.StateStoreSpec. New rules, each twinned by the bar's controller: UI_FILTER_DUPLICATE, UI_FILTER_DEFAULT_INVALID, UI_FILTER_CONTROL_UNSUPPORTED, UI_FILTER_PRESET_UNKNOWN_FILTER, UI_FILTER_PRESET_VALUE_INVALID, UI_FILTER_PRESET_LABEL_DUPLICATE, and the warning UI_FILTER_PINNED_UNUSED. BREAKING for a manifest: two fields of one bar sharing a property and an operator are refused. BREAKING for a renderer: the filters node of Ui.SpecNode now requires show, placement, controls, apply, summary, state and presets, and each of its fields requires pinned and control.
* Form surfaces: the opener of a form names where it appears, as a kind under the new Ui.Surface abstract — Ui.Dialog, Ui.Drawer, Ui.Popover (the three under Ui.Overlay), Ui.InlineSurface, Ui.Panel, Ui.PageSurface — each with only the keys that apply to it, an optional address that puts the open form in the page address, and a compact Ui.Dialog or Ui.Drawer for narrow viewports (rules UI_SURFACE_COMPACT_ADDRESSED and UI_SURFACE_COMPACT_NESTED, twinned at provide). New shapes Ui.SurfaceSpec, Ui.OverlaySpec, Ui.AfterCreate, Ui.AfterEdit and Ui.UnsavedInput. BREAKING: a Ui.Table create and edit are objects { form, surface?, afterSubmit?, unsaved? } and the bare form reference (create: !ref form) is refused; write create: { form: !ref form }. BREAKING for renderers: a table node create and edit are { form, surface, afterSubmit, unsaved } with every member present, where each was the form node.
* Table columns derived from a model leave the row key out; list it to show it. The collection contract gains GET <basePath>/<rowKey value>, answering with one record: an edit form is filled from it. BREAKING: a Ui.Table with no columns listed, over a model declaring its row key, no longer shows a column for it.
* The UI vocabulary: page nodes (box, stack, columns, text, badge, link, image, svg, composite) with a closed style list, and the composite kinds Ui.View, Ui.Table, Ui.Form, Ui.Filters, Ui.Component, Ui.ComponentExport and Ui.Theme over the Ui.Composite contract. Tables, forms and filters derive from a row model and are checked against it before boot. A link's href, an image's src and a source's basePath inside the application are app-relative paths: / followed by anything but / or a backslash, with no control character. A renderer's controller reaches the module's code entry as @telorun/ui (entryAssets, AssetFile, AssetRef), which turns a built browser entry into the files a page loads. Requires telo 0.112.0 or newer (requires: telo: ">=0.112.0").
* Ui.Collection declares what a collection's list request accepts: query.filters, each a property with one operator (eq, contains, gt, gte, lt, lte, in), and query.sort, the properties it may be sorted by. Breaking: Ui.Table and Ui.Filters each require a collection reference to one. A table column is sortable only where the collection lists its property, no longer wherever the value is scalar, and a source.filters key must be a property the collection declares with eq (UI_SOURCE_FILTER_NOT_ACCEPTED). A filter bar with no fields shows the collection's declared filters instead of one per scalar property (UI_FILTER_MODEL_INCOMPLETE when its model lacks one of their properties); a listed field must write its operator, which is no longer defaulted from the property's type, and must be a pair the collection declares (UI_FILTER_NOT_ACCEPTED). Ui.Filters no longer takes rowKey.
