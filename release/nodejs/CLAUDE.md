# Release planner — package guide

Loaded when working under `release/nodejs/`. Repo-wide rules (a fragment for every change to a released unit, pre-1.0 minors) are in the root `CLAUDE.md`; the Telo adapter's pure half is in `analyzer/nodejs/src/release/CLAUDE.md`, its evidence half and the commands only Telo has in `cli/nodejs/CLAUDE.md`. Guides: `release/nodejs/README.md` (a plain Node project), `docs/extend/releasing-modules.md` (a Telo workspace), `docs/guides/workspaces.md` (the marker). The Rust twin is `release/rust` (`telorun-release`); both halves answer the vectors in `release/conformance/`.

`@telorun/release` is MIT, **off the telo version line**, and depends on nothing in this repo but `@telorun/glob`: no analyzer, kernel, CLI, templating or CEL. The main entry builds for the browser without polyfills (the editor still answers "what does this change bump?"); `@telorun/release/node` holds evidence, the adapters' evidence halves and the command tree a host mounts with `releaseCommands`. Bin `telo-release` is that tree over the ecosystems this package ships (`npm`, `cargo`, `docker`, `helm`); `telo release` is the same tree plus the `telo` ecosystem.

**The planner never branches on an ecosystem's name.** A **unit** is a directory with one version, one changelog (`<unit>/CHANGELOG.md`) and one fragment target, however many packages it ships. Each package is an **anchor** — an ecosystem plus a literal directory inside the unit, recognised there by the ecosystem's adapter (`adapter.ts`, the seam). An adapter defaults its anchor's version location and payload, contributes the schema of its own entry keys, and adds only what no declaration can hold: a computed payload and read-back. Adapters are registered in-process by the host program, never discovered from `node_modules`, because the Rust twin cannot discover; an entry naming an ecosystem the host registered none for is `WORKSPACE_ECOSYSTEM_UNAVAILABLE`. A core file naming an ecosystem or one of its files is a defect.

**Three questions, three mechanisms.**
- **Whether** a unit bumps: the digests of its layers at its recorded version against the ledger. Each anchor contributes one layer — a file set digested by one function (`node/files-digest.ts`: sorted unit-relative path, executable bit, content hash), never archive bytes or `dist.integrity` — and a declared `payload:` one more. A cargo anchor with a `bin`, `cdylib`, `staticlib` or `dylib` target also holds `Cargo.lock` — never the file on disk, but the sorted `name version source` lines of the external packages in its normal + build closure across every feature and platform (`adapters/cargo-closure.ts`: `cargo metadata --locked --offline --all-features`, so `cargo fetch --locked` runs first; recomputed on read-back from the `.crate`'s own lockfile and packaged manifest), so a lockfile-only bump releases the binaries that link it; a library-only anchor holds none. A private npm package supplies its version and edges but no layer. No layer holds the workspace's `.changes/` (`isBookkeeping`), whichever adapter's file set reaches it: `apply` rewrites it after reading the layers, so one holding it would replan itself forever.
- **At what level**: the edge graph. Edges are never declared by hand — adapters supply import edges (`workspace:` and rewritten plain ranges, cargo path dependencies, a module's relative imports), one generic rule supplies the rest (another unit's version location inside a unit's payload), and a `metafile:` gives inline edges, which only explain drift the digest already saw. A dependent bumps at its dependency's level; a **group** releases every member at the highest level any needs; a level above `maxBump` is `MAX_BUMP_EXCEEDED`.
- **What is said about it**: fragments. A changed unit with no fragment ships as an unattributed patch and warns `CHANGELOG_ENTRY_REQUESTED`, for every unit.

**The version is resolved, never chosen by order.** A declared `version:` wins; otherwise the one anchor whose ecosystem defaults a location (`docker` defaults none); zero or several is `WORKSPACE_UNIT_VERSION_UNRESOLVED`. `apply` writes the version to every anchor's location and every `versionFiles` entry (a `Cargo.toml` also moves its `Cargo.lock` entry — a lockfile left behind makes every `cargo --locked` re-resolve over a network it forbids); the ledger records it and is never its source; `telo release check` refuses locations that disagree (`UNIT_VERSION_MISMATCH`). An anchor is exactly one package and covers nothing beneath it. A unit with no layer is `WORKSPACE_UNIT_PAYLOAD_EMPTY`, a package directory claimed by two units `WORKSPACE_ANCHOR_CLAIMED`.

**The ledger is a cache; the registry is the authority.** `.changes/ledger.yaml` records per unit its `version`, its layers **as published** nested `<ecosystem>: { <anchor>: <digest> }` (a declared payload under the reserved key `payload`), an optional `registry:` and an optional `candidate: { version, layers }`. The credential-free PR gate reads the committed ledger, so the PR gate and the publish gate compute the same number; a *missing* entry is not drift. `verify [--write]` reconciles it per layer through each adapter's read-back; a layer with no read-back (`docker`, a declared payload) keeps its digest and is reported unverifiable. `check` does NOT fail because a payload moved (a toolchain bump moves every digest; those ship as unattributed patches): it fails when no consistent plan can be formed — a fragment naming no unit, a level above `maxBump`, disagreeing version locations, a registry mismatch.

**Candidates hold no state.** `apply --candidate[=<id>]` versions each planned unit `<final>-<id>.<k>` (default id `rc`); `k` is per unit, shared within a group, and rises only when a layer differs from the unit's `candidate:` record. A candidate consumes no fragment and leaves the final entry alone, so a plain `apply` always plans the final from final entries plus every pending fragment and removes the candidate records. Candidacy is the caller's per call, never repo state. `tag` tags the commit it runs at `<unit key>@<version>` for each unit the last apply moved.

**Changelogs** are written by one writer in the module format; history a previous tool wrote stays below the new entries untouched. **`adopt changesets`** (`node/adopt-changesets.ts`) is the one place `@changesets/*` formats are read: it writes one `release.units` entry per package, `fixed` groups → `release.groups`, `ignore` → `!` entries, each pending change file → a fragment with the same units, body and id, seeds the npm layers through `verify --write`, refuses `linked` groups, deletes `.changeset/` and lists the CI steps and dependencies it did not rewrite.

**A destination** is the resolved `registry` plus the unit's name, assigned and never derived from an importer's path; `registry` cascades anchor → `release.ecosystems.<eco>` → the adapter's own rungs (only `telo`: `--registry`, `TELO_OCI_REGISTRY`, the ledger's recorded base). `NO_DESTINATION_KNOWN` and `DESTINATION_COLLISION` cover every `order` row.

**The marker** is `telo-workspace.yaml`'s `release:` block — `units`, `groups`, `ignore`, `maxBump`, `ecosystems` — read leniently with diagnostics (`marker-reader.ts`, `marker-schema.ts` as data, `release-settings.ts`); an ecosystem's keys are read only at its anchors or under `release.ecosystems.<eco>`, anything else `WORKSPACE_UNKNOWN_KEY`. The Rust twin reads YAML with its own parser and refuses a malformed file, where Node's `yaml` recovers; `release/rust/README.md` lists every difference.

## Where to look

- Planning → `release-plan.ts` (the planner, `propagate`), `units.ts` (units, anchors, `WORKSPACE_ANCHOR_*`), `bump-level.ts`, `fragment.ts`, `changelog.ts`, `ledger.ts`, `version-files.ts`.
- The marker → `marker-reader.ts`, `marker-schema.ts`, `release-settings.ts`.
- Adapters → `adapters/{npm,cargo,docker,helm}.ts` (pure halves), `node/adapters/` (evidence: pack lists, `cargo package --list`, Docker's ignore rules, `helm package`, read-back), `adapter.ts` (the seam).
- Evidence and commands → `node/evidence.ts`, `node/operations.ts`, `node/commands.ts`, `node/host.ts` (what a host supplies), `node/carried-changes.ts`, `node/metafile.ts`, `node/declared-payload.ts`.
- Conformance → `release/conformance/` (README is the format), `release/nodejs/tests/conformance.test.ts`, `release/rust/tests/conformance.rs`.
