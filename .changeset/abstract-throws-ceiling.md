Added: a `Telo.Abstract` may declare `throws: { codes }`, and an ancestor's `throws:` list is now a ceiling every descendant's codes must fall within. The kernel used to refuse `throws:` on an abstract at boot while `telo check` accepted it. A descendant declaring a code its nearest ancestor with a literal `throws:` list does not is reported as `THROWS_NOT_SUBSTITUTABLE` and refused at registration with `ERR_THROWS_NOT_SUBSTITUTABLE`, for a dependency's definition too. On an abstract, `inherit` / `passthrough` are refused, and `THROWS_ON_NON_DISPATCH_CAPABILITY` now covers abstracts. The shape of a `throws:` block and the capabilities allowed to declare one are now one rule both halves read: `telo check` reports a malformed block (`SCHEMA_VIOLATION`) that used to fail only at boot, and the kernel now refuses `throws:` on a declared capability outside `Telo.Invocable` / `Telo.Runnable`, a third party's included, as `telo check` already did. A ceiling above an `inherit` / `passthrough` ancestor still bounds the descendants below it. A dispatch through a library's kind-only `resources:` input now resolves to that kind's nearest declared list, and to an unbounded union when none is declared, where it used to read as throwing nothing — so a library's `catches:` against such an input is checked against the codes the real implementation may throw, and one over an abstract with no list needs a catch-all (`UNBOUNDED_UNION_NEEDS_CATCHALL`).
