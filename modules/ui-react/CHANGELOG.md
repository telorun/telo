# Changelog

## 0.9.0 - 2026-11-01
### Added
* The renderer draws a listing as a list, cards, a kanban board (a column per group headed by its count, each loading more on its own), a calendar of months, weeks or days, a timeline at a day, week, month or quarter scale in lanes, or a tree whose expanded records stay expanded across reloads, each with a sort control where it has no headers. Dragging a card to another column, an event to another day or column, a bar to another lane or a record under another parent runs the layout's move with to filled, never a replace through the edit form; every move also has a Move to menu, and a column or a day can create a record holding its value. New layout contract ui_react_layouts-1, published in @telorun/ui-react-contract as layouts and layoutVectors with runLayoutVector beside the controls contract: a Ui.ComponentLayout's component gets the records, groups, the shown period, tree children and the sort and reports intents, the built-in layouts being its reference implementation, and one built for another ABI is refused at start with ERR_UI_COMPONENT_ABI_UNSUPPORTED. New parts listing-sort, listing-sort-option, listing-detail, record-move, record-create and the parts of each layout (list-layout, cards-layout, board-layout, calendar-layout, timeline-layout, tree-layout and theirs); calendar-grid, timeline-axis and timeline-track reserve display and grid-template-columns.
* The renderer draws type: listing nodes in place of type: table, as a table layout: it executes the layout's read plan (a read per group value, shown period and tree level), pages by a pager, a Load more button or infinite scroll drawing only the pages in view, reloads every listing and present filter over a basePath without losing the viewer's place, an open form or its entered values, draws a record a write answered with at once, labels related records through batched in requests, swaps to the compact layout below the breakpoint keeping its state, and draws the listing's empty node. Filter fields offer related records, present values with their counts at the bar's basePath, and a switch for absent. Breaking: the listing's own parts are listing, listing-toolbar, listing-create, listing-main, listing-empty and listing-loading (were table, table-toolbar, table-create, table-main, table-empty and table-loading), a list node's empty cell is list-empty, data-state and the reserved display and grid-template-columns moved from table to listing and order from table-toolbar to listing-toolbar, and load-more is new; the table part is the table layout alone.

## 0.8.0 - 2026-10-25
### Added
* The renderer reads failures as RFC 9457 problems: a failure tree shows the response's own code and its detail (an unclaimed coded server error no longer shows as ERR_UI_REQUEST_FAILED), falling back to its own words for 401, 403 and the status; a 400's data.issues land on the field their pointer names after /body, worded by Ui.Words as the browser's own validation, the rest under the form. Breaking: the old details[] list and a body's message are no longer read, and the application's own 404s answer the bare problem { type, title, status } as application/problem+json.

## 0.7.0 - 2026-10-23
### Added
* Breaking for themes: the header's row is now its only child, the new `header-content` part, so a rule written `header > header-start` (or over any other part of the row) matches nothing and must go through `header-content`; and every theme must now give the `width.page` and `space.page` design tokens a value, which a contained page's measure and the page and header inset are drawn from. `UiReact.App.pageWidth` (`contained` by default) is forwarded to every page, whose document carries `width`; `UiReact.App.header.width` (default: `pageWidth`) is resolved into the application document as `header.width`, the same on every page, and the application document now always carries `header`. `page` and `header` carry `data-width`; the base layer insets `main` by `space.page`, draws a contained page no wider than `width.page`, centred, and insets the header's content by the same expression, so it lines up with a contained page — beside a sidebar too, where the header becomes a subgrid of every column and a contained row sits over the page column. Reserved: `page`/`max-width`, `margin-inline`, `main`/`padding-inline`, `header`/`display`, `grid-template-columns`, `padding-inline`, `header-content`/`padding-inline`, `grid-column`. The default theme sets `width.page` `64rem` and `space.page` `1.5rem` as tokens, and the contract data lists the tokens the renderer reads (`rendererTokens`).

## 0.6.0 - 2026-10-23
### Added
* A navigation entry's icon is drawn as the glyph part: the application serves the icon's file under its content digest, refusing one that is not an SVG, PNG or WebP image with ERR_UI_ICON_FORMAT_UNKNOWN when it starts, and the glyph is an empty element masked by that file over currentColor (--ui-react-glyph), so it takes the colour of the entry's text and none of the file's markup enters the page. Navigation's entries take an optional icon element, drawn before the label in a row, a column and a panel and in a rail in place of the first letter, which a vector pins; glyph joins the part list with background-color and mask-image reserved, the sidebar and tab-bar scenes carry icons, and the default theme sizes the glyph and stacks a tab's glyph over its text. A vector host turns an element spec at any depth of a prop into an element (withElements, exported by @telorun/ui-react-contract). Breaking for a theme of another module: it styles glyph; and for a controls set implementing Navigation: it draws an entry's icon.
* A slider draws its position as text after its track, in the new parts slider-value and filter-slider-value: the number it holds, or Any while a filter slider restricts nothing, following the thumb as it is dragged and hidden from assistive technology. The default theme styles both in tabular figures, leaving them room past the track's end. A filter chip carries its whole text as its title, so a chip a theme cuts short shows in full on hover.
* A stored or addressed navigation state names an entry by its key rather than its position — a sidebar's open groups under telo.ui:<mount path>:n (now v 2, an entry of v 1 ignored), a tab bar's open sheet and a tabs node's chosen tab under _telo.open.<name> — so a saved or shared state keeps naming the same entry when another is gated off or added. A tab bar keeps every tab in the bar however narrow the screen, a group's tab and More being buttons that open its sheet, expanded while it is open. The navigation landmark is named by the siteNavigation word and the sidebar toggle by collapseNavigation, or expandNavigation while collapsed.
* Above compactBelow the header is one row — header-start, the title, the navigation taking the room left, header-end at the inline end — and the default theme's header spans the full window width with its side padding instead of centring its content on the page width.
* Breaking: an action's source.path — of a Ui.Action and of a row action in a table or a list node — is now requested under the application's mount, as every other path a page names is: mounted at /admin, path: /api/reports is sent to /admin/api/reports. An application mounted under a prefix whose actions name an API served at the origin's root serves that API under its mount too. onSuccess.refreshes still names paths as written.
* Draws an action's result and failure trees, refreshes and navigates after a success, refuses a second press of a pending form or row, runs a serial action's presses on a page one after another and clears the answer on clearAnswerOn; a table's and a list's row actions draw their action's answer in place of the button (kept while a table row is on the shown page) and its failure beside it, governed by the row action's own enabled. New parts action-failure, row-answer, row-failure. Breaking: the renderer reads the new action and row-action wire shapes and no longer draws lists.
* Draws every ui field kind: input fields with the control they name (select, options, switch, slider, tags), choices and pickers over option sources (paged as the list scrolls, searched after the typing pause or on Enter with stale answers discarded, chosen values labelled by in lookups in batches of pageSize and held to the source's current filters), and date ranges with presets computed in the viewer's time zone, a start after the end blocking and a too-long range warned of. Groups are drawn as labelled sections; form and action values are kept in the address (_telo.v.<key>.<property>) and in browser storage (telo.ui:<mount>:v:<key>); fields are validated as values are entered once touched, and a 400 detail lands on the field its path's first segment names. A table's source filters are read as bindings, reading nothing while one holds nothing. New styling-contract parts for groups, warnings, switches, sliders, pickers and date ranges. Breaking: reads the new ui wire shapes (type-tagged fields, groups, state with fields, table filter bindings), so it needs this ui.
* Draws Ui.Data readers (one read in flight, one more for any triggers during it, stale answers never drawn, reload on focus and on a 401 inside the content), shown conditions over data, query, values and row with hidden content kept mounted and requestless, value and list nodes, field shown and Action enabled with disabled-text; validation interprets the full Ui.Match profile. Pages declare query parameters, the page document carries query, and a page condition cannot read request (x-telo-context-eval). New parts value, list, data, disabled-text; data-state on data. Requires telo >=0.121.0.
* Navigation and Tabs are controls of the contract. Navigation is site navigation in the WAI-ARIA disclosure pattern — links as links, groups as disclosure buttons; in a row or a rail each open group's panel a layer at the end of <body> that Tab flows into, placed to stay inside the viewport; in a column each open group's entries in place beneath its button, at every depth, in no layer; the open groups a set of keys, so several groups of a column stay open at once; given more, what does not fit a row moved into a More group; an entry given opens: dialog a button (aria-haspopup="dialog") expanded while its key is open, whose dialog the renderer draws; a nav landmark only when labelled — and Tabs is the tabs pattern with manual activation. The glyph names include menu, more, collapse and expand, and the interpreter has the hover step and the tag of a target. A menu node is drawn by Navigation as one disclosure with no landmark: its items are links, the one styled strong carries aria-current="true", and its style is on the navigation part; Menu stays the command menu. A theme styles the navigation, nav-toggle, nav-item, nav-group and nav-panel parts.
* On a narrow screen (`data-compact="true"` on the `app` part) the default theme fits the same parts to the width: the header scrolls away with the page and its title, start and end share one row; filter bounds and controls shrink and wrap so no filter is wider than the screen; and a table frame shows an edge shadow while more columns lie beyond it.
* Swappable themes. UiReact.Theme is a look — stylesheets placed in the telo.theme layer, token defaults, and UiReact.Controls sets drawn in place of the built-in controls they implement — and UiReact.Controls is a set of controls a module ships (entry, implements), checked against ui_react_controls-2 before the application starts. The built-in look moved out of code into the exported instance UiReact.defaultTheme, one stylesheet that now styles every part, the picker, date range, field groups and field descriptions included, and declares no reserved property. The application document names a theme's control sets in controls.sets, places each set's stylesheet in telo.control and serves no built-in mechanics for a control a set replaces. Two entries of a theme's controls implementing one control are refused, the same set listed through two aliases included (UI_THEME_CONTROL_DUPLICATE at each entry / ERR_UI_THEME_CONTROL_DUPLICATE naming both). Breaking: UiReact.App.theme is required and names one UiReact.Theme (theme: !ref UiReact.defaultTheme for the built-in look); the brand moves to the new tokens: field, one Ui.DesignTokens or a list of { tokens, when } chosen per request; defaultTheme is removed — a look of the application's own is a theme holding only stylesheets.
* The renderer draws a sidebar and a tab bar. Ui.SidebarNavigation is the sidebar part, a column beside main under the header holding the Navigation control in a column whose groups open in place, and with a rail the sidebar-toggle button collapsing it to a rail whose groups float beside it; its open groups and collapsed rail are kept in its store under telo.ui:<mount path>:n and read back on the next visit. Ui.TabBarNavigation is the tab-bar part along the bottom edge, its top-level entries as tabs and More last when there are more than visible, a group's tab or More opening its entries in the placement's surface. The tabs node is drawn by the Tabs control, its chosen tab under _telo.open.<name> when addressed. The parts sidebar, sidebar-toggle, tab-bar, tabs, tab-list, tab and tab-panel join the styling contract, sidebar carrying data-side and data-state (closed while collapsed), and app's display and grid-template-columns and tab-bar's position and bottom are reserved; the contract gains a sidebar scene and a tab-bar scene, and the default theme styles every new part. Breaking for a theme of another module: it styles the new parts.
* The renderer draws every interactive leaf through one controls contract, ui_react_controls-2: 24 controls (text, number, date, date-time, time, tags and date-range entry; checkbox, switch, slider, option group, select, multi-select and listbox; dialog, drawer, popover, confirmation, menu, tooltip; navigation and tabs; icon by semantic name), each fully controlled and reporting intents, with its props, parts, states and behaviour vectors as data. The built-in controls are its reference implementation, drawn on the DOM in each role's WAI-ARIA pattern with no primitive library: the renderer no longer carries Radix, and its lists, menus, tooltips, popovers and navigation panels are placed with Floating UI. The nine layer controls (select, multi-select, dialog, drawer, popover, confirmation, menu, tooltip, navigation) mark every layer they draw at the end of <body> with data-telo-layer, share one in-house layer stack, and are replaced as one unit: a UiReact.Controls set implementing any of them implements all nine (UI_CONTROLS_LAYERS_PARTIAL / ERR_UI_CONTROLS_LAYERS_PARTIAL). The contract, the scenes that draw every part, a DOM-only interpreter that runs vectors and scenes and tokenProperty, a design token's CSS spelling, ship as the code entry @telorun/ui-react-contract. A new cascade layer, telo.control, sits between telo.base and telo.theme and holds each built-in control's mechanics as a stylesheet of its own, named per control in the application document's new controls field, which also names the control sets a theme supplies; the renderer loads them through the host's module loader (mount takes one), and a set that does not load or a control that throws is an error node, ERR_UI_THEME_CONTROL_LOAD_FAILED or ERR_UI_THEME_CONTROL_FAILED, never the built-in. The styling contract lists the reserved properties a theme must not declare. Breaking: telo.base no longer styles any part only a control draws (input, select, checkbox, option groups, tags, sliders, switches, choice lists, menus, tooltips, overlay positions and the icon's layout move to telo.control); row-edit, row-delete, pager-prev and pager-next no longer carry their tooltip's data-state; data-invalid, data-placeholder and the open, on and checked states of a control's parts are documented with that control; the mechanics read no --radix-* custom property, so a stylesheet reading one gets nothing.
* UiReact.App.pages is a list of Ui.Page, written in place or named by reference, a library's included, and UiReact.App.navigation is a Ui.Navigation tree naming pages by reference, never by path. The header draws the tree through the Navigation control in a row — a group a dropdown, a nested group a submenu, what does not fit under More — and below compactBelow a menu button (the nav-menu part, first in the header, or last for a drawer opening from the end edge) opening the whole tree in a column in its surface; the shown page's entry and every group on the way to it are marked current. An entry naming a page pages does not list, at any depth, is refused by telo check (RESOURCE_RULE_VIOLATED, data.rule UI_NAVIGATION_PAGE_UNROUTED) and at creation (ERR_UI_NAVIGATION_PAGE_UNROUTED). The application document carries navigation. Breaking: a page is a Ui.Page, so a pages entry gains kind: Ui.Page or becomes a reference; the nav-link part is gone, the nav part holds the Navigation control, and a theme styles the new nav-menu part. Requires telo 0.121.0, whose rule pointers repeat a group.
* UiReact.App serves every text translated: translator: names an I18n.Translator, lang: is evaluated per request (a language tag, or CEL over request.headers), and the documents and the shell's html lang use the effective language - the catalog language the request's tag falls back to, else the language the title is written in - with one cached copy per language. Each text crosses as { message, lang } (the chosen Message, parsed) and the browser formats plurals, placeholders and numbers with the message core; enumeration values are shown by their translated labels and a field's description is drawn as a hint. Vary names exactly the request headers the per-request expressions read. Breaking: words: !ref Ui.words is required, and title and page titles are Texts. The built renderer entry is held to the message core's conformance vectors and carries the CLDR notice.
* UiReact.App takes an optional header: { start, end } of Ui.Node lists, drawn on every page (the not-found page included) before the title and after the navigation, in the new header-start and header-end parts. Header nodes travel in the application document and are resolved as a page's own nodes: when and leaf values evaluated per request over request, texts translated, composites provided, and the headers they read joining Vary; no browser root is in scope there. The renderer's layout draws both parts as wrapping rows with the end pushed to the inline end, and the default theme styles them.
### Fixed
* A table, a form and an option source now read and write their app-relative basePath under the application's mount, as a reader reads its source.path; a change is still announced under the basePath as written. After a save, afterSubmit: again returns the form to the values a new record starts from — the model's defaults and each date range's initial preset — instead of emptying it.
* One UiReact.App mounted on two servers answers a page request on each: the page is evaluated in the request scope of the server the request reached, where every server but the last mounted answered 500.
* The default theme underlines links (a link node, a link in a table cell or a value, a chosen picker value) in the accent colour, wraps long unbroken text, values and links inside their box, gives subheadings and list headings a heavier weight than body text, cuts a long filter chip with an ellipsis, insets sliders so the thumb stays inside its column at either end, and spaces the controls of a filter bar further apart. A switch field draws the switch and its label on one line, as a checkbox field does.

## 0.3.0 - 2026-10-10
### Added
* The renderer draws a Ui.Action — a form over the operation's input model with one button, which posts the entered record as JSON and draws each declared list from the answer, a 400 on its fields and any other failure as an error node — and a table's row actions, as labelled buttons before edit and delete that post the row's bound record, ask first where a question is declared, reload the tables over the same collection on success and show a refusal in a confirmation. Every form enters list properties: a multi-choice group for a list of listed values, typed tags for any other list of scalars, checked item by item in the page and left out when empty. A value whose model property declares format uri or uri-reference is drawn as a link in a table cell and an action's list when it is an address a link node may hold, and as plain text otherwise; such a link to anything but a page of the application carries target=_blank and rel=noopener. Breaking: the host takes a click on an anchor as a move within the application only when its path is exactly a declared page's — it used to take every address under the mount, showing Not found for a file served there — so a link node, a component's anchor or a cell link to such a file is now an ordinary browser load; navigate is unchanged. New parts: action, action-result, list, list-heading, options, option, tags, tag, tag-remove, row-action; data-state is also carried by action and row-action, and data-invalid by options and tags.

## 0.2.0 - 2026-10-08
### Added
* A filter bar shows the filters on one property together: one label, with each control captioned by its operator - from and to for gte and lte, after and before for gt and lt, is, contains and one of for the rest - so a date range reads as one field. Three styling parts are new: filter-group, filter-bound and filter-caption. The filter part now holds every filter of one property, where it held one filter.
* An edit form opens over the record read from GET <basePath>/<rowKey value>, not over the row the table showed, so a list narrower than a record no longer clears the properties it leaves out; while the record loads the dialog shows the loading part, and a failed read shows an error node. BREAKING: a collection a table edits must answer GET on an item.
* Every filter policy is drawn. A bar sits above its content, beside it on either side, folded behind a toggle that counts the active filters, or in a dialog, drawer or popover closed with Done, with pinned filters, Apply and Reset outside whatever folds, no toggle where a folding placement has no filter to fold, and the compact placement below the application breakpoint. Under show: chosen a list offers the filters not on show and each one on show can be removed; controls: chips opens each control from a chip; the select, options, toggle, slider and tags controls are drawn; apply commit, typing and button, summary chips, presets, and Reset returning to the declared defaults are honoured. A bar declaring policy.state keeps what is applied in the query keys _telo.f.<key>.<property>[.<operator>] (replacing the history entry, never adding one, and carried across the history entries of its page) and in browser storage under telo.ui:<mount path>:f:<key>, the address winning at the start and every value read back checked against the declared filters; a store the browser will not read or write is reported once and the bar continues in memory. BREAKING: a filter bar's controls are now inside a new filters-bar part and what it filters inside a new filters-content part; both were direct children of filters, so a stylesheet selecting them as children of filters must be updated. New parts: filters-bar, filters-content, filters-toggle, filters-count, filters-add, filters-apply, filters-presets, filters-preset, filters-summary, summary-chip, summary-chip-remove, filter-remove, filter-chip, filter-options, filter-option, filter-toggle, filter-slider, filter-tags, filter-tag, filter-tag-remove, menu and menu-item. New attributes: data-placement, data-side and data-pending on filters, data-active on filter and filter-chip.
* Every form surface is drawn: dialog, drawer on four sides, popover, inline (create above the grid, edit under its row), panel beside the list, and a page surface in place of the page content. An addressed surface keeps what is open in the query key _telo.open.<name> as a history entry: opening adds one unless a form of the same table is already open in the address, and closing removes only that surface's key, so another surface open on the page stays open. A surface with compact is replaced below the new UiReact.App compactBelow breakpoint (default 40rem, carried in the application document; app carries data-compact), and one open when the viewport crosses it is swapped in place with what was entered. A form fills its surface, its actions at the bottom edge. afterSubmit close, again and keep are honoured, and under unsaved: confirm a form holding unsaved input asks before anything closes it — its own dismissal, navigation, host.navigate from a component, back and forward, and the browser prompt on unload. BREAKING: every dialog-* styling part is renamed into one family shared with confirmations — dialog-overlay, dialog, dialog-header, dialog-title, dialog-description, dialog-close become surface-overlay, surface, surface-header, surface-title, surface-description, surface-close, with new surface-body, table-main and table-detail parts and data-surface, data-side, data-size, data-align, data-modal, data-dirty and data-compact attributes; a stylesheet written against the dialog parts must be updated.
* The renderer offers what a collection declares. Breaking for applications, through the ui vocabulary it renders: every Ui.Table and Ui.Filters placed on a page now names a Ui.Collection, a column carries a sort control only where that collection lists its property, and a filter bar shows the collection's declared filters with their declared operators. The renderer itself is unchanged: it already drew each control from the operator and each sort control from the column it was handed.
* UiReact.App, a mount that serves a Ui interface as a web application: the page shell, per-request application and page documents, content-addressed scripts, stylesheets and fonts, and an event stream, drawn by a prebuilt React renderer. Ships the styling contract (parts, states, cascade layers) and the ui_react-1 component ABI with the useHost host module. An edit form sends the whole row back, since PUT replaces it: the row's model properties with each field's entered value over them, and an emptied field left out. Requires telo 0.112.0 or newer (requires: telo: ">=0.112.0").
