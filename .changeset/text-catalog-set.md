A kind can mark a text catalog set: `x-telo-text-catalog-set: true` on a node of its `schema:` says the catalogs at and beneath it form one lookup set — every `TextCatalog` written there, and the catalogs in the configuration of each resource a reference there names, through that resource's own catalog sets, each resource once. One text and context translated twice in one language across the set is `MESSAGE_ENTRY_DUPLICATE`, keyed by the message core's identity (so a nested plural source and the plain pattern it reaches through `other`, `{ $n }` and `{$n}`, `pl` and `PL` are one), reported at the reference — or inline catalog — that brings in the later occurrence: by `telo check` for the entry's own resources — at the top level, as members of a `with:` scope and as entries of a template body — and, for a library's resource input, at each import supplying it; by the kernel before the holder's controller is created (`ERR_MESSAGE_ENTRY_DUPLICATE`). A mark whose value is not `true` is `SCHEMA_VIOLATION`, and one reaching neither a catalog nor a reference slot, or nested under another, is `TEXT_CATALOG_SET_INVALID` — at the kind, at the import reaching a dependency's, and when the kernel registers the definition (`ERR_TEXT_CATALOG_SET_INVALID`). The Rust kernel refuses a resource whose kind marks one (`ERR_UNSUPPORTED_MANIFEST_FEATURE`). The analyzer exports the reader both halves use: `textCatalogSetProblems`, `textCatalogSetMembers`, `textCatalogSetDuplicates`, `declaresTextCatalogSet`.

A kind whose whole schema is the `TextCatalog` fragment now has its catalog judged by `telo check` as any catalog is (every `MESSAGE_*` catalog code and `MESSAGE_TEXT_UNUSED`), read from what its resource writes beside `kind` and `metadata`. An expression above a catalog slot — a list of catalogs computed whole — is `MESSAGE_ENTRY_COMPUTED` at the expression, by `telo check` and by the kernel before evaluating it (`ERR_MESSAGE_ENTRY_COMPUTED`), as is a catalog a template body or a `base:` mapping computed before handing it on; a bare `self.<path>` forward is not computed. The analyzer exports `catalogsComputedAbove`, `siteValueOf` and `catalogComputedProblem`.

What a consumer hands a template body's entry with a bare `self.<path>` — a catalog, or a reference to one — joins the set the entry writes itself: `telo check` judges the two as one set and reports a duplicate at the consumer's own path, and the kernel reads each reference as the template forwarded it, so the same duplicate is refused at run. A bare `self.<path>` at a catalog slot of a body entry is no longer `MESSAGE_ENTRY_COMPUTED` at the library defining the body.
