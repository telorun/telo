# Opening the app in a browser

## Problem

A Telo web app cannot open itself. `telo run` logs `Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http` and leaves the person to put a URL together. `--open` opens only the inspector, and only together with `--inspect`. A terminal sign-in has the same gap: `OAuthClient.Authorization` returns a consent `url`, and the manifest can only print it.

The app decides when a page should open, and never waits for it. The person consents by running it at an interactive terminal, and declines a run with `--no-input` or a `BROWSER` that opens nothing. Once the app has started, the terminal's input is the app's alone: the host never reads it. An app that wants to ask before opening asks with its own steps.

## `Telo.OpenUrl`

A new built-in `Telo.Invocable` in `sdk/builtins/`, implemented by the kernel. It needs no import; like every built-in it reaches `telo check` through the `Telo.Builtins` archive the analyzer ships.

- **Input:** `url`, a `Telo.Url` with scheme `http` or `https`.
- **Output:** `null`. The call hands the URL to the host and returns at once; whether a browser opened is the host's business, and no outcome is an error, so a missing browser never stops an app or delays the targets after it.
- **Always logged:** every call logs one `info` record `telo.url.open_requested` with `url.full`. The URL is in the log whatever the host does with it.

An app opens its start page with a `targets:` step after the server, reading the server's own `localUrl` (below). A sign-in calls it as a step with the consent `url`, then waits for its callback as it does today.

```yaml
kind: Telo.Application
metadata: { name: Notes, version: 1.0.0 }
requires: { telo: ">=0.133.0" }
imports:
  Http: oci://ghcr.io/telorun/http-server@0.44.0
ports: { http: { env: PORT, protocol: tcp, default: 8080 } }
targets:
  - !ref server
  - invoke: { kind: Telo.OpenUrl }
    inputs: { url: !cel "resources.server.status.localUrl" }
---
kind: Http.Server
metadata: { name: server }
listen: { port: !cel "ports.http" }
mounts:
  - path: /
    mount: { kind: Http.Static, root: !module-path ./public }
```

The hard case, a terminal sign-in:

```yaml
kind: Telo.Application
metadata: { name: SignIn, version: 1.0.0 }
requires: { telo: ">=0.133.0" }
imports:
  OAuth: oci://ghcr.io/telorun/oauth-client@0.12.0
  Store: oci://ghcr.io/telorun/kv-store-memory@0.8.1
secrets: { clientSecret: { env: OAUTH_CLIENT_SECRET, type: string } }
targets: [!ref signIn]
---
kind: OAuth.TokenSource
metadata: { name: tokens }
client:
  kind: OAuth.Client
  authorizationServer: { kind: OAuth.AuthorizationServer, issuer: "https://auth.example.com" }
  clientId: notes-cli
  clientSecret: !cel "secrets.clientSecret"
  scopes: [read]
store: { kind: Store.Store }
key: default
---
kind: Telo.Sequence
metadata: { name: signIn }
with:
  - { kind: OAuth.RedirectListener, metadata: { name: loopback } }
targets: [!ref loopback]
steps:
  - name: auth
    invoke: { kind: OAuth.Authorization, source: !ref tokens }
    inputs: { redirectUri: !cel "resources.loopback.status.redirectUri" }
  - invoke: { kind: Telo.OpenUrl }
    inputs: { url: !cel "steps.auth.result.url" }
  - name: redirect
    invoke: { kind: OAuth.RedirectAwait, listener: !ref loopback }
    inputs: { state: !cel "steps.auth.result.state" }
  - name: exchange
    invoke: { kind: OAuth.TokenExchange, source: !ref tokens }
    inputs:
      code: !cel "steps.redirect.result.code != null ? steps.redirect.result.code : ''"
      codeVerifier: !cel "steps.auth.result.codeVerifier"
      redirectUri: !cel "steps.auth.result.redirectUri"
      iss: !cel "steps.redirect.result.iss"
  - invoke: { kind: OAuth.GrantWrite, source: !ref tokens }
    inputs: { key: default, tokens: !cel "steps.exchange.result" }
```

Refused cases. A literal URL of another scheme is refused by `telo check`:

```yaml
kind: Telo.Application
metadata: { name: Report, version: 1.0.0 }
requires: { telo: ">=0.133.0" }
targets:
  - invoke: { kind: Telo.OpenUrl }
    inputs: { url: "file:///tmp/report.html" }
```

```console
$ telo check ./report

```

A computed one passes `telo check` and is refused when the call runs:

## Who answers

The kernel takes an optional, fire-and-forget open-url hook from its host, beside the existing hook that asks for missing inputs. A kernel with no hook does nothing beyond the log record.

- **`telo run` at a terminal** (stdin and stderr are TTYs, no `--no-input`) installs the hook. It opens the URL at once, with no question, and never reads stdin: the missing-input prompt reads it before the app starts, and after that it belongs to the app.
  - **Opening:** `$BROWSER` first, otherwise the OS opener, the URL passed as one argument and never through a shell, so a consent URL's `&` and `%` arrive intact. Inside VS Code remote, `$BROWSER` is VS Code's helper, which opens the page in the local browser and forwards the port.
  - **A failed launch** prints the reason and the URL on stderr. Today's opener ignores a failed spawn; that is fixed for both its callers, the inspector included.
  - **A URL is opened at most once per session.** A `--watch` reload opening the same start page opens no new tab; a new consent URL opens.
- **Every other host** installs no hook: `--no-input`, runner sessions, CI, pipes, the test suite and the Rust CLI. The log record carries the URL.

```console
$ telo run --watch ./notes
INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080
INFO  telo.url.open_requested  url.full=http://localhost:8080
# the browser opens http://localhost:8080; a file is edited and the app reloads, no new tab
INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080
INFO  telo.url.open_requested  url.full=http://localhost:8080

$ telo run --no-input ./notes
INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080
INFO  telo.url.open_requested  url.full=http://localhost:8080

$ BROWSER=true telo run ./notes
INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080
INFO  telo.url.open_requested  url.full=http://localhost:8080

$ BROWSER=/nonexistent telo run ./notes
INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080
INFO  telo.url.open_requested  url.full=http://localhost:8080
Could not open a browser (spawn /nonexistent ENOENT). Open http://localhost:8080 yourself.

$ OAUTH_CLIENT_SECRET=s3cret telo run ./sign-in

# the browser opens the consent page; the run waits for the redirect, then stores the grant and exits
```

An app that wants to ask first asks with its own steps, so the terminal still has one reader. Under `--no-input` that question is still the app's and is still asked; the open step then only logs the URL.

```yaml
kind: Telo.Application
metadata: { name: Notes, version: 1.0.0 }
requires: { telo: ">=0.133.0" }
imports:
  Http: oci://ghcr.io/telorun/http-server@0.44.0
  Console: oci://ghcr.io/telorun/console@0.19.1
ports: { http: { env: PORT, protocol: tcp, default: 8080 } }
targets:
  - !ref server
  - invoke:
      kind: Telo.Sequence
      steps:
        - name: ask
          invoke: !ref Console.readLine
          inputs: { prompt: "Open the notes in your browser? [Y/n] " }
        - name: open
          if: !cel "steps.ask.result != 'n'"
          then:
            - invoke: { kind: Telo.OpenUrl }
              inputs: { url: !cel "resources.server.status.localUrl" }
---
kind: Http.Server
metadata: { name: server }
listen: { port: !cel "ports.http" }
mounts:
  - path: /
    mount: { kind: Http.Static, root: !module-path ./public }
```

## `Http.Server`'s local URL

- `Http.Server` declares `status: { localUrl }`, a `Telo.Url` (`http`, or `https` under `tls`) set in `run()` once the socket listens. `0.0.0.0` and `::` are written as `localhost`, an IPv6 literal in brackets. It is the socket's URL, not a public address.
- Its `http.server.started` record (message `Listening`) gains `url.full` with the same value.

Before: `INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http`

After: `INFO  Listening  server.address=0.0.0.0  server.port=8080  url.scheme=http  url.full=http://localhost:8080`

## The chat example

`examples/chat` keeps its `targets:` order and adds the open step right after `!ref server`, reading `resources.server.status.localUrl`, as in the first example above. Its description stops telling the reader to open `http://localhost:8080`, and its `requires: telo:` floor moves to the release that carries `Telo.OpenUrl`, verified by execution as the root guide requires. It declares no need and its tests change nothing.

## Rust half

`kernel/rust` refuses a `Telo.OpenUrl` resource with `ERR_UNSUPPORTED_MANIFEST_FEATURE`, naming the kind. `cli/rust` installs no hook.

```console
$ telo run ./notes      # the Rust build of the CLI
error [ERR_UNSUPPORTED_MANIFEST_FEATURE] targets[1]: Telo.OpenUrl is not supported by this kernel
```

## Documentation and records

- The root `CLAUDE.md`, `kernel/nodejs/CLAUDE.md` (the host hook) and `cli/nodejs/CLAUDE.md` (stdin is read only before the app starts; the session memory) describe the behaviour.
- `modules/http-server/docs/log-events.md` adds `url.full` to `http.server.started`, and the module docs describe `status.localUrl` as the socket's URL, not a public address.
- The authoring agent's primer gains `Telo.OpenUrl`, the start-step pattern and the ask-first pattern.
- `docs/guides/what-you-get.md` gains an entry under **Telo itself**: an app opens its own page once it is listening when run at a terminal, and logs the address everywhere else.
- One changeset for the telo version line.
- A `telo release add` fragment (`Added`) for `http-server`.

## Verify

1. In a VS Code Remote-SSH terminal, `pnpm run telo --watch ./examples/chat` with nothing set: after `Listening` the chat opens in the local browser and the record shows `url.full=http://localhost:8080`. Editing a file reloads without opening another tab.
2. `pnpm run telo --no-input ./examples/chat` starts with no address set, asks nothing, and logs `telo.url.open_requested` with `url.full=http://localhost:8080`.
3. `tests/telo-open-url.yaml` (`Assert.Equals`): with no hook the call returns `null` and the record is logged; a step reading `localUrl` listed before `!ref server` fails with `ERR_OBSERVED_STATE_UNAVAILABLE`.
4. CLI unit tests over recorded streams: the hook attaches no listener to stdin and never resumes it, and an app-side reader fed lines while a URL is opened receives every line in order; the same URL twice in one session opens once, two different URLs both open; no TTY or `--no-input` opens nothing and still logs; an opener that fails to spawn prints the reason and the URL.
5. A CLI unit test per platform opener (Linux, macOS, Windows) receives a consent URL holding `&` and `%` as one unchanged argument.
6. By hand at a terminal: a paste-the-code sign-in (`Telo.OpenUrl` on the consent URL, then `Console.ReadLine`) opens the browser and the pasted code reaches the app intact.
7. Under `tls`, the record and `localUrl` read `https://localhost:8443` for `listen: { port: 8443 }`.
8. A Rust kernel test: a manifest declaring `Telo.OpenUrl` is refused with `ERR_UNSUPPORTED_MANIFEST_FEATURE` naming the kind.
9. `npx @telorun/cli@<previous> check examples/chat` with the `requires:` block removed reports the unknown kind. With the block back it reports `MODULE_REQUIRES_NEWER_RUNTIME`.

The editor half (studio and the VS Code extension offering an Open button) is a separate change, and adds its own event then.
