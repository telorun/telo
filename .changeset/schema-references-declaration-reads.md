A reference at a `use: schema` slot is now a declaration read. The kernel never puts the target's instance there and never makes the holder wait for its target, so a resource whose `use: schema` slot names itself, or two resources naming each other, boot where they used to fail with `ERR_LOCAL_REF_PENDING` while `telo check` passed. The holder receives the reference as written and reads through it from declarations: `ctx.resolveDeclaredManifest` returns the target's fields, and `ctx.lookupSchema` returns a named shape's schema with its `extends` parents folded, from the shape's declaration when it has not been created yet. A controller that read the live instance out of a `use: schema` slot must read the declaration instead. Such a reference no longer orders teardown, and editing its target still re-creates the holder. A template body's bare `self.<path>` that continues past such a reference reads the declaration it names, resolved in the module that wrote the reference; past any reference, at `telo check` and at boot alike, a named shape is read with its `extends` folded, so a forward of an inherited property is checked as it runs. A literal in a call's `inputs:` written in its plain encoding (RFC 3339 text at a `Telo.Timestamp`) is still read as the instance when the called resource is a library's export whose `inputType` is written inline: the shape the analysis extracted from it is answered from the analysis, since no document holds it.
