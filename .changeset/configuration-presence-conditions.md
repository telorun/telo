"@telorun/kernel": minor

`analyze()` takes `within`, a partial assignment in the `data.configurations` entry encoding (a dimension's key → its value; a need's presence `"present"` / `"absent"`; an input's absence `null`), which keeps only the configurations agreeing with it: the analysis covers those, labels each finding among them, leaves out a finding that holds only in configurations outside them, and still reports one that holds in no configuration at all — a branch no configuration takes is checked at a configuration reaching its choice whether or not `within` keeps that configuration, so what it finds is the same under every `within`, a branch nested inside an option `within` leaves out included. The configurations kept are what every judgement of a narrowed analysis is relative to, so narrowed to one configuration it judges every site it keeps once and normalizes no declaration as varying; a site that a branch no configuration takes reads outside its own reach is judged at that branch's configuration for the whole space — once per distinct reading, however many such branches read it, and never by reusing a judgement made only for the configurations kept, which could have held fixed something that configuration varies; this holds in an analysis with no `within` too, so what such a branch finds is the same under every `within`. A key naming no dimension, or a value outside its domain, throws. `StaticAnalyzer.configurationsOf` lists the dimensions of the whole space and the configurations an analysis keeps, together with the union of every configuration's expansion — the one `analyze()` reads, whatever `within` keeps — in which each declaration, field value and list item a choice decides carries the presence condition it is taken under (`expandUnion`, `ConditionSpace`). A label and a `requiredWhen` are now read off one cover of that condition: the blocks are grown in the same order as before, but a block that later blocks already cover is no longer listed. Each label, and each `requiredWhen`, still describes the same configurations.

Over several configurations, each CEL expression is now type-checked once per distinct set of values it reads, instead of once per configuration or once per declaration. Those values are the inputs the configuration decides, the result types of the steps it reads, and the declarations, regions and references it reads directly or through the annotations covering it — whether any declaration reports observed state included, for an expression reading observed state or written in a kind document or an `imports:` entry, and the whole declaration for an `inputs` read typed by a contract its kind derives from that declaration. Each finding is reported for exactly the configurations those values hold in, so the reported findings and their labels are unchanged. This removes one source of analysis time that multiplied with every independent `!if` / `!switch`: a sequence of steps, each choosing on its own flag and reading the step before, now checks each step's expression a bounded number of times.

The diagnostics merge now takes findings with presence conditions (`mergeConditionedDiagnostics`). `ConditionedDeclaration` carries the document and place each union declaration is written at. Each union option carries its written place (`AlternativeOption.at`), and `ConditionedExpansion.project` projects any union value to one configuration together with the condition of the options it takes.

The builders that type a CEL expression no longer receive a list of manifests; they ask for what they read. A `DeclarationRequests` object (`listRequests(manifests)` answers every request from a list) offers two forms: by name (`names`, the scoped rule) and named enumerations (`kindDocuments()`, `moduleDocuments()`, `published()`, `callables()`, `catchScope()`, `referrersOf(m)`). `buildKernelGlobalsIndex`, `observedDeclarations`, `buildObservedStateIndex`, `ModuleFunctionIndex`, `CatchLadder`, `collectScopedManifests`, `TextLanguageScope`, `CelScopeQuery`, `resolveTypeFieldToSchema`, `isTypeKind`, `resolveNamedShape`, `analyzerContractScope`, `buildStepContextSchema` and `manifestRootForResolver` take one in place of a list. Several option fields are renamed with it: `CelScopeInputs.allManifests` becomes `declarations` and gains `shapes`, and drops `referrersOf`, which is now a request. `ContractScope.typeManifestsFor` becomes `declarationsFor`, `NamedShapeScope.typeManifests` becomes `declarations`, and the third argument of `resolveContextAnnotations` is the options object alone, with `allManifests` renamed `declarations`. `manifestListScope` is now `projectionScopeOf(declarations, …)`. `CelScopeQuery` takes the module-call names as its third argument. Name resolution goes through a resolution seam. `resolveRefSentinels` and `resolveShapeRefs` take a `RefResolution` (`listResolution(resources, crossModuleTargets)`) in place of the cross-module target list. `readTemplateConsumers` takes `names` and `buildTemplateForwardViews` a `NameResolution` (`namesResolution(manifests)`). A `ConditionedNameIndex` answers the same lookups over the union, each outcome under the condition it holds in. The union now keeps a branch no configuration takes as an unreachable option. An option carries its local condition and the choices taken to reach it, and an unreachable branch also carries a configuration reaching its choice. `ConditionedExpansion.at` and `project` take a forcing (choice → branch). `project` returns the place map that moves a projected position back to where it is written. No finding or label changes.

Each distinct set of values a CEL expression reads is now judged in an environment of its own, built from those values alone: the expression's own declaration and every declaration none of the configurations varies, as they stand where those values hold, plus the declarations the values cover — and nothing else. No configuration is analysed to judge an expression any more. Three more reads are captured: the declaration a step invokes, with its contract (`steps.<name>.result` where the invoked declaration's own `outputType` holds a choice); a named shape a contract or a kind's schema names (a `Telo.JsonSchema` with a member under `!if`); and a branch no configuration takes, whose expressions are judged where its choice is reached with the branch taken. A read the values do not cover stops the analysis with an internal error naming the expression and what it asked for, instead of producing a finding about some other configuration. `buildStepContextSchema` takes the steps the judged expression reads and types a step it cannot reach without reading the step's target. `ConditionedExpansion` gains `takenAt` and `relocatorOf`, `ConditionedNameIndex` exposes its condition `space`, `CatchLadder` gains `holdsCatchEntryAt`, and `observeAnalysisRuns` reports each analysis pass with its purpose. A read of a declared `resources` entry whose content the values do not cover stops the analysis however it reads the entry, the whole value included (`resources.x != null`). Named shapes no configuration varies are the only ones the registry keeps between passes: each configuration's pass holds the others to itself, and outside a pass reading one is an internal error, so no configuration is checked against another's shape — and an expression typed through a shape a kind reaches by `$ref: telo://…`, in a contract or in a context its schema declares, is judged by where that shape varies. A `!ref` inside a branch no configuration takes resolves to what that branch declares (`ConditionedNameIndex.locateAt` / `inModuleAt`, over a `Witness`), so a step there is typed from a target the branch itself declares; `ChoiceReading.standIns` takes the forced choices, and `visitManifest` takes the named-shape lookup it reads schemas through (`shapes`).

Building those environments no longer costs the size of the application per expression judged. Each declaration is normalized once per distinct content and outcome of the references it stamps, and two judgements reading equal content share the same normalized declaration. A declaration no configuration varies and whose references resolve one way everywhere is normalized once per analysis and shared beneath every judgement; a judgement holds only the declarations its values cover. The typed CEL environment is cached for the whole analysis by the content it is built from (`CelScopeInputs.typedEnvironments`), in place of a cache keyed by manifest identity, so equal environments are built once across judgements. An application padded with a thousand declarations no configuration varies, each holding one expression, now takes time linear in their number, where it grew with their square. `ConditionedNameIndex` gains `locateFixed` / `inModuleFixed`, telling a lookup whose outcome is the same at every witness. No finding or label changes.

`AnalysisRegistry.forConfiguration(expanded)` is a read-only view of the registry as one running configuration holds it, beside `forModule`: a named shape no configuration varies is answered by the shared registry, one that varies by the shapes `expanded` declares (canonical in their module, `extends` folded, a library's beside), built by the function the analysis reads a witness's shapes with. Its `shapeLookup`, `referenceSitesOf`, `referencePositionsOf` and `refFieldsForResource` read through it. The kernel holds one view per module context — the root's from the running configuration's expansion, each import's from its own — and reads every named shape for a kind through the view of the context declaring it, so a kind reaching a shape that varies gets that configuration's eval paths, accessor sites and regions at `create()`, as `telo check` reads them there. A load that hits the analysis stamp now promotes to the shared registry only the shapes no configuration varies, as a cold load does.

A declaration's own schema checks — its configuration against its kind's schema (projections resolved, decided inputs as their literals), each `x-telo-value-schema-from` slot, a module file named at a host-path slot, and a `Telo.Abstract`'s shape — are now judged once per distinct set of values they read, outside every configuration's analysis: the declaration's content where those values hold, the named shapes its kind's schema reaches, the inputs it holds as literals, and what the annotations in it read. A choice in one part of a declaration is cut out into a region judged on its own where every schema node on the way reads its members one by one (`properties`, `patternProperties`, `additionalProperties`, `propertyNames`, list `items`, `type`, scalar `enum` / `const`, annotations, `allOf`); a keyword relating members (`oneOf`, count bounds, `required` naming a member the choice may leave out, …) keeps the choice with the node it relates. A declaration whose value a named shape refuses only where a choice leaves a member out of that shape is now reported for exactly those configurations, where it used to be reported for all of them. `collectValueSchemaIssues` and `valueSchemaSites` take the declarations a named type resolves against as a `DeclarationRequests` (`types`) in place of a list. A step invoking a member of its own `with:` scope is typed from that member as each configuration declares it. The kernel reads every declaration's reference sites — for data views, catalog sets, injection and need observations — through the configuration view of the module that declared it, and a view and the registry no longer evict each other's cached sites.

Every other check of a declaration's own is now judged the same way, outside every configuration's analysis, and the per-declaration signatures that gated them are removed: its inline declarations, a template's entry points against the contracts they meet, a contract slot typed by a projection that does not resolve, a module call where nothing binds one, what a reference slot's target returns and is given, a step's arguments and a live value a retry would lose, its bindings' names, its accessor fields, browser exports and expressions at or above a reference slot, a kind document's or named shape's annotations, a matcher no accessor can satisfy, and each expression's fit to the slot it flows into. These relate a declaration's parts, so each is judged over the whole declaration as a set of values projects it: its content there, the declarations its references name and what those name in turn, what its contracts read, and what each of its expressions was typed as where those values hold. An expression is now held to its slot as each configuration declares the slot — a value at a member of a named shape whose type a choice decides is reported for exactly the configurations it does not fit, where it was not reported at all. `DerivedSlotContext.typeManifests` becomes `types` (a `DeclarationRequests`), and so does the host field of `AnalysisRegistry.derivedSlotsOf` and `namedShapeOf`. The kernel now reads a declaration's reference positions — where it refuses an expression with `ERR_REF_SLOT_COMPUTED` — through the view of the module that declared it, as it reads its sites: a library's kind declared in the application with an expression at its reference slot is refused at creation, where the kernel used to evaluate the expression and leave data at the slot.

A kind document's or named shape's annotations, and a template definition's entry points (`inputs:` against its dispatch target, `result:` against its own output contract), are now judged per instance rather than over the whole declaration. Each instance is identified by the written place of what it compares (its anchor): `schema` for the first, and `inputs` or `result` for the second. It is judged once per distinct set of values it reads: the anchor as those values hold it, the places of its declaration it declares it reads, the inputs its expressions read, what the annotations in force at it read, and the declarations its references and named shapes name. Where to judge comes from a census by position. One pass reads a declaration at its first configuration, and one more reads each choice branch not taken there, at the first configuration taking it (forced where none does), so each written place is read once whatever the number of choices. A judgement no longer normalizes its declaration whole: it normalizes the anchor's region and each read place's region on its own, a manifest holding only the declaration's `kind`, `metadata`, the way to the region, and the region. Its rule receives that one instance, and asking for any place of the declaration it does not declare stops the analysis with an internal error. While each configuration is still analysed, its pass marks where each instance's findings go, and an instance there that the census does not hold is an internal error. `observeRelationParity` reports, at every configuration and every forced branch, where the census or a region read on its own differs from the declaration normalized whole. No finding or label changes.

Every other check relating a declaration's parts is now judged per instance in the same way, and no check is keyed by a declaration's whole content any more: an inline declaration left in place (at the inline value), a contract slot typed by a projection that does not resolve (at the contract the declaration writes, or at the declaration where its kind's contract derives from it), a module call where nothing binds one (at the text), what a reference slot's target returns and the arguments its `inputs:` names (at the slot), a step's arguments and a live value a retry would lose (at the step), a bindings field's names (at the field, and at `kind` for a kind pointing the annotation at several fields), an accessor field, a browser export (at the object holding it and the entry it names) and an expression at or above a reference slot (at that place), a matcher no accessor can satisfy (at the matcher), and each expression's fit to the slots it flows into (at the expression). A sequence of steps each choosing on its own flag is now judged a bounded number of times per step, where it was judged once per configuration. A judgement reads, beside its anchor and the places it declares, the declarations its references name, what its expressions were typed as, the steps whose results it forwards, the scopes declared on the way to it — through which its names resolve and into which extraction places what it draws out — and what each object on the way to it holds beside it, which selects a union branch there; any other read stops the analysis with an internal error. A named shape some configuration varies is read with every option of its choices kept while instances are found, and as each configuration holds it when one is judged. A declaration holding a resource of a templated kind keeps one judgement over the whole declaration, for the relations its forward views hold. No finding or label changes.

A declaration's own schema checks now read a reference by what it resolves to — whether it resolves, and to which kind and declaration — never by the content of the declaration it names, so an application whose boot target names a sequence of choices is judged once rather than once per combination of them; a reference read through an annotation that crosses it still reads what it names. Identifier names (a declaration's own name, its module's `variables:` / `secrets:` / `ports:` / `resources:` / `needs:` keys, a function's parameters and its steps' names) are judged with a declaration's schema checks, once per distinct value, and no longer in each configuration. No finding or label changes.

A relation judgement no longer reads what another instance of its own check judges: each region it reads — its anchor, the places it declares it reads, and the steps whose results it forwards — holds a stand-in in place of every instance of the same check nested beneath it, at that instance's position whatever any configuration takes there, so a step holding a list of steps, each choosing on its own flag, is judged once rather than once per combination of them; a rule needing anything of such a place must declare it as a read. `ConditionedExpansion.carve` returns a union value with places replaced by a stand-in, read by a projection as the union is. `observeRelationParity` also reports, for each instance, where its findings judged on the regions with those places carved differ from its findings judged on the same regions whole, and where a carved region read on its own differs from the declaration normalized whole with the same places carved. No finding or label changes.

A CEL expression's judgement reads its module's inputs as that module's globals, built once from its whole document, with only the inputs the expression reads narrowed to what the configuration decides laid over them; no judgement holds a module document any more, so declaring more inputs no longer makes every expression's judgement larger or slower. `observeRelationParity` also reports, for each CEL expression and each declaration's own-check site, where its findings judged that way differ from its findings judged on its declarations whole with the module documents whole and the configuration's narrowing whole (`keySites` counts the sites compared). No finding or label changes.

A declaration's own schema checks are now judged, for each distinct set of values they read, on the region of the declaration the check covers rather than on the whole declaration: the part of it no choice cuts away, with each part judged on its own replaced by a placeholder, plus the places the annotations and contracts in it read beyond it. A sequence of steps each choosing on its own flag is now checked step by step on that step alone, and the sequence on its own fields with one placeholder per step, so the work per check no longer grows with the number of steps. No finding or label changes.

A read of a step name no step in the sequence carries, such as a misspelled `steps.frist.result`, is now judged once for each set of step names the configurations give the sequence, so its `CEL_UNKNOWN_FIELD` lists the step names of the configurations it is reported for. Before, it was judged once and listed the step names of one configuration for every configuration. A read of a step that is there, by contrast, still depends only on that step and does not split by which optional steps beside it are present.

Every step body's `steps` is now one closed record in the CEL environment, whatever its steps produce, and the step context's schema never judges a step name. A misspelled step name in a body whose steps all dispatch, such as `steps.frist.result` beside `first` and `second`, is still one `CEL_UNKNOWN_FIELD`, now worded `"frist" is not declared here (declared: first, second)` and decided by the type checker at the misspelled member, where it was `'steps.frist' is not defined (available: first, second)` from the context schema; a body producing no result refuses every step name the same way. A named repeat's `steps.<name>` is typed by its shape — a map of `{ result }` by element key for a map source, untyped for a list source — so a misspelled member after `steps.<name>[k]` is refused. A step whose `value:` is one expression has its result typed once, by what the expression checks to where the step is written — a step inside a `catch:` sees `error` — and every reader takes that type, where it used to be re-checked in each reader's own scope; steps reading each other read each other as `dyn`, whichever order they are written in. A result typed where it is read could be given a type its own site never gives it, so such a reader may lose a finding that was wrong, and one whose producer types differently where it is written may gain one. `buildStepContextSchema` marks the context it returns, which `buildTypedCelEnvironment` registers as the closed record, and `KeyCost` gains `step-result-probe`, one per producer typed.

A CEL expression's judgement now normalizes only its region of the declaration: the expression, the places its annotations and contracts read beyond it, the steps it reads, the declaration's `inputType` and the scopes on the way. A step it reads whose value is one expression another judgement types is held as a stand-in carrying that judgement's result type, so a sequence of steps each choosing on its own flag and reading the step before is judged on that step and the one it reads, whatever the number of steps; the `steps` record lists the step names the judgement covers, every name where it reads one no step carries. A kind document's expressions, a template body's, and those of a declaration holding a resource of a templated kind are still judged on their declaration whole. `CelScopeInputs.stepNamesAt` gives the names a resource's `steps` record lists beyond the steps it holds. No finding or label changes.

A step whose `value:` is tagged now has its result typed by that step alone, once, as the pair of the type its value records and the schema a plain chain forwards, both resolved where the step is written; every reader takes that pair. A step forwarding another step's result (`!cel "steps.s0.result"`) or an input (`!cel "inputs.cfg"`) carries on the schema its own site resolves — references followed, `inputs` read from the resolved input contract, the kind's included — so a member read below a forwarded result is now checked where the source's declared shape was missed before: a forward of an input the kind's own `inputType` declares closed, with no `inputType` on the instance, now refuses `steps.fwd.result.missing` with `CEL_UNKNOWN_FIELD`. A step whose value is `!interpolate` now has a `string` result, so `steps.text.result * 2` is `CEL_TYPE_ERROR` where it was accepted. A forward of a literal step keeps the literal's closed record, as before. Over several configurations, a forward of a result whose declared shape a choice decides is now judged per shape, so a member it leaves out is reported for exactly the configurations leaving it out, where it was reported for all of them; and a chain of forwards no longer makes each read of the chain's end larger with the chain's length. `CelScopeResolver.stepsReadAt` gives the `steps` record a site reads.

A schema finding's message now quotes the place it is reported at, as written: a finding inside a list item a choice includes, or after one, quotes the written index and branch (`/targets/1/then/timeout must be >= 1`), where it used to quote the index one configuration's expansion gave it (`/targets/0/timeout`) and so read differently per configuration. Manifests without choices read as before. Each judgement over configurations is also keyed by where a place is written rather than by that projected index, so a list item after an `!if` item is judged once rather than once per number of items before it, and a site a configuration leaves out reads nothing. The same holds for the messages that quote a dotted path: a reference or step `invoke:` that does not resolve or has the wrong kind (`reference at 'targets[1].then'`), a value held to the type declared elsewhere on the resource, a template body entry's target mismatch, a scope member's schema finding and a schema matched against an accessor it can never hold for, which names both places (`the schema at 'content.children[1].then.shown.matches' can never hold for 'content.children[1].then.shown.at'`). Each quotes the place as written, after or inside a choice, where it quoted the index one configuration's expansion gave it. `data.quotedPlace`, which a message quoting its place carries beside `data.path`, is now a list with one entry per place the message writes.

Every forward view is built by one builder (`buildForwardViews`), which works over the union of every configuration as well as over one configuration's declarations. Over the union it is lifted: a forwarded value keeps the options its choices give it, moved to where the consumer wrote it; a body `!if` / `!switch` whose read some configurations vary is an option node, one option per outcome; an item a `!for-each` emits for an element some configurations leave out, or place elsewhere, holds only where it is that element; and a reference the path crosses names each declaration it can resolve to, under the condition it resolves there. `ConditionedExpansion` holds the views beside its declarations (`views`, `ConditionedView`: its consumer and its condition, the consumer's AND the body options it is built through), registers containers it did not build (`hold`), tells where a declaration is written (`placeOf`), and projects a container from its own written place; an option and a place mapping may be `exact`, reporting everything beneath it at the option itself. `StaticAnalyzer.configurationsOf` returns the union with its views and `viewsAt(assignment)`, the views of that configuration's own expansion. `ChoiceReading.valueOutcomes` gives every value an expression takes over a space, each with its condition; `TemplateExpander` gains `space`, `branches` and `keys` and `LoopElement` a `holding`, read only by a lifted expansion; `createConsumerExpander` and `readTemplateConsumers` take `lift` (`ConsumerLift`). A finding about a view is now placed by the view's place map, through the same rendering every other relocation uses, in place of `TemplateForwardViews.mapDiagnostics` (now `placed`): a forwarded finding whose message quotes a place now quotes it where the consumer wrote it, where it quoted the entry's own place. No other finding or label changes.

A forwarded expression is now typed where the view holds it, once per key of that view's site, so a finding inside a forwarded value carries the full condition it holds under: a forwarded step reading another step is labelled with both steps' choices (`(when variables.flag1 is false and variables.flag2 is true)`), where it named only its own. One written place may now be several CEL sites — the consumer's own expression where no view holds it, and each view holding it where that view holds — so an expression a body forwards only where a consumer field says so is judged as the entry's field there and as the consumer's elsewhere. A view keeps a forwarded value's branch no configuration takes, so that branch is judged as the entry's field too. `ConditionedView` gains `upstream`, the declaration it was built from, and `StaticAnalyzer.configurationsOf`'s `viewsAt` takes a forcing, giving the views of a branch no configuration takes. Where several sites share a written place, what each expression was typed as is read in the order a run meets them — each by its position in the layout of forward views the run lists, every view's own, then what its slots drew out — so a declaration drawn out of one entry's view and held in place by another's is judged on its own typing. A value a body forwards across a reference into a resource that holds a choice (`steps: !cel "self.src.steps"`, `holder` holding an `!if`) is now checked, where it stopped the analysis with an internal error; each judgement over the consumer reads the places the forward crosses into, never the referent whole, and `ConditionedView` gains `crossed`, every reference its forwards read across.

A consumer of a templated kind written beneath another declaration — inline at a reference slot or as a step's target, at any depth, or as a `with:` member — now gets its forward views in the union too, each under the consumer's own condition AND the options on the way to it, so its forwarded expressions are typed once per distinct reading, like a top-level consumer's, where every expression of the declaration holding it was judged on that declaration whole; such a finding is now labelled with the configurations it holds in, where it could hold in every one (`(when variables.flag1 is false)` on a step a forwarded choice types). `ConditionedDeclaration` gains `declaredIn`, the declaration of the union a nested consumer is written in, and `StaticAnalyzer.configurationsOf`'s `viewsAt` gives exactly the views a configuration's own run builds, nested consumers included. A finding about a declaration drawn out of a view now quotes its place re-rooted at the consumer that wrote it (`'value'` at `steps[0].invoke.value.else`), where it quoted it from the drawn-out declaration.

A nested consumer is identified by where it is written. A `with:` member consumer's forward that crosses a reference now resolves it in the member's scope, as the run resolves it: `src: !ref src` naming a sibling member reads that member, shadowing a module-level `src`, where it read the module-level one or stopped the analysis with an internal error, and a choice in that member's forwarded value is checked at the reference. Where expressions drawn out at different depths of one view share a written place, each is read in the order a run meets it by its own position in the layout (`CelOccurrenceFacts.layout`, in place of `CelSiteVerdict.layout`, one position per judgement).

A finding inside a declaration written inline now names the declaration the author wrote and quotes the full written path: an inline `Run.Sequence` step target's CEL error reads `Run.Sequence/holder: CEL at 'steps[1].invoke.steps[0].inputs.a' …` in every configuration, where it named a generated name that followed the step's projected index and quoted the place relative to the extraction. The same holds for a forwarded value reported at an inline consumer. No generated name appears in a message label or in the `available:` list of an unknown `resources.<name>`, and a quoted place is the `data.path` it is reported at, except a place relative to a template body entry or to a `with:` member the author named. A step target's contract mismatch names an inline target as "the inline Run.Sequence" where it named the generated name.

A zone refusal names an inline declaration as "the inline GraphLayers.NodeConflicts" where it named the generated name (the origin, each hop of the path, the region provider and the contained resource), and a throws-coverage finding about an inline handler reads "handler the inline Run.Sequence". A rule that did not run (`RESOURCE_RULE_SKIPPED`, `REFERRER_RULE_SKIPPED`) at a place inside an inline declaration quotes it as the full written path.

Checking a resource that reads across a reference — a step's target, or a forward through a reference slot (`steps: !cel "self.src.steps"`) — now holds the referenced declaration only as the places it reads there (the target's `outputType` and `inputType`, the steps forwarded), never the declaration whole, so its CEL and schema checks no longer grow with the size of the declaration it names. A step reading the result of a target that declares no output contract, whose contract its kind derives from a value slot (a `Run.Value`'s `value:`, a `Run.Sequence`'s `outputs:`), is now checked against that slot as each configuration writes it: `steps.made.result.x` over a `value:` a flag chooses between `{ x: 1 }` and `{ y: 1 }` is reported where the flag is false only, where it was reported in every configuration.

An expression reading another resource by name — `resources.<name>.<field>`, a bare `resources[…]`, or a module call (`Self.fn(x)`) — now holds the declaration it names only as the places its reading is typed from: a resource's identity, its `outputType` / `inputType` and the value slot its kind derives an output contract from; a function's `params`, `returns` and body, and the functions that body calls in turn. Its type checks no longer grow with the size of the declarations it reads, and a declaration a choice varies only outside those places no longer splits the expression's checks into one per configuration. The reported findings are unchanged.

A check an annotation makes through a reference — a resource rule's `resolve:` pointer (and a referrer rule's `resolveSelf:`) continuing into what a slot names, a text catalog set reaching the catalogs of the resources it names, a zone requirement whose correlation key crosses a reference, a value held to the types at a location past a reference, a catch list answering for what the resource drives, an accessor chain's typing — now holds each declaration it reaches only as the places its reader reads there: the members a rule's condition reads and which of the declaration's fields hold an expression, the catalogs and catalog sets its kind marks, the rest of the pointer, the reference slots, step bodies and scopes it drives others from, the contracts a dispatch to it is typed by. A named shape is still read whole. These checks no longer grow with the size of the declarations they read through, and a declaration a choice varies only outside those places no longer splits them into one per configuration. The reported findings are unchanged.

The same holds for every other annotation that reads through a reference: a boot target or a slot (`x-telo-ref`), a region typed from what a reference names (`x-telo-context-ref-from`, `-from`, `-from-root`, `-parameters-from`, `-from-ref-kind`, the element and collection bindings), a slot typed from its anchor (`x-telo-schema-from`), a scope (`x-telo-scope`), a function's `returns`, a bindings field, an item-fills list, a child application's inputs, a provided zone's correlation key, a contract and a projection (`x-telo-schema-projection-from`, read through the kind's own projection: its entries, and the fields an entry's reference takes its values from) — and every annotation that reads whoever references the resource (`x-telo-context-from-referrer`, a zone requirement, a referrer rule), which now holds each referrer as the places holding the reference and what its reader reads there: the scope in force at those places, or the members a referrer rule reads. Each holds the declarations it reads as their identity and the places it reads in them, so its checks no longer grow with the size of those declarations, and a declaration a choice varies elsewhere no longer splits them into one per configuration. The reported findings are unchanged.

The checks relating parts of one declaration read the declarations they name the same way: an inline declaration left in place at a step, a contract projected from what a reference names, a template's top-level `inputs:` against the input contract of the body entry it dispatches, a value held to a type past a reference, and a call's arguments against its target's input contract. Each holds a named declaration as its identity and the places its check reads there — a call target as what its contract reads, including an input contract derived from a field of the target and what that field names — and never the declaration whole, a named shape aside. These checks no longer grow with the size of the declarations they name, and a declaration a choice varies elsewhere no longer splits them into one per configuration. The reported findings are unchanged.

A templated kind's own checks read what its body names the way any declaration's do: a reference in a body entry is resolved by the body's own lookup — a sibling entry read as part of the definition, any other declaration as what the reference resolves to and the places the annotations reading it name there — and only a named shape is read whole. A declaration a body entry names no longer splits the definition's checks into one per configuration where a choice varies it elsewhere, and those checks no longer grow with its size. A declaration is now read whole as a named shape only when it is one, whatever schema, contract or annotation reached its name. The reported findings are unchanged.

A declaration's checks read the scopes declared on the way to what they judge — a sequence's `with:` above a step — by the names declared there: each member as its `kind` and `metadata`, and a member's own content only where a check reads it, such as the contract of a member a step invokes or a member a `resources.<name>` read names. A `with:` member nothing else reads no longer splits its holder's other checks into one per configuration where a choice inside it varies, and those checks no longer grow with the member's size. A forward that crosses a reference held by a `with:` member (`self.src.src.steps` through two members) is read in the declaration holding that member, so the checks of that declaration follow the choices of the member the reference names.

A forward view's own checks — its configuration against the body entry's kind, as the consumer forwards it — are now judged on the view's own regions, cut at the choices its forwarded values hold the way any declaration's are, instead of with the consumer's checks: a choice in one forwarded value no longer splits the checks of the consumer and of its other forwarded values into one per configuration, and the consumer's own checks no longer build its views. A view is identified by its consumer and the body entries leading to it, never by its position among the consumer's views, so an entry a choice declares ahead of another no longer moves what a finding about the later one is attached to. A finding a view repeats that the analysis already reports at the same place is still reported once. The reported findings are unchanged.

A declaration written inline — at a reference slot, or as a step's target — now has its own schema checks cut at the choices it holds as a declaration of its own kind is, since its holder's schema judges only the reference left in its place: an inline `Run.Sequence` step target whose steps each choose on a flag is judged once per step and flag value, no longer once for every combination of them, including where a choice between that inline declaration and a reference stands at the step. A `with:` member is judged by its holder's schema and its own kind's together, so a choice inside a member is no longer judged apart from a holder's scope field that relates the member's content — a holder whose scope field's `items` hold a member's field to a `oneOf` reports that member's field where a choice inside it breaks the `oneOf`, which it missed. Which objects are declarations of their own is what the configuration runs analyse as one — an object holding a `kind` anywhere else is judged by its holder's schema alone — decided by one enumeration of the declaration for each configuration that takes them together.

The relations a forward view holds — a forwarded step checked against the entry that receives it, a forwarded value fitted to its slot — are judged at relation sites of their own, one per instance and each keyed by what it reads, as a declaration's are, instead of as one site holding the whole declaration that builds its views: a choice in one forwarded value no longer splits the relation checks of the consumer and of its other forwarded values into one per configuration. A view's instances are found where their findings are reported — the consumer and the body entries leading to it — so an entry a choice declares ahead of another moves nothing, and a finding a view repeats that the analysis already reports at the same place is still reported once. A value a loop binding forwards that is a reference now makes the view the kernel builds from it where the union lacked one, and a region inside a value forwarded across a reference is written at that value itself, as the whole view's places write it. The reported findings are unchanged. A site marker standing for a view's relation instance is no longer dropped as a duplicate of its consumer's marker at the same place, and a relation key replays what an expression was typed as by its own text among the expressions of one forwarded place, so a type error in a forwarded value in a branch no configuration takes is reported again.

A step whose target is a declaration written inline, and any other relation check reading an inline declaration it follows into, now keys that check on the places it reads of the declaration — the target's `kind`, `metadata`, its contracts and its re-attempt fields — and carves the rest of the declaration out of the check's region, since the declaration's own kind judges what it holds and its holder only reads the reference left in its place (the same restart the schema checks make): a sequence whose inline target holds a choice per step is judged once per step's relation, no longer once for every combination of them. Which declaration is drawn out of its holder is the configuration runs' enumeration, never an object's shape. The reported findings are unchanged.

A kind's resource rules (`x-telo-resource-rules`) are now judged once per distinct set of values they read, outside every configuration's analysis, as a relation group of their own: the places of the declaration their conditions and `in:` pointers reach (a chain through a comprehension's or `cel.bind`'s variable followed to the member it reads, `this` through a repeated group the list it ranges over, a declaration whole only for a read of the root) and, by name, what each `resolve:` pointer reaches in the declarations it crosses into. A rule's violation is reported for exactly the configurations in which the member it reads is what it is; the rule no longer splits the CEL and schema keys of the declaration it judges. A rule that failed to evaluate is still reported once per declaring kind, and a rule no resource of its kind exercised once per running configuration. `analyzerPeerBinder` takes the `DeclarationRequests` it resolves references through in place of a manifest list, and `RelationDoor` gains `functions`. A rule condition calling a module function is judged in a configuration's key like any other: the group declares the functions its conditions call (`RelationReads.calls`) and the key reads each callee by name, where the call used to be unbound for a function the key did not hold. `RelationReaderScope` gains `moduleNames`. `observeRuleEvaluations` reports every evaluation of a rule family, and whether a configuration run made it, for whoever counts them. A rule's presence test on the declaration itself (`has(self.port)`) reads that member, not the declaration whole, and a forward view's rules are judged at the view (anchored at the first field they read that the view holds), so a value a template hands its entry is checked against the entry kind's rules.

Three whole-application passes carry presence conditions: each runs once over the union of every configuration's expansion and answers its findings with the configurations each holds in, where it used to run once per configuration. `DUPLICATE_RESOURCE_NAME` between declarations at module level is reported at the later of two present declarations of a name against the earliest present one, in the configurations holding both and no earlier one. `UNUSED_DECLARATION` holds in every configuration, since an expression counts as a read whichever branch it is written in. `SINK_UNATTACHED` holds where the sink is declared and no declaration present beside it references it: a reference is an edge of the call graph, read off each declaration as it stands under every combination of choices a reference sits beneath (a `!ref` in a kind document's template body or in a step's plain value attaches nothing), whose name the conditioned name index resolves to the sink, where that combination and the resolution hold. A configuration run reads the findings back from the pass's table in the raw form its own findings take, so they are relocated and labelled like the rest of its findings. Collisions inside a scope and sinks declared in a scope are still judged by the configuration run. `observeConditionedPasses` reports every run of these passes, and whether a configuration run made it, for whoever counts them. Two configuration fixtures are added: `sink-attachment-choice.yaml` and `sink-attachment-reference-choice.yaml`, and `unused-declaration-choice.yaml`. `OBSERVED_STATE_REQUIRED_FORBIDDEN` is the fourth such pass: a kind document is the same in every configuration, so it holds in all of them and is judged once.
