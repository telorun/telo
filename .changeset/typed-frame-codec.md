`encodeTypedFrame` / `decodeTypedFrame` write and read the typed frame: one schema-independent JSON form covering the whole CEL value domain, so a value read back has the CEL type it was written with. An `int`, `uint`, bytes, timestamp or duration is written as `{"$telo":"<CEL type>","value":"<plain encoding>"}`, as is a double that JSON cannot carry (NaN, ±Infinity, negative zero); a map with a non-string key or the key `$telo` is a tagged list of pairs; everything else is plain JSON, and an untagged number reads as a double. The text is canonical (RFC 8785 member order and number form), so identical values produce identical bytes. A value outside the domain — a class instance, including one with `toJSON`, a function, a symbol, `undefined`, a `Map` with a key CEL cannot hold or with two keys CEL reads as one (an `int` and a `uint` of the same number), a list carrying a property beside its items, a cycle — throws `ERR_TYPED_FRAME_UNENCODABLE`; a malformed frame, an unknown tag, a non-canonical payload, an object repeating a member name, or a number beyond a double's range (`1e400`) throws `ERR_TYPED_FRAME_UNDECODABLE`. Both carry `data.path`, the JSON Pointer of the offending node, a key's unpaired surrogates written as U+FFFD. `TYPED_FRAME_TAGS` lists the closed tag vocabulary. The format and its conformance vectors are specified in `kernel/specs/durable-execution.md` §6.
