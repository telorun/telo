An application declares the addresses it is reached at as needs of two kernel-declared types: `Telo.PublicUrl` (field `url`, an http/https origin; parameters `port`, `primary`, `customDomains`) and `Telo.PublicHostPattern` (field `pattern`, `https://*.tenants.example` or `https://*-tenants.example`; parameter `port`). `Telo.NeedType` gains `supply: root`: a need of such a type is fulfilled only through a root need forwarded whole, and a self-supplied fulfilment, a field-by-field supply or a library need reaching the root unforwarded is `NEED_ROOT_SUPPLY_REQUIRED` / `ERR_NEED_ROOT_SUPPLY_REQUIRED`. A root address need names a `tcp` port, and at most one is `primary` and one per port takes `customDomains` (`NEED_PARAMETERS_INVALID`). The kernel answers an unset `Telo.PublicUrl` from the host values `TELO_HOST_PUBLIC_URL_TEMPLATE` and `TELO_HOST_PUBLIC_URL_SECONDARY_TEMPLATE` (`ERR_NEED_HOST_VALUE_INVALID` for a bad template or derived label), refuses two addresses no host could route apart with `ERR_NEED_PUBLIC_URL_COLLISION`, announces each port's hosts as `publicUrls` on `Kernel.PortsResolved`, hides both host values from controllers and strips them from a started child's environment. `ctx.resolveNeed` answers an address need with the number of its port. `Telo.Url` gains the `user`, `password`, `path` and `query` member parameters. A presence test `has(a.b)` in a resource or referrer rule condition reads only `a`'s keys, so a dynamic value at `a.b` no longer skips the rule. A port an address need names counts as used (no `UNUSED_DECLARATION`). `telo needs report` lists a kernel-declared type under `type.module: Telo`, and a field whose value type's sensitive member the slot forbids (a `Telo.PublicUrl`'s password) is not reported sensitive. A main template holding `{label}` is refused, and the templates are read only when the application declares a `Telo.PublicUrl`. The controller protocol's `Need.Resolve` response gains an optional `port`.
