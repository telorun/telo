# Authoring agent — package guide

Loaded when working under `apps/authoring-agent/`. Repo-wide rules live in the root `CLAUDE.md` — including the MANDATORY rule that every architectural change updates this agent's system prompt (`chat/telo.yaml`, the `system:` block) in the same change.

## Asking the user

- "how does the agent ask the user a question?" → the analysis phase in the authoring agent's system prompt (`apps/authoring-agent/chat/telo.yaml`) and its e2e pair (`chat/tests/{authors-manifest,asks-before-building}.yaml`), `apps/studio/src/agent/questions.ts` (the block's single reader), `components/agent/QuestionCard.tsx`. **A question is a fenced `telo-questions` JSON block in the reply TEXT, never a tool call** — a tool result feeds the model loop straight into another step, so a tool cannot end a turn, and ending the turn is what asking is for. The editor renders it as clickable options and sends the picks back as an ordinary message, so the agent is never told whether a client parsed the block; a client that does not, and the user's own opt-out, both degrade to the same questions as text. **A question with NO options is an open one** — a fact only the user has (a sheet's columns, a tracker's field names, a join key), which the agent must never invent: the hub answers what a MODULE's fields are, nothing answers what the USER's are, and a made-up column name is not a syntax error but a manifest that checks clean, runs, and is wrong. The phase is CONDITIONAL on the request leaving something material unsaid — which is why the two e2e cases only assert anything as a pair, since either alone is satisfied by an agent that always asks or never does. **A placeholder is never an implementation** — a fetched-then-ignored source, a join returning a constant, a `value:` step of example rows where a computation belongs. Such a manifest checks clean and renders invented numbers, which is worse than not building: it reads as real and nothing downstream flags it. A computation the agent cannot work out is reported at the top of its reply; a gap in the CENTRAL capability is asked about before building around it, never footnoted after (the rule that permitted this said "build everything that does not depend on it", which is right for a peripheral unknown and licenses a hollow app for the load-bearing one). **A `default:` for a fact only the user has is an invented answer** wearing a nicer word, so such a variable is declared required. **A PROBE beats a question**: where a system is addressable and the agent has its identifier and a credential, it writes a throwaway read-only manifest under `.probes/`, runs it through `run_manifest`, reads what it printed off stdout and deletes it — so a spreadsheet's tabs and headers are discovered rather than transcribed by the user, leaving only the identifier and the credential's env var to ask about. The read-only rule is prompt-level and therefore NOT enforcement (the agent authors the probe); the enforceable control is the credential's own scope. **Having no credential is not a refusal** — the agent obtains one through `oauth-client`'s DEVICE flow (print the verification URL + user code, the user approves, poll), never the redirect flow, whose callback needs a listener the user's browser can reach and the container is not. It spans two runs, since a poll cannot outlast `runTimeoutMs` while a human signs in, and the second run does the READING too — an in-memory grant dies with the process that obtained it, so keeping the grant and the work together is what removes the need to persist one. Gated by `ALLOW_MANIFEST_RUNS`, off by default — the switch grants running ANY manifest, so it reaches the user's live systems with whatever the container holds, which is why it is named for what it does rather than for tests. **Questions come in ROUNDS that narrow** (shape first, then only what the previous answers made relevant, three-round ceiling): asking everything at once is what produced compound questions cramming four asks into one, and a tab's column headers cannot be asked for before the tab is known. **What the workspace CONTAINS is injected into every turn** as a `WORKSPACE STATE:` message rather than left to `list_dir` — the agent asked whether to create a new app or extend an existing one against an empty workspace, and a tool the model must remember to call is one it sometimes will not.
