---
"@telorun/runner-core": minor
---

A runner session is now a durable workspace, and its contract is rewritten around that (breaking). `POST /v1/sessions` takes `{ workspace, agent?, apps, config? }` — no bundle, no env, no `mode` — creates an empty session whose apps sit idle until `POST /v1/sessions/:id/apps/:app/run` (`{ env, io, cols?, rows? }`, `409 run_active` while one is live) and `…/stop`, and answers `409 session_exists` with the existing id for an owner's second session on one workspace. New routes: `PUT …/agent`, `POST …/suspend`, `POST …/io-tickets`; telo versions are judged on create and `PUT …/apps`. A create with no identity answers a resume secret once and keeps only its SHA-256; every session route takes it as `Authorization: Bearer` (`401 session_auth_required` without it, `404` for a session it does not own), and `/io` takes only a single-use 30 s `?ticket=` (closes `4401` without one, `4403` for a used, expired or foreign one). Every record change goes to the session store first; at boot every stored session is loaded, a running one adopted or suspended, and the orphan sweep spares known sessions; sessions suspend when idle or past `RUNNER_SESSION_MAX_RUNNING_SECONDS`, `failed` ones keep their storage and resume, and retention deletes suspended ones with their storage. Each app reports an `app` event (`ready`, `running` with its `runId`, `ready` with how a run `ended`), `run` triggers are `run` / `watch` / `manual`, reachability is reported only while an app runs, and the agent's token is minted per workload creation. Removed: one-shot `run` sessions, `POST /v1/apps/:name/sessions` and the capabilities `apps` list (with its `RunnerAppDescriptor` type), `features.watch`, the `exited` status, the workspace checkpoint (and the workspace app's `/workspace/snapshot` route), `stopAllSessions` and `watch.enabled`. The `RunnerBackend` seam becomes `create` / `adopt` / `destroy` / `reapOrphans({ known, live })` over a `BackendWorkload` (`runApp`, `stopApp`, per-run stdin and resize, `setApps`, `setAgent`, `suspend`, `detach`), with `buildServer` now taking the session `store`. A runner configured with `RUNNER_IDENTITY_AUDIENCE` (its canonical https base URL) and `RUNNER_IDENTITY_ISSUERS` (comma-separated https issuers) — boot refuses either alone, an http one, and an audience with a query, fragment or trailing slash — also accepts DPoP-bound identities: `Authorization: DPoP <access token>` plus a `DPoP` proof, the token an RFC 9068 JWT from a configured issuer (keys through RFC 8414 / OIDC discovery) for the audience with a `cnf.jkt`, the proof bound to that key, the request method and `<audience><path>`, within 120 s, with `ath` and a `jti` never seen before (kept in the session store across restarts). It advertises RFC 9728 metadata as `identity` on `/v1/capabilities` and at `/.well-known/oauth-protected-resource`, and every 401 carries `WWW-Authenticate: DPoP … resource_metadata="…"`. Refusals are `401 invalid_token` / `invalid_dpop_proof`, and an unreachable issuer `503 identity_provider_unavailable` while resume secrets keep working. An identity's create is owned by `(iss, sub)` with no secret; `GET /v1/sessions` (`?workspace=`) lists an identity's sessions (`403 identity_required` for a resume secret); `POST /v1/sessions/:id/owner` with `{ resumeSecret }` adopts a resume-secret session for the identity (`404` for a wrong secret, `409 session_exists` when the identity already has one for that workspace).

New: the session supervisor, the main process every app container runs — a static Linux executable built from the package's `supervisor/` crate (`build:supervisor`, `--target x86_64-unknown-linux-musl` / `aarch64-unknown-linux-musl`), not shipped on npm. It listens on `TELO_SUPERVISOR_LISTEN` at `GET /v1/supervisor` for one WebSocket carrying `Authorization: Bearer <TELO_SUPERVISOR_TOKEN>` (`4401` without it, `4403` for another; both variables are removed from its environment before anything runs), and speaks protocol generation 1 (`specs/supervisor-protocol.md`): the runner's `hello { generation, lastSeq }` answered with the supervisor's `hello { generation, instance, state, runId? }` and a replay of its output ring above `lastSeq`; `run` / `stop` / `resize` and stdin frames in; `started` / `exited` / `failed` / `refused` and `[seq][stream][payload]` output frames out, idempotent by `runId`. A run is its own process group on a fresh pty or on pipes, stopped with SIGTERM then SIGKILL after `graceMs`, and a dropped connection stops nothing. `SupervisorClient` is the runner's half: it reconnects and is replayed from its last seq, and reports a generation mismatch, a refused token, a superseded connection and a restarted supervisor as distinct terminations. The codec (`encodeRunnerMessage`, `decodeSupervisorMessage`, `decodeOutputFrame`, `SUPERVISOR_GENERATION`, `SUPERVISOR_CLOSE`) is exported beside it.

`RunnerBackend.reservedPorts?(apps)` lets a backend name the ports its workload binds beside an app set (`{ app, port, protocol, purpose }`); an app declaring one is refused `400 port_conflict` on `POST /v1/sessions` and `PUT …/apps`, naming what binds it.

A runner now supervises telo 0.123.0 and later (`MIN_SUPERVISABLE_TELO`, forward-declared until that release is published): it is the release whose `telo run --watch` lets a one-shot application's generation end, so its run is reported `completed` with its exit code; an app pinned to an older release is refused `400 telo_version_unavailable` when the app set is created or replaced. `RUNNER_STATE_DIR` names a runner's whole state directory: `loadCoreConfig`'s `stateDir`, a host's own resolved state root, now wins over it rather than standing in for it, so the store cannot land apart from the host's session directories.

`SupervisedApp` is the container backends' one adapter over `SupervisorClient`, exported beside it: it reports an app slot in `/v1` terms (`started` as `running`, `exited` / `failed` as `ready` with the run's ending), says on the app's output how many output frames were lost, reports nothing before `report()`, and names what the supervisor runs in by the `label` the backend passes; `isGenerationMismatch` recognises a supervisor of another protocol generation. A new `@telorun/runner-core/test-support` entry exports `FakeSupervisor`, a session supervisor that runs no program, for runners' tests; runner-core runs the protocol vectors against it.

A session record write that fails is retried (100 ms, 500 ms, 2 s); one that still fails moves the session to `failed` with the store's error as its message — runs ended, workload removed, storage kept, resumable — and the request that caused it is answered `500 session_store_failed` (`buildServer`'s optional `storeRetryDelaysMs` sets the waits). A runner shutting down no longer removes the containers its sessions started through their engine, nor ends a session's engine: the session store (schema version 2, migrated in place with every row carried forward) keeps each session's containers and the SHA-256 of every engine token a live run may hold, so a session the restarted runner adopts keeps its containers and its runs' token, and one it does not adopt is suspended, which removes them. `SessionContainers.releaseAll` is replaced by `shutdown`, and `SessionRecord` gains `containerEngine`.

A debug frame larger than 1 MiB is relayed to clients as a stand-in naming its event, timestamp and size instead of the frame itself, so an application whose invocations carry large payloads no longer exhausts the runner's memory.
