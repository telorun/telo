A `sources:` entry may name how its files are built in the repository, keyed by build system: `build: { cargo: <module-relative crate directory>, inputs: sha256-<base64url> }`, `inputs` being the digest of that crate's build inputs. `telo check` reports a `build.cargo` outside the module or a `build.inputs` not in that form as `SOURCE_INVALID`, and a `build` recording no `inputs` as `SOURCE_BUILD_UNPINNED`. `telo release stage --pin` records `build.inputs` as a byte splice: a digest over the files git tracks in the crate and in every path crate it reaches transitively — through a path dependency (with `workspace = true` resolved against `[workspace.dependencies]`) or a `[patch]` entry — the `Cargo.lock` packages those crates reach, every `.cargo/config(.toml)` and `rust-toolchain(.toml)` git tracks from the crate's directory up to the repository root, and from the workspace root's `Cargo.toml` the inherited `[workspace.dependencies]` entries, `[patch]`, `[replace]`, `[profile]` and `[workspace]`'s `resolver`, `package` and `lints`. A lock entry no such crate reaches and a file git does not track move nothing, and a crate git does not track is refused. `telo release check` recomputes it from the manifests without running cargo, and fails naming the module and the source when it differs, was never recorded, or the manifest does not parse.
