"@telorun/docker-runner": minor

Session containers now run unprivileged, as the session user `RUNNER_SESSION_USER` (a numeric `<uid>:<gid>`, default `1000:1000`, the kernel image's `node` user, as on the k8s runner): the `workspace`, `app-<name>` and `agent` containers run as it whatever their image's own `USER`, and each session create and resume gives the session's directory on the bundle volume to that user before any container starts, re-owning what an earlier root-run runner (or another session user) left. An entry the runner cannot give away fails the session's start, naming it. Every container gets a writable `HOME` (`/home/telo`, with `npm_config_cache` beneath it) on its role's directory under `<sessionId>/home/`, since Docker gives a uid its image does not list `HOME=/`. uid `0`, a user name or a missing gid refuses to boot. After an upgrade, or a change of `RUNNER_SESSION_USER`, a session the previous runner left running is suspended once instead of adopted and its resume rebuilds it. A host-path `AGENT_MODULE_REF` must be readable by the session user, and an `AGENT_IMAGE` must run as an arbitrary numeric uid. Containers a session starts through its container engine keep the user their request or image names. The runner image no longer carries a `.env*` file from the checkout: a deployed runner gets its `AGENT_*` settings through its environment or a file mounted into `/app`.
